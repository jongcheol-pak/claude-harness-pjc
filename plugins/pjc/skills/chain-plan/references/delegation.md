# 판정 위임 (`pjc:chain-plan`)

> `../SKILL.md` 「답하는 기준」이 두 경우에만 이 파일을 연다 — 워커 `plan.md` 승인 요청의 봉투 대조가 어긋날 때(아래 「봉투 밖 승인 요청」), 워커가 외부 계약 갈림길을 묻거나 승인 요청의 `승인 필요 항목` 에 공개 API 추가가 있을 때(아래 「외부 계약 위임」). 여기 나오는 봉투의 세 대조(task 줄·`승인 필요 항목`·`DB 변경`)와 사용자 몫(요청 밖 작업 등 넷)은 `../SKILL.md`「답하는 기준」의 것이다.

## 봉투 밖 승인 요청

- **하나라도 어긋나면 봉투 밖이다 — 회피 설계부터 지시한다.** 봉투의 task 줄 대조가 넘침이면 그 task 없이 목표가 되는지 보고 되면 `E: <그 task 를 뺀다> (코디네이터 판정 — <근거>)`, 안 되면 사용자 몫의 요청 밖 작업으로 사용자에게 넘긴다. task 줄 대조가 누락이면 `E: <빠진 항목> 을 넣거나 빠진 근거를 적는다 (코디네이터 판정 — <근거>)`. `승인 필요 항목`·`DB 변경` 대조가 어긋나면 사용자 몫(아래 「외부 계약 위임」이 사용자에게 보내는 기존 계약의 변경·삭제·UX 동작, 위임이 꺼졌을 때의 공개 API 추가 포함)이 아닌 한 어긋난 항목이 생기지 않는 설계가 있으면 `E: <회피 설계> (코디네이터 판정 — <근거>)`, 없을 때만 `Y (코디네이터 판정 — <근거>)` — 워커가 스스로 고른 설계가 만든 승인 항목은 대개 다른 설계로 사라진다(`../../plan/SKILL.md` Step 4). 봉투 밖이라는 사실만으로 사용자에게 넘기지 않는다. 이 `E:` 도 사용자가 아니라 코디네이터가 정한 것이라 `report.md` 의 `코디네이터 판정:` 줄에 모은다.

## 외부 계약 위임

- **위임 범위는 추가형 프로그램 접점이다 — 새 CLI 갈래·플래그, 새 API·공개 함수, 새 설정 키를 더하되 기존 이름·인자·출력 형식·기본값을 바꾸거나 지우지 않는 것** — 사용자가 체인 승인의 `외부 계약 위임:` 줄을 `Y` 로 승인해 미리 준 승인이라, 글로벌 「공개 API 변경은 승인」이 그 자리에서 채워진다. UX 동작(버튼·화면·문구)은 취향이 갈려 범위 밖이다. 체인 승인 화면의 위임 줄은 이 범위를 한 구로 옮긴 것이라, 범위를 바꾸면 그 줄도 함께 고친다.
- **판정 전에 위임 상태를 확인한다 — 체인 승인 답 원문이 컨텍스트에 있으면 그것으로, 없으면(압축) `compaction.md`「압축 뒤 복원」 으로 되찾은 objective 에서 `[체인 승인:` 앞의 `[위임 없음]` 표식으로 가르고, 둘 다 확인되지 않으면 사용자 몫으로 본다** — 사용자가 끈 위임을 압축 뒤에 쓰는 쪽이 더 위험한 실패다.
- **질문은 셋이 다 참일 때만 위임으로 답한다** — ⓐ 추가형 프로그램 접점 ⓑ 재진술 `결과` 를 이루는 데 필요하다(요청 밖이면 사용자 몫의 요청 밖 작업) ⓒ 워커 권장안(`(권장)`)이 있고 재진술 제약조건 안이다. 답은 `<권장안> (코디네이터 판정 — 외부 계약 위임: <ⓐ~ⓒ 근거>)` 이고, `report.md` 의 `코디네이터 판정:` 줄에 `(외부 계약 위임)` 으로 모은다.
- **워커 표식 `[외부 계약:추가]`·`[외부 계약:변경]` 은 판정의 입력일 뿐이다 — 질문 본문이 무엇을 더하거나 바꾸는지로 다시 가르고, 표식이 없으면 본문만으로 가른다** — 표식을 그대로 믿으면 워커의 분류 실수가 사용자 몫을 우회한다.
- **그 밖은 사용자 몫이다(`user-relay.md`「사용자에게 넘기기」)** — 기존 계약의 변경·삭제 · UX 동작 · 권장안이 없거나 목표·제약 밖 · 위임 없음 · 셋 중 하나라도 애매함.
- **승인 요청의 봉투 `승인 필요 항목` 대조는 위임이 켜져 있으면 ⓐ·ⓑ 와 제약조건 안인 공개 API 추가를 체인 승인 때 승인받은 것으로 센다** — 승인 제시에는 선택지가 없어 ⓒ 는 보지 않는다. 질문 단계에서 위임으로 답한 항목이면 그 판정을 그대로 잇는다.
