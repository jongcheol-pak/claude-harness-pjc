# 대기 종료 (`pjc:chain-plan`)

> `../SKILL.md` 「워커 루프」의 대기(`cli-errors.md`「오류 응답」 의 자리 대기 포함) 출력에 `RESULT` 줄이 없을 때(「RESULT 없음」)와 「체인 승인」의 `대기 보호:` 줄을 채울 때(「대기 보호」)만 이 파일을 연다. 멈춤 판정(같은 화면 3장)·잠금·`RESULT` 갈래는 `../scripts/wait-worker.py` 가 정본이다.

## RESULT 없음

- **완료 알림이 메모리 부족 종료(`was stopped because the system is running low on memory`)면 다시 띄우지 않는다 — 무엇을 기다리다 멈췄는지(워커 대기면 그 계획과 워커가 탭에서 계속 돈다는 것, 자리 대기면 아직 띄우지 않은 계획), 끄는 법(아래 「대기 보호」의 변수)을 사용자에게 알리고 turn 을 끝낸다** — 그 알림이 요청받을 때만 다시 띄우라고 지시해, 한 번 다시 띄우는 아래 규칙과 부딪히면 알림 쪽이 이겨 체인이 규칙 밖에서 선다(2026-10-06 Karina 체인 plan 1~3 에서 매번). 사용자가 이어 가라고 하면 그 turn 이 대기가 도는지 모르는 사용자 입력 turn 이라 대기를 다시 띄운다.
- **그 밖의 종료(강제 종료 포함 — 미루지 않는다)는 한 번만 다시 띄우고, 두 번 연속이면 출력을 보고하고 멈춘다.**

## 대기 보호

- **체인 승인을 내기 전에 Bash 로 `printenv CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP` 를 읽어 `1` 이면 `켜짐`, 아니면 `꺼짐 — 메모리가 부족하면 대기가 끊겨 계획마다 설 수 있다 · 끊김 알림이 권하는 대로 이 변수를 1 로 둔 환경에서 Claude Code 를 시작해야 한다(사용자 환경변수로 넣고 Karina 를 다시 시작)` 으로 적는다. 꺼짐이어도 멈추지 않는다** — Claude Code 는 세션이 쉬는 동안 OS 가 메모리 부족을 알리면 백그라운드 셸을 끊는데, 코디네이터는 대기 내내 쉬는 세션이다. 변수는 Claude Code 가 시작할 때의 환경에서만 읽혀 셸 명령으로 넣으면 듣지 않는다(그 알림 원문). 변수를 켠 뒤 Windows 에서 끊김이 사라지는지는 아직 재지 않았다. 공식 문서는 Windows 에서 효과가 없다고 적지만 Windows 11·v2.1.290 에서 이 끊김과 변수 안내가 실제로 났다(2026-10-06).
