# 사용자 중단·무관한 요청 (`pjc:chain-plan` 진행 중)

> `../SKILL.md` 「하지 않는 것」이 이 파일을 연다 — Run 을 만든 뒤 보고 전에 사용자가 체인을 멈추라고 하거나(「사용자 중단」) 체인과 무관한 요청을 할 때(「무관한 요청」)만 읽는다. 체인 승인 화면의 `[N] 중단` 은 Run 을 만들기 전이라 여기가 아니다.

## 사용자 중단

- **돌고 있는 워커는 `worker-retain --dispatch <id>` 로 탭을 지키고 체인을 멈춘다 — 코디네이터는 `worker-stop` 하지 않는다** — retain 은 터미널만 지키고 워커를 끝내지 않아(Karina 가이드 「an unfinished worker stays assigned — use `worker-stop` to end it」) 워커는 그 탭에서 하던 task 를 이어 커밋할 수 있다. 끝내는 것은 사용자 몫이다 — 보고에 「plan <N> 워커는 탭에서 계속 돌 수 있다(다음 질문·승인 요청에는 답이 가지 않아 약 27분 뒤 스스로 failed 로 멈춘다) — 멈추려면 그 탭에서 직접 하거나 `worker-stop --dispatch <id>` · 이 탭에서 「plan N부터」 재개하기 전에 그 워커를 끝낸다 — 끝내지 않으면 그 뒤에 온 메시지를 새 Run 의 대기가 받는다」 를 싣는다. 탭을 닫으면 커밋 전 변경과 화면을 사용자가 볼 수 없다.
- **백그라운드 대기는 끊지 않되 중단 뒤에는 사용자 입력 turn 이라도 대기를 새로 띄우지 않고, 돌아온 `RESULT` 는 따르지 않는다 — 완료 알림이 오면 배치는 `check --ack` 만 하고 처리하지 않으며 메시지 유형과 요지(질문이면 질문 한 줄, `worker_done` 이면 outcome 과 승인 필요 항목)를 한 줄로 알린다** — 배치를 처리하거나 대기를 다시 띄우면 멈춘 체인이 다시 움직이고, ack 하지 않으면 같은 탭의 다음 Run 이 그 배치를 받을 수 있다(`check` 는 ack 전까지 같은 배치를 다시 준다).
- **사용자에게 넘긴 질문이 열려 있었으면 「답하지 않음 — 사용자 중단 · 워커는 그 질문에서 상한 없이 기다린다(탭에서 직접 답하거나 닫을 때까지)」 로 보고에 싣는다** — 대기 신호를 받은 워커는 만료 상한이 없다.
- **보고는 `report.md`「보고 서식」 그대로다 — 멈춘 사유는 「사용자 중단 — plan <N> <무엇을 하던 중>」, 남은 탭에 retain 한 dispatch 를 싣는다. 재개는 사용자가 「plan N부터」로 부른다(`resume.md`「재개」) — 코디네이터가 스스로 재개하지 않는다** — 멈춘 자리는 승인이 필요한 정지이고, 다시 부르면 그 계획을 새로 실측한다.

## 무관한 요청

- **체인과 무관한 요청(다른 질문·조사)이 오면 「이 세션의 컨텍스트는 체인이 깨어날 때마다 다시 읽힌다 — 다른 탭을 권한다」 를 한 줄 알리고 그대로 수행한다. 같은 체인에서 두 번째부터는 알리지 않는다** — 착수 전 `fresh-session.md`「새 세션 권고」 는 묻지만, 진행 중에는 질문 한 번이 곧 깨어남 한 번이라 묻지 않는다(2026-10-04 실측: 61만 토큰 세션의 체인이 대기 중 31M 토큰).
- **파일 수정과 계획 작성은 무관한 요청이라도 `../SKILL.md` 「하지 않는 것」 그대로 하지 않고 「다른 탭에서」 를 안내한다** — 워커가 같은 레포 경로에서 돌아, 이 세션이 쓴 `plan.md`·파일이 워커의 것과 어긋난다.
- **체인이 멈추지 않았으면, 요청을 마친 turn 에 대기가 도는지 모를 때 `../SKILL.md` 「워커 루프」의 사용자 입력 turn 규칙대로 대기를 다시 띄운다** — 무관한 요청 사이에 앞 대기가 끝났을 수 있다.
