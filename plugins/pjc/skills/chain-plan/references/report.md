# 체인 보고 (`pjc:chain-plan` 끝 1회)

> `../SKILL.md` 「보고」가 이 파일을 연다 — 체인이 끝나거나 멈출 때만 읽는다. 행동 규칙(워커가 받은 승인 필요 항목을 이 세션에서 실행하지 않는다)은 `../SKILL.md` 에 남아 있다.

## 보고 서식

```
계획 체인 — <완료 N/총 | plan N 에서 멈춤>

plan 1: <결과>
  무엇이 바뀌었나: <워커 --body 의 사용자용 요약>
  확인 방법: <워커 --body 의 확인 방법>
  남은 일: <워커 --body 의 남은 일>
  이어받기: <수 — 없으면 줄 생략>
plan 2: …

승인 필요 항목: <워커 --body 에서 받은 것 전부 — 없으면 「없음」>
HUMAN-VERIFY·미검증: <워커 --body 에서 받은 것 전부>
사용자에게 넘긴 질문: <수>
코디네이터 판정: <판정으로 답한 질문·승인(봉투 밖 `E:` 지시 포함)마다 「<무엇을 답했나> — <근거> — 틀리면: <무엇을 치르는가 · 되돌리는 법>」 — 외부 계약 위임으로 답한 것은 `(외부 계약 위임)` 표기 · 없으면 「없음」>
환경 개선 후보: <마찰마다 「<무엇> — <횟수> · <출처: plan N 워커 | 코디네이터> — <행선지 | 올린 위치>」 — 없으면 「없음」>
남은 탭: <체인이 끝나거나 멈출 때 `worker-list --run <Run id> --json` 의 이 Run 행 중 `terminalState` 가 `released` 가 아닌 것(dispatch·state·terminalState) · CLI 오류 응답(`worker_start_failed`·`duplicate_worker`·`task_not_startable`)이 이름 댄 다른 탭·dispatch — 없으면 줄 생략>
멈춘 사유·남은 task: <멈췄을 때만 — CLI 오류로 멈췄으면 코드·`error` 문장, `protocol_error` 면 retry id 와 「이미 실행됐을 수 있다 — `worker-list` 로 확인」>
```

- **plan 별 칸은 워커 `--body` 의 같은 이름 필드에서만 채운다** — 이 세션은 파일을 읽지 않으므로, 필드에 없는 것을 채우면 추측이다. 남은 탭은 그때 돌린 `worker-list` 출력과 CLI 오류 응답에서 온다 — 멈춘 경로(release `retained`·failed·대기 스크립트 stall 의 retain·시작 이상의 abandon)가 무엇이든 탭이 남은 dispatch 가 한 출력에 모인다. `worker-list` 가 실패하면 받아 둔 `worker-release`·`worker-retain` 응답과 CLI 오류 응답으로 채우고 나머지는 `모름` 으로 적는다. 멈춘 사유는 `failed` 의 `--body` 나 CLI 오류 응답에서 온다(`cli-errors.md`「오류 응답」). **예외는 이어받기다** — `이어받기:` 수는 이 세션이 만든 이어받기 task 수에서 오고, plan N 칸은 원 워커와 이어받기 워커의 `--body` 를 합친다(무엇이 바뀌었나·확인 방법은 이어 붙이고, 남은 일은 이어받기로 처리한 `[다음 회차]` 만 빼고 모든 워커의 것을 합친다 — 마지막 워커의 것만 쓰면 앞 워커가 남긴 일이 사라진다).
- **이 세션이 직접 쓰는 줄(코디네이터 판정·환경 개선 후보·멈춘 사유)은 CLI 출력·워커 메시지로 확인한 사실만 적고, 확인하지 못한 것은 `추정(근거)` 또는 `모름` 으로 표시한다. 워커 필드의 추정·모름 표시는 지우지 않고 그대로 옮긴다** — 확인한 것과 짐작한 것이 같은 문장으로 적히면 사용자가 둘을 가르지 못한다.
- **판정마다 `틀리면:` 마디를 판정한 그 자리에서 정해 둔다 — 되돌리는 법은 이 세션이 아는 단위(plan 번호·그 워커의 task)로 적고 모르면 `모름` 이다. 서식은 `pjc:implement` 의 Progress Log `판정:` 세 마디와 같다** — 판정이 여럿이면 사용자는 틀렸을 때 치를 것이 큰 것부터 검토한다. 이 마디는 판단이라 위 사실 표기 대상이 아니고, 그 규칙은 근거 마디에 걸린다.
- **`환경 개선 후보:` 줄은 워커 `--body` 의 `환경 마찰` 과 이 세션이 본 마찰(사용자에게 넘긴 질문·대기 스크립트 stall·이어받기·CLI 오류 응답)에서만 모으고, plan 칸이 아니라 이 한 줄에 모든 워커(이어받기 포함)의 것을 합친다.** 같은 갈래의 사용자 이관·같은 hook 차단·같은 원인 반복 실패는 체인 전체에서 2회 이상일 때만 싣고, `AGENTS.md` 에 없어 찾거나 물은 명령과 이어받기·stall 은 1회도 싣는다. 행선지는 넷이다 — `AGENTS.md` 명령 → `pjc:record-project-fact` · 대상 레포 규약 → 그 레포 Deferred 대장(없으면 「대장 없음 — 사용자가 정한다」) · hook·하니스 동작 → pjc 플러그인 레포 · 작업 규약·함정 → 위키. 워커가 이미 대장·위키 큐·`AGENTS.md` 에 올린 것은 행선지 대신 그 위치를 적는다. **이 세션은 행선지에 쓰지 않고 제안만 한다** — 마찰은 워커 화면과 이 세션에 흩어져 있어 보고에 모이지 않으면 다음 체인이 같은 자리에서 다시 서고, 행선지까지 적어야 사용자가 무엇을 고칠지 고른다. 파일을 고치지 않는 이 세션이 쓰면 워커의 `plan.md` 가 모르는 변경이 생긴다(`../SKILL.md` 「하지 않는 것」).
