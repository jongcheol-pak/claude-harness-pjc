# 체인 보고 (`pjc:chain-plan` 끝 1회)

> `../SKILL.md` 「보고」가 이 파일을 연다 — 체인이 끝나거나 멈출 때만 읽는다. 행동 규칙(워커가 받은 승인 필요 항목을 이 세션에서 실행하지 않는다)은 `../SKILL.md` 에 남아 있다.

## 보고 서식

```
계획 체인 — <완료 N/총 | plan N 에서 멈춤>

plan 1: <결과>
  무엇이 바뀌었나: <워커 --body 의 사용자용 요약>
  확인 방법: <워커 --body 의 확인 방법>
  남은 일: <워커 --body 의 남은 일>
  이어받기: <수 — 없으면 줄 생략>
plan 2: …

승인 필요 항목: <워커 --body 에서 받은 것 전부 — 없으면 「없음」>
HUMAN-VERIFY·미검증: <워커 --body 에서 받은 것 전부>
사용자에게 넘긴 질문: <수>
코디네이터 판정: <판정으로 답한 질문·승인(봉투 밖 `E:` 지시 포함)과 근거 — 외부 계약 위임으로 답한 것은 `(외부 계약 위임)` 표기 · 없으면 「없음」>
남은 탭: <체인이 끝나거나 멈출 때 `worker-list --run <Run id> --json` 의 이 Run 행 중 `terminalState` 가 `released` 가 아닌 것(dispatch·state·terminalState) · CLI 오류 응답(`worker_start_failed`·`duplicate_worker`·`task_not_startable`)이 이름 댄 다른 탭·dispatch — 없으면 줄 생략>
멈춘 사유·남은 task: <멈췄을 때만 — CLI 오류로 멈췄으면 코드·`error` 문장, `protocol_error` 면 retry id 와 「이미 실행됐을 수 있다 — `worker-list` 로 확인」>
```

- **plan 별 칸은 워커 `--body` 의 같은 이름 필드에서만 채운다** — 이 세션은 파일을 읽지 않으므로, 필드에 없는 것을 채우면 추측이다. 남은 탭은 그때 돌린 `worker-list` 출력과 CLI 오류 응답에서 온다 — 멈춘 경로(release `retained`·failed·대기 스크립트 stall 의 retain·시작 이상의 abandon)가 무엇이든 탭이 남은 dispatch 가 한 출력에 모인다. `worker-list` 가 실패하면 받아 둔 `worker-release`·`worker-retain` 응답과 CLI 오류 응답으로 채우고 나머지는 `모름` 으로 적는다. 멈춘 사유는 `failed` 의 `--body` 나 CLI 오류 응답에서 온다(`cli-errors.md`「오류 응답」). **예외는 이어받기다** — `이어받기:` 수는 이 세션이 만든 이어받기 task 수에서 오고, plan N 칸은 원 워커와 이어받기 워커의 `--body` 를 합친다(무엇이 바뀌었나·확인 방법은 이어 붙이고, 남은 일은 이어받기로 처리한 `[다음 회차]` 만 빼고 모든 워커의 것을 합친다 — 마지막 워커의 것만 쓰면 앞 워커가 남긴 일이 사라진다).
- **이 세션이 직접 쓰는 줄(코디네이터 판정·멈춘 사유)은 CLI 출력·워커 메시지로 확인한 사실만 적고, 확인하지 못한 것은 `추정(근거)` 또는 `모름` 으로 표시한다. 워커 필드의 추정·모름 표시는 지우지 않고 그대로 옮긴다** — 확인한 것과 짐작한 것이 같은 문장으로 적히면 사용자가 둘을 가르지 못한다.
