# 체인 보고 (`pjc:chain-plan` 끝 1회)

> `../SKILL.md` 「보고」가 이 파일을 연다 — 체인이 끝나거나 멈출 때만 읽는다(예외: 「체인 시작 시각」 절은 `../SKILL.md` 「인터뷰」가 주입 줄이 없을 때 시작 때 연다). 행동 규칙(워커가 받은 승인 필요 항목을 이 세션에서 실행하지 않는다)은 `../SKILL.md` 에 남아 있다. 이 파일의 행동 규칙은 「인계 파일 정리」 와 그 뒤의 체인 끝 PR 포인터 둘이다 — 보고 직전에 수행해 그 결과를 보고에 싣기 때문이다.

## 보고 서식

```
계획 체인 — <완료 N/총 | plan N 에서 멈춤>
소요: <체인 시작> ~ <완료 | 멈춘 시각> (<N시간 M분>)

plan 1: <결과>
  소요: <워커 --body 의 소요>
  무엇이 바뀌었나: <워커 --body 의 사용자용 요약>
  확인 방법: <워커 --body 의 확인 방법>
  남은 일: <워커 --body 의 남은 일>
  검증: <워커 --body 의 검증>
  코디네이터 검증: <명령마다 통과 | 실패 → 이어받기 <k> | 미검증 — <사유> | 건너뜀 — <사유> — PR 모드·병렬 계획은 줄 생략>
  판정: <워커 --body 의 판정>
  이어받기: <수 — 없으면 줄 생략>
plan 2: …

승인 필요 항목: <사용자 결정 N건(모든 plan 합) — 워커 --body 의 항목을 `plan N:` 을 붙여 옮기되 워커 줄 머리의 건수는 뗀다 — 없으면 「없음」>
HUMAN-VERIFY·미검증: <워커 --body 에서 받은 것 전부 · 코디네이터 검증의 미검증·건너뜀(`plan N:` 을 붙여)>
사용자에게 넘긴 질문: <수> (미답 기본값 <k>건 — 시한까지 답이 없어 기본값으로 답한 것 · 0 이면 괄호 생략)
코디네이터 판정: <판정으로 답한 질문·승인(봉투 밖 `E:` 지시 포함)마다 「<무엇을 답했나> — <왜> — 근거: <워커 질문 원문, 체인 승인의 판정 원칙 줄, 사용자 답 원문, 워커가 인용한 파일:줄 | 없음> — 틀리면: <무엇을 치르는가 · 되돌리는 법>」 — 미답 기본값은 「<무엇을 답했나> (기본값 적용·사용자 미답)」 으로 시작한다 — 없으면 「없음」>
기본값 뒤 답: <미답 기본값을 보낸 뒤 사용자가 답한 것마다 「plan N: <질문 한 줄> — 적용한 기본값 <한 구> → 사용자 답 「<원문>」(뒤 계획의 같은 질문에서 사용자 답으로 씀)」 — 없으면 줄 생략>
환경 개선 후보: <마찰마다 「<무엇> — <횟수> · <출처: plan N 워커 | 코디네이터> — <행선지 | 올린 위치>」 — 없으면 「없음」>
인계 파일: <경로 — 지움 <커밋 sha>(체인 끝 PR 이 건너뛰었거나 실패했으면 「로컬 커밋 — push 안 함」 을 덧붙인다) | 남김 — <사유> | 없음>
병렬 병합: <그룹마다 plan · 병합 커밋 sha(PR 모드면 PR URL · merge 커밋) | 미병합 — <사유> · worktree 경로 · 브랜치 — 지우지 않음(`parallel.md`「닫기」) | 없음>
PR: <PR 모드면 계획마다 「plan N: <워커 --body 의 PR>」 에 이어 「체인 끝 PR: <URL> · <체인 브랜치> → <기본 브랜치> | 건너뜀 — <사유>」 — 꺼졌으면 대상 레포마다 「체인 끝 PR: <URL> · 브랜치 <pjc/chain-…> | 건너뜀 — <사유>」>
화면 확인 대기: <PR 모드면 워커 --body `PR:` 이 `· 화면 확인 대기` 인 plan 마다 「plan N — <URL>」 · 체인 끝 PR 본문에 `## 화면` 이 있으면 그 URL — 없으면 줄 생략>
남은 탭: <체인이 끝나거나 멈출 때 `worker-list --run <Run id> --json` 의 이 Run 행 중 `terminalState` 가 `released` 가 아닌 것(dispatch·state·terminalState) · CLI 오류 응답(`worker_start_failed`·`duplicate_worker`·`task_not_startable`)이 이름 댄 다른 탭·dispatch — 없으면 줄 생략>
멈춘 사유·남은 task: <멈췄을 때만 — CLI 오류로 멈췄으면 코드·`error` 문장, `protocol_error` 면 retry id 와 「이미 실행됐을 수 있다 — `worker-list` 로 확인」 · stall·failed 로 멈췄으면 「워커를 그 탭에서 직접 이어 가게 했으면 이 탭에 「plan <N> 워커 재개」라고 알린다 — 체인이 거기서 잇는다」>
```

- **plan 별 칸은 워커 `--body` 의 같은 이름 필드에서만 채운다 — 예외는 `코디네이터 검증:` 줄이고, 이 세션이 `continuation.md`「코디네이터 검증」 으로 돌린 명령 출력에서 온다** — 이 세션은 파일을 읽지 않으므로, 필드에 없는 것을 채우면 추측이다. 남은 탭은 그때 돌린 `worker-list` 출력과 CLI 오류 응답에서 온다 — 멈춘 경로(`release.md`「닫기」 가 자리만 푼 abandon·failed·대기 스크립트 stall 의 retain·시작 이상의 abandon)가 무엇이든 탭이 남은 dispatch 가 한 출력에 모인다. `worker-list` 가 실패하면 받아 둔 `worker-release`·`worker-retain` 응답, `worker-stop`·`worker-abandon` 응답과 CLI 오류 응답으로 채우고 나머지는 `모름` 으로 적는다. 멈춘 사유는 `failed` 의 `--body` 나 CLI 오류 응답에서 온다(`cli-errors.md`「오류 응답」). **예외는 이어받기다** — `이어받기:` 수는 이 세션이 만든 이어받기 task 수에서 오고, plan N 칸은 원 워커와 이어받기 워커의 `--body` 를 합친다(무엇이 바뀌었나·확인 방법·검증·판정은 이어 붙이고, 남은 일은 이어받기로 처리한 `[다음 회차]` 만 빼고 모든 워커의 것을 합친다 — 마지막 워커의 것만 쓰면 앞 워커가 남긴 일이 사라진다).
- **머리의 `소요:` 는 남은 탭의 `worker-list` 명령 앞에 `"<skill>/../implement/scripts/work-clock.ps1" -Since '<체인 시작>'` 을 `;` 로 얹어 얻고 `pjc-clock` 줄로 판정한다(호출형·판정은 `../../implement/references/report-format.md`「소요 기록」 · 그 줄이 없으면 `시각 미확인`) — `<체인 시작>` 은 인터뷰 때 얻어 둔 값이고, 컨텍스트에 없으면 `run-show --id <Run id> --json` 의 objective 에서 `[체인 시작: …]` 을 읽으며, 거기도 없으면 `시작 모름` 이다 · 주입 줄을 여기서 다시 고르지 않는다** — 시각은 셸 출력만 쓰고 왕복을 늘리지 않는다. 체인 끝에는 체인 승인 같은 사용자 메시지가 주입 줄보다 뒤에 있어, 다시 고르면 맞는 줄을 버리거나 다른 계획의 줄을 집는다. **plan 칸의 `소요:`·`검증:`·`판정:` 은 `--body` 에 그 필드가 없으면(failed·옛 워커) 줄째 뺀다** — 이어받기면 워커별 값을 이어 붙인다.
- **`화면 확인 대기:` 줄은 merge 가 사용자 확인을 기다리는 PR 목록이다 — 사용자가 스크린샷을 보고 PR 마다 「화면 확인함」 으로 `pjc:pr` ship 을 요청해야 merge 된다(`../../pr/references/ship.md` 7번)** — plan 칸의 남은 일에 흩어지면 merge 를 기다리는 PR 이 있다는 사실이 묻힌다.
- **이 세션이 직접 쓰는 줄(코디네이터 판정·환경 개선 후보·인계 파일·멈춘 사유)은 CLI 출력·워커 메시지로 확인한 사실만 적고, 확인하지 못한 것은 `추정(근거)` 또는 `모름` 으로 표시한다. 워커 필드의 추정·모름 표시는 지우지 않고 그대로 옮긴다** — 확인한 것과 짐작한 것이 같은 문장으로 적히면 사용자가 둘을 가르지 못한다.
- **이 세션이 쓰는 문장(머리·코디네이터 판정·환경 개선 후보·멈춘 사유)은 `../../WRITING.md` 의 한글 문체 규칙을 따르고, 워커 `--body` 에서 옮겨 싣는 칸은 고치지 않는다** — 사용자는 체인 전체를 이 보고 하나로 판단하고, 옮겨 싣는 칸을 고치면 워커가 확인한 사실이 바뀐다.
- **판정마다 `틀리면:` 마디를 판정한 그 자리에서 정해 둔다 — 되돌리는 법은 이 세션이 아는 단위(plan 번호·그 워커의 task)로 적고 모르면 `모름` 이다. 서식은 `pjc:implement` 의 Progress Log `판정:` 세 마디에 근거 포인터 마디를 더한 네 마디다** — 판정이 여럿이면 사용자는 틀렸을 때 치를 것이 큰 것부터 검토한다. 이 마디는 판단이라 위 사실 표기 대상이 아니고, 그 규칙은 왜·근거 두 마디에 걸린다.
- **근거 포인터는 문단이 아니라 되짚을 수 있는 위치다 — 가리킬 위치가 없는 순수 판단이면 `없음` 으로 적는다** — 사용자는 판정을 검토할 때 그 위치를 열어 보고, 이유를 풀어 쓴 문단은 열어 볼 곳을 주지 않는다. 이유는 왜 마디가 따로 담는다.
- **`환경 개선 후보:` 줄은 워커 `--body`(succeeded·failed) 의 `환경 마찰` 과 이 세션이 본 마찰(사용자에게 넘긴 질문·대기 스크립트 stall·이어받기·CLI 오류 응답)에서만 모으고, plan 칸이 아니라 이 한 줄에 모든 워커(이어받기 포함)의 것을 합친다.** 같은 갈래의 사용자 이관·같은 hook 차단·같은 원인 실패·같은 CLI 오류 코드는 체인 전체에서(워커가 적은 횟수와 이 세션이 센 것을 합쳐) 2회 이상일 때만 싣고, `AGENTS.md` 에 없어 찾거나 물은 명령과 이어받기·stall 은 1회도 싣는다. 행선지는 넷이다 — `AGENTS.md` 명령 → `pjc:record-project-fact` · 대상 레포 규약 → 그 레포 Deferred 대장(없으면 「대장 없음 — 사용자가 정한다」) · hook·하니스 동작 → pjc 플러그인 레포 · 작업 규약·함정 → 위키. 워커가 이미 대장·위키 큐·`AGENTS.md` 에 올린 것은 행선지 대신 그 위치를 적는다. **이 세션은 행선지에 쓰지 않고 제안만 한다** — 마찰은 워커 화면과 이 세션에 흩어져 있어 보고에 모이지 않으면 다음 체인이 같은 자리에서 다시 서고, 행선지까지 적어야 사용자가 무엇을 고칠지 고른다. 파일을 고치지 않는 이 세션이 쓰면 워커의 `plan.md` 가 모르는 변경이 생긴다(`../SKILL.md` 「하지 않는 것」).

## 인계 파일 정리

- **체인이 끝까지 성공했으면(모든 계획 `succeeded` · 남은 일 「없음」 또는 이어받기 완료) 보고를 내기 직전에 인계 파일을 지우는 커밋 1개를 만든다 — `git -C "<대상 레포 경로>" rm -q -- <인계 경로>` 뒤 `git -C "<대상 레포 경로>" commit -m "문서: 계획 체인 인계 파일 정리 — <Run id>" -- <인계 경로> 2>&1`** — 끝난 체인의 파일이 남으면 `resume.md`「재개」 의 글롭이 다른 체인을 재개할 때 그것까지 집는다. 내용은 git 이력에 남는다. 체인이 끝난 뒤라 워커의 `plan.md` 가 모르는 변경이 생기지 않는다.
  - **남은 일이 화면 확인 대기 PR 뿐이면, 그 PR 들이 인계 파일을 담지 않을 때만 성공으로 친다 — 판정은 PR 마다 `gh pr diff <n> --name-only` 에 인계 경로가 있는가다** — 담은 PR(병렬 그룹원)이 있으면 정리하지 않고 `인계 파일:` 줄에 `남김 — 화면 확인 대기 PR 이 인계 파일을 담음` 을 싣는다. 지우면 나중에 그 PR 을 merge 할 때 수정·삭제 충돌이 난다.
- **정리 커밋 뒤, 보고 전에 `Y` 면 `pr-mode.md`「Y 체인 끝 PR」, `P` 면 같은 파일 「P 체인 끝 PR」 을 따른다 — 체인 끝 PR 이 이 정리 커밋까지 싣는다** — 정리 커밋이 PR 에 실려야 squash 뒤 기본 브랜치에 남는다. `P` 의 정리 커밋은 체인 브랜치의 로컬 커밋이고 그 절의 push 가 원격 체인 브랜치로 올린다. 체인이 멈췄으면 열지 않는다 — 「plan N부터」 재개가 같은 브랜치에서 잇는다.
- **인계 파일이 없으면(계획 하나뿐이라 인계 절을 쓴 워커가 없는 체인) 정리할 것이 없다 — `인계 파일:` 줄은 `없음` 이다** — 아래 `ls-files` 판정에 넣으면 실패를 「남김」 으로 잘못 적는다.
- **멈춘 체인의 인계 파일은 지우지 않는다** — `failed`·사용자 중단·CLI 오류로 멈췄으면 「plan N부터」 재개가 그 파일을 읽는다.
- **인계 파일이 커밋돼 있지 않거나 미커밋 변경이 있으면 지우지 않는다** — `git -C "<대상 레포 경로>" ls-files --error-unmatch -- <인계 경로>` 가 실패하거나 `git -C "<대상 레포 경로>" status --porcelain -- <인계 경로>` 가 비어 있지 않으면, 지우면 복구 경로가 없다. 그 사실을 `인계 파일:` 줄의 사유로 싣는다.

## 체인 시작 시각

**`../SKILL.md` 「인터뷰」가 이번 발동의 `[pjc 작업 시작]` 줄을 찾지 못했을 때만 연다(hook 미발화 — 옛 설치본·hook 꺼짐).** 인터뷰 첫 셸 호출에 `"<skill>/../implement/scripts/work-clock.ps1"`(`<skill>` 은 `../SKILL.md` 의 폴더) 를 인자 없이 얹고, 출력의 `pjc-clock <YYYY-MM-DD HH:mm>` 을 체인 시작으로 objective 의 `[체인 시작: …]` 에 적는다 — 호출형은 `../../implement/references/report-format.md`「소요 기록」 이다. **그 줄이 없으면 `[체인 시작: 시각 미확인]` 으로 적는다** — 보고 때 그 값을 `-Since` 에 넘기면 `ERROR` 줄이 나와 `시작 판독 실패` 로 이어진다. 시작 때 재지 않으면 끝에 잴 기준이 없고, 끝에 이 폴백을 따르면 시작이 곧 완료 시각이 되어 `0h 0m` 이 서식에 맞는 채 실린다.
