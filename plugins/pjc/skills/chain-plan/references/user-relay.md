# 사용자에게 넘기기 (`pjc:chain-plan`)

> `../SKILL.md` 「답하는 기준」이 워커의 질문·승인 요청이나 실행 시점 승인 항목을 사용자 몫으로 넘길 때(「사용자에게 넘기기」·「미답 기본값」)와 워커 `plan.md` 승인 요청에 답할 때(「봉투 대조」·「봉투 밖 승인 요청」), 그리고 대기 출력이 `RESULT: deadline` 일 때(「미답 기본값」)만 이 파일을 연다. 무엇이 사용자 몫인지는 거기가 정본이다.

## 사용자에게 넘기기

- **사용자에게 넘길 때는 사용자를 부른 뒤 묻는다** — 알림이 없으면 사용자는 이 탭에 질문이 떠 있는 줄 모른다. 워커는 답이 올 때까지 상한 없이 기다린다(`../../plan/references/relay-edge-cases.md`「ask 만료」) — ②·③ 은 아래 「미답 기본값」 시한에 이 세션이 답하며 다시 알리고, ①·④ 는 답이 늦어도 따로 알릴 것이 없다.
  1. `PushNotification`(`status: "proactive"`, 메시지 `plan <N>: 사용자 확인 필요 — <질문 한 줄>`) — 지연 로드면 ToolSearch 로 불러 쓰고, 도구가 없거나 보내지 않았다고 하면 건너뛴다
  2. 질문 원문(승인 요청이면 그 승인 제시 전문)과 `GUESS:` 를 그대로 보이고 답을 글자 그대로 옮긴다 — 요약해 넘기면 사용자가 워커의 실제 질문이 아니라 이 세션의 해석에 답하게 된다
  3. `prior-answers.md`「앞선 답」 이 같은 질문으로 고른 앞 답이 있으면 2 에 `참고: plan <M>[ 이어받기 <k>] 에서 같은 질문에 「<답 원문>」(<사용자 답 | 코디네이터 판정>)` 을 덧붙이고, 앞 답과 어긋나게 판정해야 해 넘기는 것이면 ` — 이번에 다르게 볼 이유: <질문에 인용된 새 사실>` 을 잇는다 — 앞 답으로 대신 답하지 않는 대신 사용자가 같은 답을 빨리 고르게 하고, 출처가 없으면 사용자가 코디네이터 판정을 자기 앞 결정으로 읽는다

## 미답 기본값

- **대상은 사용자 몫 ②(사용자 답 뒤집기)·③(요청 범위 변경)으로 넘긴 질문·승인 요청뿐이다 — ①(실행 시점 승인)·④(이미 있는 것을 깨는 변경)는 답이 올 때까지 기다리고 대기도 띄우지 않는다** — 되돌리기 어려운 결정을 기본값이 대신하지 않는다.
- **넘긴 직후 시한 값을 먼저 얻는다 — `echo $(( $(date +%s) + <분>*60 ))`(분은 체인 승인 `미답 시한:` 값 · objective `[미답 시한:]` · 기본 30 · 45 를 넘기면 45 로 두고 한 줄 알린다). 그 리터럴을 `../SKILL.md` 「워커 루프」 대기 명령에 `--answer-by <값>` 으로 더해 띄우고, 무엇을 기다리는지 알리는 한 줄에 그 값을 적는다** — 어느 갈래로 다시 띄우든 같은 리터럴을 쓴다. 다시 계산하면 시한이 뒤로 밀린다.
- **시한 전에 사용자 답이 오면 지금처럼 글자 그대로 `reply` 하고 `--answer-by` 없이 대기를 다시 띄운다** — 새 대기가 잠금을 가져가 시한 대기는 superseded 로 물러난다.
- **`RESULT: deadline` 이 오면 기본값으로 `reply` 한다 — 그 직전 이 탭에 사용자 답이 와 있으면 그 답이 먼저다.** 기본값은 셋이고, 셋 다 꼬리 `— 그 때문에 서지 않는 목표 항목은 Deferred 에 보류하고 남은 일: 에 미완으로 적는다 · 같은 질문을 다시 넘기지 않는다 (코디네이터 판정 — 기본값 적용·사용자 미답)` 를 붙인다 — 범위를 넓히거나 사용자 답을 뒤집는 쪽은 모델 단독 판정으로 열지 않는다. task 만 빼고 꼬리가 없으면 리뷰어가 목표 누락으로 같은 질문을 다시 올려 시한마다 되돈다.
  - ② `「<원래 답 원문>」 유지 <꼬리>`
  - ③ `범위를 넓히지 않는다 — <그 작업> 은 Deferred 에 보류 <꼬리>`
  - 봉투 밖 승인 요청을 ③ 으로 넘긴 것이면 `E: <그 task 를 뺀다> <꼬리>`
- **기본값을 보낸 뒤 사용자를 부른다 — `PushNotification`(`status: "proactive"`, 메시지 `plan <N>: 미답 기본값 적용 — <질문 한 줄> → <기본값 한 구>`, 도구가 없으면 건너뛴다)과 이 탭에 질문·기본값을 보이고, 보고 `코디네이터 판정:` 에 `기본값 적용·사용자 미답` 표기로 싣고 `chain-decisions.md`「결정 기록」 에 `미답 기본값` 줄을 덧붙인다(`report.md`)** — 사용자가 돌아와 무엇이 자기 대신 정해졌는지 한 자리에서 본다.
- **같은 계획에서 같은 질문(`prior-answers.md`「앞선 답」 의 같은 질문 기준)이 다시 오면 넘기지 않고 같은 기본값(기본값 뒤 답이 있으면 그 답)으로 답한다** — 다시 넘기면 시한마다 체인이 같은 자리에서 선다.
- **기본값 뒤 답 — 기본값을 보낸 뒤 사용자가 그 질문에 답하면 체인을 멈추지 않고 이미 이어 간 워커에 다시 보내지 않는다. 보고 `기본값 뒤 답:` 줄에 질문·적용한 기본값·답 원문을 싣고 `chain-decisions.md`「결정 기록」 에 `기본값 뒤 답` 줄을 덧붙이며, 뒤 계획의 같은 질문에서는 그 답을 사용자 답으로 쓴다** — 사용자 답 「보고 기록 + 뒤 질문에 사용」. 「무응답 실패 뒤 늦은 답」(`manual-resume.md`)과는 다르다 — 그쪽 워커는 답을 못 받고 멈췄고, 이쪽 워커는 기본값으로 이어 갔다.
- **병렬 그룹이 돌 때와 사용자 중단 뒤에는 쓰지 않는다** — 병렬 대기는 `--answer-by` 를 받지 않고(동시 감시 보류), 중단 뒤에는 `interrupt.md`「사용자 중단」 대로 RESULT 를 따르지 않는다.

## 봉투 대조

- **재료는 그 승인 제시의 task 줄·`승인 필요 항목`·`DB 변경`·`실측 요지 대비:` 줄이다. 셋이 다 참이면 `Y (체인 승인 위임 — <체인 승인 때 사용자의 답 원문>)` 로 답한다** — 사용자는 체인 승인에서 이미 답했다.
  - ① task 가 그 계획의 재진술(결과·범위 밖)을 벗어나지도 빠뜨리지도 않고 — 결과의 각 항목(포함한 요청 밖 항목 포함)이 task 에 있고 spec `실측 요지:` 의 이 계획 초안 중 빠진 것은 `실측 요지 대비:` 에 근거가 있다 —, 다른 회차 task 를 흡수하지 않는다
  - ② `승인 필요 항목` 이 없거나, 체인 승인 때 명시해 승인받은 것이거나, 사용자 몫 ④ 밖의 변경(내부 API·설정 키)뿐이다
  - ③ `DB 변경` 이 체인 승인의 DB 목록 안이다(`../SKILL.md` 「답하는 기준」의 판정 불릿이 정한 새 DB 포함)
- **승인 제시 `결정:` 의 `(확인 필요)` 는 봉투 대조와 별개로 `../SKILL.md` 의 사용자 몫 넷과 판정 기준으로 가른다** — 그 표기는 워커가 답을 받지 못한 결정이라는 뜻이지 사용자 몫이라는 뜻이 아니다.

## 봉투 밖 승인 요청

- **하나라도 어긋나면 봉투 밖이다 — 회피 설계부터 지시한다.** 봉투의 task 줄 대조가 넘침이면 먼저 그 task 가 `../SKILL.md` 사용자 몫 ③ 의 지목에 드는지 본다 — 들면 넘침이 아니다(승인 제시 `요청 밖 항목:` 의 `(판정 원칙)` 표기가 그 후보다). 나머지 대조가 맞으면 `Y (코디네이터 판정 — <지목한 원칙·목표>)` 로 답한다 — 원본 이식 체인에서 원본 요소를 빼라고 하면 사용자 지시를 거스른다. 들지 않으면 그 task 없이 목표가 되는지 보고 되면 `E: <그 task 를 뺀다> (코디네이터 판정 — <근거>)`, 안 되면 사용자 몫 ③ 요청 범위 변경으로 사용자에게 넘긴다. task 줄 대조가 누락이면 `E: <빠진 항목> 을 넣거나 빠진 근거를 적는다 (코디네이터 판정 — <근거>)`. `승인 필요 항목`·`DB 변경` 대조가 어긋나면 사용자 몫(`../SKILL.md` 넷)이 아닌 한 어긋난 항목이 생기지 않는 설계가 있으면 `E: <회피 설계> (코디네이터 판정 — <근거>)`, 없을 때만 `Y (코디네이터 판정 — <근거>)` — 워커가 스스로 고른 설계가 만든 승인 항목은 대개 다른 설계로 사라진다(`../../plan/SKILL.md` Step 4). 봉투 밖이라는 사실만으로 사용자에게 넘기지 않는다.
