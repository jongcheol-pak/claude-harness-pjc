# 회차 넘김 (`pjc:plan` 경유)

> `../SKILL.md` 「계획 목록」이 이 파일을 연다 — args 첫 블록이 `회차 경계:` 일 때, 곧 `pjc:plan` Step 5 가 회차를 나눠 넘긴 실행에서만 읽는다. 계획 목록을 사용자가 직접 준 실행은 읽지 않는다.

## 넘김 args

**`pjc:plan` 이 회차를 나눠 넘겼으면 args 는 아래 다섯 블록이다 — 경계는 그 단계가 사용자와 확정했고, 회차별 확인은 아래 「확인 인터뷰」가 받는다.**

```
회차 경계:
plan 1: <한 줄>
plan 2: <한 줄>
회차 재진술:
[plan 1]
- 결과: …        (2-6 서식 6줄 — 동의 전 초안)
[plan 2]
…
인터뷰 요지:
[공통] Q: … / A: <사용자 답 원문>
[plan 1] Q: … / A: <사용자 답 원문>
회차 체크리스트:
[plan 1] ① <Q/A 인용 | 미확인> ② … ③ … ④ … ⑤ …
[plan 2] …
회차 실측:
[plan 1]
- task 초안:     <T1 한 줄 · T2 한 줄 … | 미측정>
- 바뀌는 파일:   <경로 · 경로 | 미측정>
- 승인 필요 후보: <항목 | 없음 | 미측정>
- 요청 밖 후보:   <항목 — 왜 필요한가(근거 파일:줄) | 없음 | 미측정>
[plan 2]
…
```

- `회차 경계:` 는 계획 목록, `회차 재진술:` 은 계획마다의 재진술 **초안**, `인터뷰 요지:` 의 `[공통]` 과 그 계획 태그 Q/A 는 그 계획의 「원문:」, `회차 체크리스트:` 는 아래 「확인 인터뷰」가 빈 항목을 가르는 입력이다.
- **`회차 실측:` 은 `pjc:plan` 이 Step 3·4 에서 잰 것이고 세 자리로 간다** — 요청 밖 후보는 아래 「확인 인터뷰」의 질문, 바뀌는 파일·승인 필요 후보는 `../SKILL.md` 「체인 승인」의 같은 칸, task 초안·바뀌는 파일은 spec 의 `실측 요지:` 다. 이것이 없으면 원 세션이 잰 것을 워커가 처음부터 다시 재고, 체인 승인 화면은 실측 없는 추측을 보인다.
- **`미측정` 칸은 체인 승인에 「워커 실측 후 확정」으로 보인다** — 원 세션이 그 회차를 분해하지 않았으면 추측으로 채우지 않는다.

## 확인 인터뷰

- **계획마다 확인 화면을 먼저 낸다 — 재진술 초안 6항목과 다섯 항목을 보이되, 찬 항목에는 인용한 Q/A 의 태그를 붙이고 빈 항목은 「미확인」으로 보인다. 그다음 빈 항목만 2-2 서식으로 하나씩 묻는다** — 찬 항목은 앞 단계에서 사용자가 이미 답했으니 다시 묻지 않는다. 사용자가 확인 화면에서 인용·태그를 고치면 그것을 따른다.
- **같은 화면에 그 회차의 요청 밖 후보를 보이고, 빈 항목 다음에 후보마다 2-2 서식으로 하나씩 묻는다 — 답은 `포함 / 제외 / 보류` 셋이다** — 요청하지 않은 수정이 사용자 모르게 체인에 들어가지 않게 한다. 후보의 기준은 `../../plan/SKILL.md`「Step 5. plan.md 작성」 이 정본이다.
  - 포함 → 재진술 `결과` 에 더한다 · 제외 → `범위 밖` 에 더한다 · 보류 → `범위 밖` 에 `(보류 — Deferred)` 를 붙여 더한다
  - 재진술에 넣어야 워커의 승인 대조 ①이 그 답을 안다 — 「원문:」에만 두면 대조할 재료가 없다.
- **빈 항목과 후보를 다 채우면 그 계획의 재진술과 다섯 항목을 다시 보이고 계획마다 명시적 동의를 받는다(2-6)** — `pjc:plan` 이 받은 동의는 요청 전체에 대한 것이라 회차별 성공의 모습·범위 밖은 아직 확인되지 않았다. 여기서 받은 답과 고친 재진술은 그 계획의 「원문:」 Q/A 에 덧붙인다.
