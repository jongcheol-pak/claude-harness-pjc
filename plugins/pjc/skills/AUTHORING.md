# pjc 스킬 작성 스타일 가이드

> **이 파일은 스킬이 아니라 작성 가이드 문서다.** (skill frontmatter `name:`/`description:` 없음 → 플러그인 로더가 스킬로 등록하지 않는다. 스킬은 `<name>/SKILL.md`만 대상.)

pjc 플러그인에 **새 스킬을 추가하거나 기존 스킬을 개정**할 때 참고하는 스타일 가이드다.
기존 8개 스킬을 이 골격으로 **소급 재작성하지 않는다**(최소 수정 원칙) — 향후 작업의 참고용이다.

상충 시 우선순위: **글로벌/프로젝트 `CLAUDE.md` 절대·보안 규칙 > 기존 스킬의 고유 규칙 > 이 가이드.** 이 가이드는 그것들을 대체하지 않고 보완한다.

## 권장 섹션 골격

스킬 본문은 다음 순서를 기본으로 한다(해당 없는 항목은 생략 가능):

1. **Quick start** — 가장 흔한 사용을 **구체 호출 예시**로 맨 앞에 보여준다. 추상 설명보다 "이렇게 부르면 이렇게 된다"가 빠르다.
2. **Why(왜)** — 이 스킬/절차가 왜 이렇게 동작하는지 1~3문장. 의도를 알면 LLM이 경계 사례에서 더 잘 판단한다.
3. **Workflow** — 번호 매긴 절차. 각 단계는 명령형("확인한다", "작성한다").
4. **Anti-patterns (WRONG/RIGHT)** — 추상 금지 규칙 대신 **실제 함정을 대비 예시로** 보여준다(아래 원칙 ① 참조).
5. **Checklist** — 완료를 **기계로 검증 가능한 기준**으로 적는다("잘 동작한다" 금지).
6. **See also** — 관련 형제 스킬 링크(언제 그쪽을 써야 하는지 한 줄).
7. **Troubleshooting** — 흔한 실패와 대응(공용 내용은 별도 파일로 분리해 포인터).

## 작성 원칙

① **추상 규칙보다 WRONG/RIGHT 구체 예시.** "올바르게 매칭하라" 같은 추상 지시는 약하다. 실제 함정을 코드/예시로 대비시킨다:
   ```
   WRONG: cwd.startsWith(projectPath)  → "/repo-a"일 때 "/repo-a-staging"을 오매칭
   RIGHT: cwd === projectPath || cwd.startsWith(projectPath + sep)  → 디렉터리 경계 검사
   ```

② **"왜"를 설명한다.** 대문자 MUST·NEVER를 늘어놓기보다 이유를 적는다 — 이유를 이해한 모델이 더 정확하다(CLAUDE.md "영리한 추상화보다 명시적·직접적" 정신과 일치). 단 진짜 절대 규칙(보안·파괴적 작업)은 단호하게.

③ **빈 결과 = 사실대로 보고(지어내지 않음).** 검색·조회·집계가 **아무것도 못 찾으면** "없음"을 그대로 보고한다. 비었다는 이유로 기억·추측으로 내용을 채우는 것은 환각이다:
   ```
   WRONG: 결과가 비어서 "지난 한 주 생산적으로 작업했다"를 기억에서 합성
   RIGHT: "지난 7일 해당 항목 없음"
   ```
   (pjc 전역 절대 금지 "검증 없이 완료 보고"의 조회·보고판. 가장 위험한 곳에만 명시 — 모든 스킬에 중복 삽입하지 않는다.)

④ **pjc 공통 지침 준수.** 한글 작성, UTF-8, 승인 워크플로우(구조·공개 API·의존성·commit은 승인 필수), description=트리거 1차 메커니즘(near-miss 포함), Type 분류·자율 루프 등 **pjc 고유 규칙을 이 가이드가 대체하지 않는다**. 골격은 형식 권장일 뿐, 내용의 진실원천은 CLAUDE.md와 기존 스킬 규칙이다.

## description 작성 (트리거 메타데이터)

스킬 트리거의 1차 메커니즘이다(skill-creator 가이드 정합):
- **무엇을 하는가 + 언제 트리거되는가**를 모두 담는다.
- 구체적 트리거 표현(한/영)을 나열해 undertriggering을 막는다(약간 pushy하게).
- **near-miss(트리거 금지) 경계**를 명시한다 — 과트리거를 줄이고 형제 스킬과의 경계를 분명히 한다.

## 출처

이 골격·원칙은 외부 오픈소스 스킬(agentmemory의 스킬 미시 구조, Understand-Anything)의 **프롬프트 패턴만** 검토·차용한 것이다. 두 프로젝트의 기능/인프라(메모리 엔진·MCP·지식 그래프 등)는 도입하지 않았다.
