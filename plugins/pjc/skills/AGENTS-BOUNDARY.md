# AGENTS.md 내용 경계 (정본)

> 이 파일은 스킬이 아니라 **스킬 공용 참조 문서**다(frontmatter 없음 — 로더는 `<name>/SKILL.md`만 스킬로 등록한다).
>
> **이 파일이 「AGENTS.md 내용 경계」의 정본이다.** `docs/harness-conventions.md`에서 옮겨 왔다 —
> 그 문서는 **하니스 레포에만 있어** 다른 프로젝트 세션에서 포인터를 따라가도 열리지 않았다.
> 플러그인과 함께 배포되는 이 자리로 옮겨 어느 레포에서든 도달하게 한다.
> `pjc:plan`·`record-project-fact`·`llm-wiki`는 이 파일을 가리키기만 하고
> 각자 재서술하지 않는다.

> `docs/harness-conventions.md`의 「조건부 참조 문서 크기 임계」가 **얼마나 큰지**를 재고 같은 문서의 「AGENTS.md 주입 상한 관리」가 **넘쳤을 때**를 다룬다면, 이 문서는 **애초에 무엇이 들어가는가**를 정한다. 셋은 계측 → 경계 → 처방의 한 벌이며, 경계가 없으면 나머지 둘은 매번 같은 자리로 돌아온다(실측: `AGENTS.md`가 `2026-08-05 16,249B → 08-06 13,965B → 08-20 16,348B → 08-21 14,783B → 08-22 13,192B` — 하루 평균 +170B로 자라 2주에 이관 3회).

**판정 기준은 하나다 — `AGENTS.md`는 매 세션 자동 주입되고 위키는 필요할 때 읽는다.** 그래서 *"매 세션 예외 없이 필요한가 · 틀리면 즉시 사고나는가"* 가 갈림선이다.

| 저장처 | 담는 것 | 근거 |
|---|---|---|
| **`AGENTS.md`** | 위키 포인터 1줄 · `## Build & Test`(빌드/실행/테스트 **명령** + **배포·릴리즈 규약** + ⚠ 1줄) · **검증 매핑 표** · `## Conventions`(인코딩·줄바꿈·주석 언어 + **아키텍처 선언 1줄** — "어디에 코드를 둘지") · `## DO NOT` · `## Plan Location`(**PRD 경로만** — plan은 루트 `plan.md` 고정이라 `Plan Location:` 선언을 두지 않는다. **PRD를 쓰지 않는 레포는 이 절 자체를 두지 않는다**) · `## 데이터 접근`(명령·환경변수 **이름**만) · `## 산출물·파일 관리`(산출물·캐시 **경로**만) | 검증 단계마다 실행하거나, 파일을 쓸 때마다 적용되거나, 어기면 되돌리기 어렵다. **검증 매핑 표는 `AGENTS.md`에 있어야 게이트가 켜진다** — `pjc:implement` V-2가 그 표의 존재를 조건으로 쓰므로 옮기면 문서 이동이 아니라 동작 변경이다. **배포·릴리즈 규약도 여기다** — 릴리즈 때만 쓰지만 틀리면 외부로 나가 되돌릴 수 없고, 글로벌 지침이 *"규약 위치는 프로젝트 CLAUDE.md 또는 AGENTS.md"*로 이 파일을 지목한다. **절을 새로 만들지 않고 `## Build & Test`의 `Release` 항목으로 넣는다** — CI 명령은 같은 절의 Build/Test 가 이미 담는다 |
| **레포 상세 문서**(이 레포는 `docs/harness-conventions.md`) | 각 검증 명령이 **무엇을 대조하는가** · **함정** · 축의 설명 | 명령을 실행할 때가 아니라 결과를 해석할 때 필요하다 |
| **위키**(`llm-wiki`) | 프로젝트 성격·`tech_stack`·플랫폼·레포 경로·**아키텍처 상세와 온보딩**(레이어·핵심 흐름·복잡도 핫스팟) · 기능 목록 · 크로스 세션 작업 규약·함정 · 결정 이력 · 기능 상세 | 그 작업을 할 때만 필요하고 계속 누적되며 코드를 읽으면 복구된다. 손으로 유지하는 사본이 낡는 대표 자리다 |
| **어디에도 안 감** | plan 진행 상태 · "다음 작업"·"다음 회차가 알아야 할 것" · 세션 인계 서술 | 진행 중은 `plan.md`, 영구 기록은 git 커밋 본문이 정본이다 |

## 생성물 골격 (정본)

**절 구성도 그 배치 순서도 아래 뼈대가 정본이다** — 위 표는 *무엇을 담는가*의 목록이고 순서를 정하지 않으므로, 두 곳에서 파생한 순서가 갈리지 않도록 여기서 못박는다. `AGENTS.md`를 새로 만들 때(`pjc:plan` Step 1)와 절을 더할 때(`pjc:record-project-fact`)가 같은 뼈대를 본다. 스택이 달라도 이 구성은 같다.

```markdown
# AGENTS.md — Agent Guide

## 위키
- **프로젝트 페이지**: `20_projects/<personal|work>/<프로젝트명>.md` (LLM WIKI vault)
- 프로젝트 성격·기술 스택·디렉터리 구조·**아키텍처 상세**·기능 목록은 **위키가 정본**이다.
  이 파일에 중복 기재하지 않는다 (단 `## Conventions`의 **아키텍처 선언 1줄**은 여기 남는다).

## Build & Test
- **Build**: `<명령>`   - **Run (개발)**: `<명령>`   - **Test**: `<명령>`
- **Lint/Format**: `<있으면>`   - **Clean**: `<있으면>`
- **Release**: `<버전을 올린 뒤 무엇을 하는가 — 태그·발행·배포 명령. 없으면 "없음">`
> ⚠️ Build/Test가 비면 `pjc:implement`의 검증이 무의미해진다.

<검증 매핑 표 — 변경 파일 패턴 → 필수 검증. 축이 둘 이상일 때만 만든다>

## 데이터 접근
- **DB/스토어**: <없으면 "없음">
- **접속**: <환경변수 **이름**만 — 실제 값 금지>

## 산출물·파일 관리
- **빌드 산출물** / **런타임 생성물** / **임시·캐시**: <경로만>

## Conventions
- **아키텍처**: <계층을 어떻게 갈랐는지 1줄. 앱인데 계층을 두지 않았으면 **그 근거를** 같은 줄에>
- **인코딩** / **줄바꿈** / **주석 언어** / **이름 규칙** / **테스트 위치** / **포맷터**

## DO NOT
- 실제 IP·계정·비밀번호·토큰·DB 연결문자열을 코드·문서·plan에 기록 (환경변수 이름만)
- 환경변수 파일(`.env*`)·secrets·인증서 커밋
- 빌드 산출물 디렉터리 커밋
- 검증 스크립트에 평문 자격증명·`-WindowStyle Hidden`·과도한 `-ExecutionPolicy Bypass`
- <그 밖 stack별 금지사항>
```

- **`## Plan Location`은 그 레포가 PRD를 쓸 때만 만든다**(경로만).
- **`## Stack`·`## Repository Structure` 같은 프로젝트 정보 절을 만들지 않는다** — 위 표가 위키로 배정했다.
- **스택 고유의 UI·디자인·마크업 규칙을 여기 넣지 않는다** — 위 표의 *"크로스 세션 작업 규약·함정"* 이라 위키 `conventions.md` 소관이다.
- **아키텍처는 「1줄」이다** — 선택지 나열이나 하위 설명 블록을 두지 않는다. 상세는 위키가 갖는다. **비채택 근거도 그 1줄 안에 넣는다**(예: *"계층형(서비스 중심) — 규칙이 얇은 앱에 과한 추상화를 피한 선택"*). **빈칸으로 두지 않는다** — 근거 없는 미분리는 결정이 아니라 누락이고, 그것을 가르는 자리가 여기뿐이다.

**증가 억제 규칙 — 이 표가 「남는다」고 한 절 안에도 적용된다.** 절 이름이 잔류라고 그 절 전체가 잔류인 것이 아니다. 절 **안**을 가르는 축은 하나다 — ***명령을 실행할 때 필요한가, 결과를 해석할 때 필요한가.*** 앞은 남기고 뒤는 **레포 상세 문서**(이 레포는 `docs/harness-conventions.md`)로 보내고 포인터만 남긴다.

- `## Build & Test`에는 **명령과 ⚠ 경고 1줄만** 둔다 — *"그 명령이 무엇을 대조하는가"*·*"어떤 함정이 있는가"* 는 상세다. 검증 축이 늘 때마다 이 절이 함께 자라는 것이 위 증가율의 정체다.
- **절 단위 판정만으로는 줄지 않는다** — 실측: 한 프로젝트의 `## Plan Location`이 **41,555B**였는데 남을 것은 경로 4줄이었다(나머지는 진행 상태·인계 서술이라 「어디에도 안 감」).

**서술 밀도 규칙.** `AGENTS.md`의 독자는 사용자가 아니라 **다음 세션의 에이전트 자신**이다. 설득·경위·근거 서술을 쓰지 않고 **명령·값·규칙·⚠ 1줄**만 적는다. *"왜 그런가"* 가 필요하면 **레포 상세 문서**나 위키로 보내고 포인터를 남긴다.

**이 문서가 정본이다 — 표와 위 두 규칙 전부.** `pjc:plan`·`record-project-fact`·`llm-wiki`는 여기를 가리키기만 하고 각자 재서술하지 않는다.
