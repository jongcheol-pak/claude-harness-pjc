# 삭제 복구 경로 판정

> 삭제 대상이 있는 계획·실행·리뷰에서만 읽는다.

## 삭제 복구 경로 판정

**파일 삭제는 건수가 아니라 복구 경로로 가른다.** 지운 내용을 되살릴 수 있으면 몇 개를 지우든 사용자가 잃는 것이 없고, 되살릴 수 없으면 한 줄이라도 잃는다 — 그래서 실행 중 정지를 수가 아니라 이것으로 가른다.

- **복구 경로가 있다 = `git ls-files -- <경로>` 가 1줄 이상이고 `git status --porcelain --ignored -- <경로>` 가 0줄이다** — 지운 내용이 git 이력에 있어 `git checkout <커밋> -- <경로>` 로 되살아난다. 이 판정의 복구 경로는 git 커밋만 센다(원격·다른 위치의 사본은 세지 않는다). `--ignored` 를 빼지 않는 것은 디렉터리를 지우면 그 안의 ignored 파일(`.env` 등)까지 사라지기 때문이다.
- **복구 경로가 있으면 plan 승인으로 덮고 실행 중 다시 묻지 않는다(건수 무관)** — 되살릴 수 있는 삭제에서 루프를 세우면 사용자는 잃을 것이 없는 일에 답하러 와야 하고, 그동안 나머지 task 도 선다.
- **복구 경로가 없으면 `../SKILL.md`「Step 3. 영향 범위 실측」 이 실측해 `plan-template.md`「승인 필요 항목」 에 올린다** — 실행 중에 처음 드러나면 루프가 그 자리에서 서지만, 계획에 올리면 plan 승인 한 번으로 끝난다. 되돌리는 방법은 실행 직전 시스템 임시 폴더 백업과 그 위치이고, plan 승인이 곧 그 삭제의 승인이다.
- **판정은 실행 직전 다시 돈다 — 빼는 것은 행위자 기준이다**: 진행 중 task 가 새로 만든 경로와 `plan.md`·`notes.md` 는 판정 밖이고(지킬 사용자 내용이 없다), 진행 중 task 가 고친 경로는 그 task 착수 때 깨끗했을 때만 `status` 줄을 무시한다. **그 밖의 줄은 계획 뒤에 생겼어도 넣는다** — 사용자·병행 세션의 미커밋 편집이 거기 있다. 앞 task 의 산출물은 task 마다 커밋돼 이미 이력에 있다.
- **이동·이름 변경과 덮어쓰기는 이 판정 밖이다** — 이동·이름 변경은 내용이 남고, 덮어쓰기는 글로벌 「범위 확인」의 「승인 또는 사전 백업」이 맡는다.
