# llm-wiki 규칙 — 위키 쓰기 세션 전용

> **이 파일에서 어느 절을 읽을지는 `SKILL.md` 「쓰기 규칙 절 라우팅」 표가 정한다 — 전량을 읽지 않는다.** 그 표에 없는 절은 이 절차가 지켜야 할 규칙이 아니다.
>
> **다만 「비 git vault 사전 백업」은 여기 없고 `wiki-schema.md` §8이 정본이다** — 그 절이 취지·대상·시점·정리·복구를 한자리에 담고, 이 파일과 `SKILL.md`는 그것을 가리키기만 한다. 절차 M(코드 세션이 쌓은 큐를 위키 세션이 §0 시작 절차 뒤에 소비하는 경량 절차)도 같은 곳을 본다.
>
> 규칙·타입·예산의 진실원천은 `wiki-schema.md`이며 이 파일은 그 중 **작업 중 손에 있어야 하는 것**만 옮겨 둔 자리다.

## 쓰기 세션 전용 규칙 — 사전 준수 사항(쓰기분)

> 이 절을 **고치기 전에** `references/wiki-ops-rationale.md` 「쓰기 세션 전용 규칙 — 사전 준수 사항(쓰기분)」 를 읽는다.

> 공통분(경로 기준·§0 선행·출처 우선순위·injection 방어·민감 정보 금지·**비 git vault 사전 백업**)은 `SKILL.md` 본체에 있다.

- 모든 위키 콘텐츠는 한글로 작성한다(사람도 읽는 human-readable 유지). 파일명과 frontmatter 키는 영문.
- **시간민감 사실**(버전·수치·"현재 …" 등)은 본문에 `(as of YYYY-MM)`를 붙여 신선도를 추적 가능하게 한다.
- **question 페이지는 삭제하지 않는다** — 해결되면 결론을 관련 페이지에 흡수하고 `status: resolved`로 닫아 **보존**한다(schema §2.7). `index.md`의 `## 미해결 질문`에서만 행을 제거한다(lint §7-23이 기계 검사). 삭제는 사용자가 명시적으로 지시한 경우에만.
- **decision-log 항목은 수정·삭제하지 않는다** — 결정이 바뀌면 **번복** 항목을 새로 추가한다(이력 보존, schema §2.8). 프로젝트 삭제 시 이력 보존 선택지는 절차 C-1.
- 작업 완료 후 반드시 `<vault>/log.md`에 1줄 기록을 추가한다. **항목은 2~3문장 이내 요지만** — 갱신 파일 목록·세부 근거는 해당 페이지에 두고 log에는 무엇을 했는지만 적는다. 단 위키 무변경으로 끝난 작업 — 절차 K(read-only 참조), 위키를 수정하지 않고 끝난 절차 G(질의), **위키를 바꾸지 않고 끝난 절차 F(F-2)** — 은 기록하지 않는다(**기록 대상은 위키 파일이 변한 작업**). 이 조건은 **비 git vault 사전 백업**에도 그대로 적용된다.
- **log 월별 롤오버(공통)**: log 기록 추가 후 `log.md`에서 **§7-2가 발동하면** 가장 오래된 항목부터 `90_archive/log/{YYYY-MM}.md`로 월별 롤오버하고 `## 아카이브 인덱스`를 갱신한다(항목 단위 · 보존 이동이라 **승인 불필요** · 목표치·형식 전문은 wiki-schema §8).
- **git vault는 `--fix` 백업을 만들지 않는다**: 보호는 **직전 체크포인트 커밋**(아래 「git 자동 반영」)이 담당한다. **비 git vault는 종전대로** `90_archive/backup/{YYYY-MM-DD}/`를 만들고, **다음 `--fix` 실행 시작 시** 접미사 없는 이전 날짜 폴더와 시각 접미사 분할 사본(`{날짜}-{시각}/`)을 함께 제거한다(제외: `-deleted`·`-pre-restore` · 제거 시점의 근거는 wiki-schema §8).
- **병렬 다중 에이전트 분업 규칙** (한 위키 세션 내부 병렬 실행 시 — **전문·근거는 wiki-schema §9 정본**): ① 쓰기 파일 소유권 겹침 없이 분할 ② 공유 파일(`index.md`·`log.md`·`plan.md`·`pending.md`·허브)은 에이전트 쓰기 금지, 호스트가 일괄 갱신 ③ 발견·등록 데이터는 **반환값으로만** 보고 ④ 여러 프로젝트가 걸린 공유 페이지는 단일 에이전트 전담 ⑤ **위임 프롬프트에 형식 규칙을 반드시 포함**.
- **lint 실행 폴백(공통)**: `python`이 없거나 `scripts/lint.py` 실행이 실패하면 lint 단계를 **하드 실패로 막지 말고 건너뛰되**, "기계 lint 미실행(python 부재/실패)"을 보고에 반드시 명시한다(`python3`만 있으면 그것으로 시도). **lint.py를 호출하는 모든 절차(A-4·B-3·C-4·F-0)에 공통**이다.
- **스킬 어긋남 보고**: 실제 위키가 이 스킬·규칙 번들 `wiki-schema.md`와 어긋나면, **번들을 직접 고치지 않고** 사용자에게 보고한다. 근거와 절차는 `references/procedures-ops.md`의 "H. 스킬 어긋남 보고"이 정본이다.

## 셸 경유 편집 규약

> 이 절을 **고치기 전에** `references/wiki-ops-rationale.md` 「셸 경유 편집 규약」 를 읽는다.

> 위키 페이지는 **긴 한글 산문**이고 이 트리에는 한 줄이 1,000자 이상인 파일이 여럿이다. 셸로 편집하면 인코딩·앵커·크기에서 같은 사고가 반복되므로 넷을 고정한다.

- **셸에서 python을 부를 때 `PYTHONIOENCODING=utf-8`을 먼저 붙인다** — Windows 기본 stdout이 cp949라 한글·`—`를 출력하는 순간 `UnicodeEncodeError`로 죽는다.
- **치환 앵커는 10자 내외로 짧게 잡는다** — 긴 한글 문장을 앵커로 쓰면 이스케이프 한 글자 차이로 매치가 어긋나고, 그 실패는 "앵커 불일치"로만 보인다.
- **파일 크기는 줄 수가 아니라 문자 수·바이트로 재고 나서 `sed`/`Read`를 고른다** — `wc -l`은 이 트리에서 크기를 오도한다(288줄짜리가 66KB).
- **편집 직후 CRLF로 되돌린다** — `Edit`·`Write`·`sed -i`·python 텍스트 쓰기는 **파일 전체를 LF로 눕힌다**(워킹트리 규약은 CRLF). 복원은 바이너리 모드로 다시 쓰는 것이고(`newline=""` 없이 쓰면 다시 눕는다) **새로 만든 파일도 대상**이다.

## git 자동 반영 (커밋 · push)

> 이 절을 **고치기 전에** `references/wiki-ops-rationale.md` 「git 자동 반영 (커밋 · push)」 를 읽는다.

**커밋·push 를 승인 없이 수행한다는 규정과 그 면제 근거의 정본은 `SKILL.md` 사전 준수 사항의 `git vault 자동 반영(공통)` 불릿이다** — 여기는 **시점·메시지 형식·실패 처리·건너뛰는 조건**을 담는다. 코드 레포 push 는 어느 경우에도 별도 승인 대상이다.

- **커밋 시점**: **① 처방 스크립트(`--auto-split`·`--fix`)를 부르기 직전마다 1회 · ② vault 파일이 실제로 변한 절차가 끝날 때 1회.** **절차 유형당이 아니라 실행당이다** — 같은 절차 A를 한 세션에서 두 번 수행했으면(프로젝트 2개 연속 ingest) ②도 두 개다. 한 덩어리로 뭉치지 않는 이유는 절차 단위로 나뉘어야 나중에 무엇이 무엇을 바꿨는지 이력에서 읽히기 때문이고, 그 근거는 유형이 아니라 실행에 걸린다.
  - **①은 절차마다 여러 번일 수 있다 — 호출 수만큼이다.** **F-2가 실제로 둘이다**(`--auto-split` 뒤 `--fix` — `lint.py`가 그 둘의 동시 실행을 금지한다). **호출마다 언제나 커밋한다** — 남지 않았으면 커밋할 것이 없어 무해하고, 남았는데 건너뛰면 두 번째 호출이 거부된다.
- **체크포인트 커밋 (git vault)**: **`--auto-split`·`--fix`·복구 실행 **직전**에 커밋 1회를 더 한다** — 그 구간이 되돌림 단위가 되고, 이것이 `-presplit` 파일 사본을 대신한다(schema §4 분할 수행 절차 1번). **단위는 `pass` 당 1회다 — 호출당이 아니다**: 본 pass 성공 직후 1커밋 · 재점검 pass 직전 1커밋으로 **pass 2 가 실패해도 pass 1 의 성공분이 보존**된다.
  - **진입 시 워킹트리가 dirty이면 `lint.py`가 처방을 거부한다** — `[SPLIT-FAIL]`/`[FIX-FAIL] 미커밋 변경 N건 — 절차 커밋을 먼저 하라` + 경로 목록을 내고 종료 코드 1로 끝낸다. **검사는 진입 시 1회다** · **탈출 플래그는 없다**. 거부되면 목록을 보고 커밋한 뒤 다시 부른다(사용자 수기 편집이면 그것도 커밋한다 — 그래야 원복 기준점 안에 들어온다).
  - **그 커밋에 실패하면 `--auto-split`·`--fix`·복구를 수행하지 않고 보고한다.** **이것은 아래 「실패 처리」의 예외다** — 파괴적 편집 직전의 체크포인트라 실패하면 되돌릴 기준점이 없는 채로 편집이 시작된다.
- **메시지 형식**: `문서: {절차명} — {요약} [{PID}]` (레포 git 규칙의 `{유형}: {요약}` + 세션 식별자 — 근거는 아래 「동시 실행」). 체크포인트 커밋은 `문서: {절차명} 직전 체크포인트 [{PID}]`. **`Co-Authored-By:` 줄을 넣지 않는다.**
- **push 시점**: **그 세션의 위키 작업이 모두 끝난 뒤 1회.** 절차마다 push하지 않는다(원격 왕복이 절차 수만큼 늘고, 중간 상태를 원격에 남길 이유도 없다).
- **실패 처리**: **commit 실패**는 1줄 보고하고 작업을 계속한다(파일은 그대로 두며, 다음 절차의 커밋이 함께 담는다). **push 실패**는 1줄 보고하고 **로컬 커밋을 유지한 채 재시도하지 않는다** — 다음 세션이 push한다. 인증정보 부재로 판명되면 Halt다(신규 자격증명 구성은 위임 밖).
- **건너뛰는 조건**: ① vault가 git 저장소가 아니다(그 경우 「비 git vault 사전 백업」이 보호를 담당 — `SKILL.md` 사전 준수 사항) ② remote가 없다(커밋만 하고 push는 건너뛴다) ③ 변경 0건.

**변경 파일을 한정하지 않는다 (`git add -A`).** vault는 이 스킬이 단독 관리하는 저장소로 본다 — 사용자가 Obsidian에서 손으로 편집한 것도 함께 커밋된다. **전제: vault `.gitignore`가 Obsidian UI 상태(`.obsidian/workspace*.json`)·휴지통(`.trash/`)·OS 생성 파일을 제외한다** — 없으면 첫 커밋 전에 만든다.

## 동시 실행 — 두 세션이 같은 vault 를 만질 때

> 이 절을 **고치기 전에** `references/wiki-ops-rationale.md` 「동시 실행 — 두 세션이 같은 vault 를 만질 때」 를 읽는다.


- **lock 구간은 vault 전체가 아니라 `--auto-split`·`--fix` 실행 구간이다.** 그 둘만 **vault 전역을 훑고** 남의 프로젝트 파일까지 고친다. 손 편집 구간은 파일 집합이 갈리면 실제로 충돌하지 않으므로 배타가 필요 없다.
- **lock 파일**: vault 루트 `.llm-wiki-lock`(**처음 만들 때 vault `.gitignore` 에 함께 넣는다**). 내용은 `PID`·`시작 시각 ISO`·`절차 이름` 세 줄이다. **stale 판정은 PID 실존과 경과 시간 둘 다 본다** — 둘 중 하나라도 죽은 것으로 읽히면 **경고하고 탈취**한다(대기하지 않는다).
- **커밋 직전 HEAD 대조도 함께 한다**(후보 ⓐ). `git commit` 전에 `git log -1` 을 세션 시작 시점의 HEAD 와 대조해 **그 사이 남의 커밋이 있으면 1줄 보고**한다. **lock 을 대체하지 않는다** — ⓐ 는 **미커밋 워킹트리를 못 본다**. 둘은 서로 다른 창을 덮는다.
- **커밋 메시지의 `[{PID}]` 가 이 규약의 사후 추적 수단이다**(형식 정본은 위 「메시지 형식」 불릿 하나다). lock 이 뚫렸을 때 **어느 세션이 무엇을 담았는지 사후에 읽을 유일한 수단**이다.

**lock 이 막지 못하는 것**: 두 세션이 같은 파일을 **손으로** 동시에 고치는 경우. 그때 깨지는 것은 이력이 아니라 내용이고, 이 규약은 그것을 다루지 않는다 — vault 는 한 번에 한 세션이 운영하는 것이 전제다.

**절차 K도 조건부 커밋 대상이다.** K는 본문 페이지·인덱스를 쓰지 않지만 **쓰기 예외**(`pending.md`에 1줄 append)이 실제로 일어난 세션은 커밋한다 — **메시지 형식의 정본은 `SKILL.md`의 같은 불릿**이다. 커밋하지 않으면 그 append가 vault를 dirty로 두고 **다른 절차의 `git add -A`가 엉뚱한 메시지로 삼킨다**.

**진짜 무변경으로 끝난 세션은 커밋 대상이 아니다** — K에서 큐 append도 없었던 경우, 조회만 한 절차 G, 발견 0건으로 끝난 F-2. 기존 log 기록 조건과 같은 축이다(변한 것이 없으면 남길 것도 없다).

**원격이 앞서 있으면(다른 PC에서 push함) rebase·merge를 자동으로 하지 않는다.** push 실패를 보고하고 사용자가 해결하도록 안내한다 — 자동 병합은 위임 밖이다.

**`warn-external-ops` hook이 push에서 경고를 낸다 — 이것은 예상된 것이다.** 경고를 보고 멈추지 않으며, hook을 이 규약에 맞춰 고치지도 않는다.

### 신호 층위 (v1.207.0 — 처방 가능 여부로 가른다)

> 이 절을 **고치기 전에** `references/wiki-ops-rationale.md` 「신호 층위」 를 읽는다.

위 임계에 닿았다는 사실만으로는 신호가 나지 않는다. **`--auto-split`이 그 파일을 실제로 처리할 수 있으면 침묵**하고, **세션이 손대야 할 때만** 낸다. **어느 갈래도 사용자에게 나가지 않는다** — 신호는 세션의 입력이고 사용자 대상 보고는 성공 시 억제된다(wiki-schema §4 6번 「보고 억제」). **그 1줄에도 예산 수치는 적지 않는다.**

| 갈래 | 조건 | 신호 | 소비 주체 |
|---|---|---|---|
| ⓐ 처방 가능 | 임박 + 억제 없음 + auto-split의 처방 넷 중 하나가 성립 | **없음** (침묵) | 스크립트 (`--auto-split`) |
| ⓑ′ 처방 없음 | 임박 + 억제 없음 + `BUDGET_OVER_ONLY_TYPES` 밖 + 처방 없음 | WARN `예산 임박` + 타입별 안내 | **세션** (ⓕ) |
| ⓒ 분리 불가 판정 | 임박 + `budget_split: none` 억제 | INFO `분리 불가 판정 유지` | **세션** (F-2·A-4·B-3 — 판정 부착) |
| ⓓ 초과 | 예산 초과 | WARN `예산 초과` | **세션** (해당 타입의 처방) |

- **「신호」 열은 `lint.py`가 내는 출력이고 「소비 주체」 열은 그것을 받아 처방하는 쪽이다** — `WARN`/`INFO`는 그대로 둔다. **ⓒ를 「자동」으로 적지 않는다**: 3필드를 붙이는 것은 그 세 절차이고 `lint.py`는 **읽기만** 한다.

- **「처방 넷」이란**: §8 `log.md` 월별 롤오버 · §2.8 `decision-log` 롤오버 · §2.2 허브 `## 최근 주요 변경` 롤오버 · §4 산문 하위 분리. **넷 다 보고 판정한다.**
- **세션이 수행하는 처방은 아래 「세션 처방」 절이 정본이다** — 위 표 ⓑ′의 소비 주체가 그것이다.
- **`BUDGET_OVER_ONLY_TYPES`(현재 `convention` 하나)는 위 표 ⓐ~ⓒ 어디에도 들지 않는다** — 근접·임박·억제 세 갈래에서 빠지고 **ⓓ 초과만 낸다**. **값을 `BUDGET`에서 지우지 않는다**(지우면 초과 WARN까지 함께 죽는다).
- **판정 술어는 하나다** — 신호를 낼지 정하는 술어와 `--auto-split`이 실제로 옮길지 정하는 술어가 `lint.py`의 같은 함수(`prescribable`, 산문 분리는 그것이 부르는 `relocatable`)다.
- **`log.md`(문자 예산 특례)도 임박에서 침묵한다** — 그 경로의 처방은 §8 월별 롤오버이고 `--auto-split`이 자동 수행한다(ⓐ와 같은 취지). **초과 WARN은 그대로 남고 그것을 받는 것도 세션이다**(ⓓ).
- 근접(80%)은 **임박의 선행 게이트**이며, 그 게이트가 참인 파일 중 **비율 조건 *또는* 잔여 조건**(임계는 위 표) 하나라도 만족하면 임박이다. **선행 게이트를 지우지 않는다** — 잔여 조건만으로 72%짜리가 걸린다.
- **소비 주체**: **ⓑ′·ⓒ·ⓓ 전부**가 **절차 F(F-2)와 절차 B(A-4·B-3)가 처방을 수행할 대상**이며(표의 「소비 주체」 열), 그 세 지점은 **승인 없이 자동 수행**한다(안전장치는 wiki-schema §4 「분할 수행 절차」). **자동 수행하는 것은 이 세 지점뿐이다.**
- **「분리 불가 판정」(`budget_split`)**: 나눌 하위가 없는 페이지(단일 레시피·단일 개념)는 §4의 이동·분리 처방이 성립하지 않는다. frontmatter에 `budget_split: none` + `budget_split_chars`(**lint 예산 판정과 같은 기준으로 잰 문자 수** — 펜스 제외 guide는 유효 문자 수) + `budget_split_reason`을 적으면 임박이 **INFO로 강등**된다(표 ⓒ). **재판정 마진**을 넘게 자라면 억제가 풀린다. 필드 정의는 wiki-schema §3.

### 세션 처방

> 이 절을 **고치기 전에** `references/wiki-ops-rationale.md` 「세션 처방」 를 읽는다.

`--auto-split`이 못 하고 **세션이 직접 수행**하는 처방이다(위 표 ⓑ′의 소비 주체). 소비 지점(F-2·A-4·B-3)이 **승인 없이 수행하고 성공은 보고하지 않는다** — 안전장치·보고 억제는 `wiki-schema.md` §4 「분할 수행 절차」를 그대로 쓴다.

- **ⓕ 처방 없는 타입의 상세 이관**: `source-stub`은 상세를 feature/entity로 옮기고 포인터만 남긴다(§2.1) · `question`은 관련 페이지에 흡수하고 `status: resolved`로 보존한다(§2.7). **둘 다 이동이라 원문 손실이 없다.**

### J. 빈 위키 부트스트랩

`<vault>`가 비었거나 골격이 없으면 생성한다(이미 있으면 건너뜀). §0-2에서 트리거.

1. **디렉터리**: `10_sources/{personal,work}`, `20_projects/{personal,work}`, `30_knowledge/{tech,patterns,questions}`, `40_guides/{platforms,ui-ux,recipes}`, `90_archive`
2. **`index.md`**: 빈 카탈로그 골격 — **frontmatter 포함**: `type: index` · `okf_version: "0.2"` · `updated: YYYY-MM-DD` (OKF 버전 선언 위치는 루트 index.md 뿐 — wiki-schema §12). 섹션: `## 개인 프로젝트` / `## 업무 프로젝트` / `## 기능별 인덱스` / `## 증상별 인덱스`(증상→검증된 원인→해법 역인덱스, wiki-schema §6) / `## 기술 스택 지식 (tech/)` / `## 범용 패턴 (patterns/)` / `## 미해결 질문` / `## 참조`. **`## 가이드 / 레시피`는 두지 않는다** — 가이드·레시피는 `--build-index`가 `index-guides.md` 통합 표로 파생한다(wiki-schema §5). 표는 헤더만, 내용은 "아직 없음" 주석. 참조 섹션은 **실제 존재하는 파일만** 링크(`log.md` 등). **생성 대상 6섹션(개인 프로젝트~미해결 질문)을 `<!-- AUTO-INDEX:BEGIN -->`~`<!-- AUTO-INDEX:END -->`로 감싼다** — 새 vault는 처음부터 생성 체계로 출발하는 것이 옳다(wiki-schema §6). **증상별 인덱스·참조는 마커 밖에 둔다**(수기 판단 영역). 마커를 넣어 두면 이후 `--build-index`가 바로 동작하고, 넣지 않으면 그 명령이 "마커 없음"으로 거부한다.
3. **`log.md`**: `## 최근 변경` + `- [YYYY-MM-DD] [INIT] 위키 초기 골격 생성 (llm-wiki 스킬).` + `## 아카이브 인덱스`(빈 목록 — **§7-2 발동 시** 월별 롤오버 항목을 `- {YYYY-MM}.md: {키워드}`로 등록, wiki-schema §8). `90_archive/log/`는 첫 롤오버 시 생성(미리 만들지 않음).
4. **규칙은 vault에 복사하지 않는다** — 진실원천은 스킬 번들 `references/wiki-schema.md` 뿐. index `## 참조`에는 번들 경로를 텍스트로 안내한다(vault에 SCHEMA.md를 만들지 말 것).
5. 부트스트랩 완료 후 본래 요청(A~I)을 이어서 진행한다.
