# 저빈도 상세 규칙 — implement-task

## 빌드/테스트 fallback 표 (V-1·V-2 — AGENTS.md에 명령이 없을 때만)

**V-1 빌드** — AGENTS.md 없거나 build 명령 미정의 시 표식 파일로 자동 추론:
  - `*.csproj`/`*.sln` → `dotnet build`
  - `build.gradle*` → `./gradlew assembleDebug`
  - `package.json` → `npm run build` (script 있을 때) 또는 skip
  - `pyproject.toml` → `python -m build`
  - `go.mod` → `go build ./...`
  - `Cargo.toml` → `cargo build`
  - 위 어느 것도 아님 → AGENTS.md에 build 명령이 있으면 그것 사용. 없으면 Halt → 사용자에게 build 명령 요청 (또는 `pjc:bootstrap-agents-md`로 AGENTS.md 생성 제안)

**V-2 테스트** — AGENTS.md 없거나 test 명령 미정의 시 표식 파일 fallback:
  - `*.csproj` → `dotnet test`
  - `build.gradle*` → `./gradlew test`
  - `package.json` (test script 있음) → `npm test`; **test script 없음 → skip** (V-1 빌드 fallback과 동일 — 테스트 없는 패키지는 Halt가 아니라 skip)
  - `pyproject.toml` → `pytest`
  - `go.mod` → `go test ./...`
  - `Cargo.toml` → `cargo test`
  - 위 어느 것도 아님 → Halt

hot-path(SKILL 본문)에서 참조로 뺀 상황별 상세. **해당 상황에서만 읽는다** — 트리거·요지는 SKILL 본문에 남아 있다.

## UI 문구 사용자 친화 (규칙 7-2 상세)

화면 표시 문구(레이블·버튼·메시지·오류·툴팁·플레이스홀더)는 개발 용어가 아니라 **일반 사용자가 이해하는 일상 언어**로 쓴다. 최종 사용자는 개발자가 아니다.

- **개발/기술 용어 노출 금지**: `null`, `exception`, `validation failed`, `timeout`, `400 Bad Request`, `parse error`, `commit`, `query`, `token`, 변수명·클래스명·열거형 값(`Status.PENDING`)을 그대로 화면에 쓰지 않는다.
- **오류 메시지는 원인+다음 행동 중심**: 무엇이 잘못됐는지보다 사용자가 **무엇을 하면 되는지**를 알려준다. 예: `Error: connection refused` → "서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요." / `ValidationError: email invalid` → "이메일 주소 형식을 확인해 주세요."
- **일상 표현 사용**: "삭제(delete)" 대신 "지우기", "동기화 실패" 대신 "최신 정보를 가져오지 못했습니다" 등 맥락에 맞는 자연스러운 표현. 단, 해당 도메인에서 사용자에게 익숙한 전문 용어(예: 회계 앱의 "분개")는 그대로 둔다.
- **비난조·기술 추궁 금지**: "잘못된 입력", "유효하지 않음" 같은 딱딱한 표현 대신 부드럽게 안내한다.
- 판단이 애매한 문구(전문 용어를 일상어로 바꿔도 되는지 등)는 plan에 ⏳ HUMAN-VERIFY로 표시해 사용자 확인을 받는다. 문구는 리소스로 분리하되(다국어 규칙), **분리한 문구의 내용 자체가 사용자 친화적**이어야 한다.

## 검증 스크립트 Windows 보안 (PowerShell)

빌드·테스트·런타임 실증용 임시 스크립트를 작성할 때, 아래 패턴이 한 스크립트에 모이면 Windows Defender·백신이 **credential stealer / 공격 도구로 오인**해 스크립트나 산출물을 격리(삭제)할 수 있다:

- **자격증명을 하드코딩하지 않는다.** 로그인 테스트의 비밀번호·토큰·API 키는 환경변수(`$env:TEST_PW` 등)에서 읽는다(절대 규칙 6-1 — 보안 + 백신 회피 양쪽). 평문 `Password='...'`은 금지.
- **`-WindowStyle Hidden`을 쓰지 않는다.** 검증/테스트는 숨길 이유가 없다 — "숨김 실행"은 멀웨어 핵심 신호다.
- **`-ExecutionPolicy Bypass`는 최소화.** 꼭 필요할 때만, 그리고 위 다른 위험 신호와 겹치지 않게 한다.
- **위험 신호를 한 스크립트에 모으지 않는다.** "정책 우회 + 숨김 실행 + 자격증명 + 토큰 스크래핑 + 프로세스 강제 종료"가 동시에 있으면 휴리스틱에 걸린다. 빌드 검증과 로그인/런타임 테스트는 가능하면 분리한다.
- 그래도 격리되면 사용자에게 "개발 작업 폴더를 Windows Defender 예외(`Add-MpPreference -ExclusionPath`)에 추가"를 **안내만** 한다 — 보안 설정 변경은 사용자가 직접 한다(자동 실행 금지, block-destructive·승인 게이트 대상).

## 코드에 흔적이 남지 않는 결정의 주석 (규칙 7-3 상세)

규칙 7-3의 네 경우는 모두 **"코드를 읽어도 알 수 없음"**이 공통 조건이다. 코드로 읽히는 것에 주석을 다는 것은 이 규칙이 아니라 규칙 6 위반이다.

| 경우 | WRONG (주석 없음 → 다음 세션이 오판) | RIGHT |
|---|---|---|
| ① 의도적 배제 | 화질 목록에 `2160`이 그냥 없음 → "빠뜨렸다"로 오판, 다음 세션이 추가 | `// 2160 제외 — 렌더 스케일 특성상 4K에선 "원본"과 결과가 동일 (D3)` |
| ② 의도적 잔존 | 미사용 enum 값이 진입점 없이 남음 → "미완성"인지 "하위호환"인지 불명 | `// 저장 JSON 하위호환용 잔존 — UI 진입점 없음 (제거 시 기존 설정 파일 로드 실패)` |
| ③ 튜닝 상수 | `Delay(1500)` → 바꿔도 되는 값인지 몰라 아무도 손대지 못함 | `// 1500ms — 완료 신호가 없어 실측 최댓값 약 1.2초에 여유를 둔 값` |
| ④ 기본값 적용 범위 | 기본값만 보고 "모든 사용자가 이렇게 동작"으로 오해 | `// 신규 사용자만 적용 — 직렬화가 기본값도 기록하므로 기존 설정 파일은 저장된 값을 유지` |

**쓰지 않는 경우 (장식 주석 — 규칙 6 위반)**:

```
WRONG: // 사용자 이름을 저장한다       → 코드가 말한다
WRONG: // 재시도 횟수 (튜닝 상수)      → "왜 이 값인가"에 답하지 않음. 라벨은 근거가 아니다
WRONG: // 성능을 위해 3으로 설정       → 근거처럼 보이지만 검증 불가한 사후 서술
RIGHT: (근거가 없으면 아무것도 쓰지 않는다)
```

**근거의 출처는 plan이다.** `## Decisions`의 Rationale·`## Out of Scope`·Design ④ 비추상화 선언에 이미 적힌 근거를 **1줄로 압축해 옮기는 것**이지, 구현 중에 새로 발명하는 것이 아니다. plan에 근거가 없고 구현 중 스스로 정한 값이면(주로 ③) 그 판단 근거를 그대로 적는다("실측 최댓값 기준", "라이브러리 기본값 따름"). 판단 근거조차 없이 고른 값이면 그것은 주석 문제가 아니라 **근거 없는 결정**이다 — 규칙 11(중대하면 Halt) 또는 plan follow-up 등록으로 처리한다.

## 질문 도구 제거의 실동작 — 왜 보조 장치인가

이 스킬의 frontmatter는 `disallowed-tools`로 질문 도구를 내려놓는다(공식 문서가 "자율 배경
루프의 `AskUserQuestion`"을 이 필드의 용례로 든다). **실동작은 확인됐다** — 설치본에서 스킬을
로드한 뒤 `AskUserQuestion`을 호출하면 거부된다(2026-07-30 실측).

다만 **그 제거는 사용자가 다음 메시지를 보내면 풀린다** — 한 turn 안에서만 유효하다. 그러니
"도구가 막혀 있으니 안전하다"고 가정하면 안 된다: *"task 사이에 묻지 않는다"* 와 금지 표현
목록이 실제로 지키는 규칙이고, 필드는 실수를 한 겹 더 막아 줄 뿐이다.

**이 제거는 Halt 보고·리뷰어 과부하 시 선택 요청·최종 보고에 영향이 없다** — 그 셋은 모두
텍스트로 출력하고 사용자의 다음 입력을 기다리는 경로이지 질문 도구를 쓰는 경로가 아니다.
