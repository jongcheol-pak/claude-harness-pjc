# Phase V-9 상세 — 시각 충실도 검증 (implement-task)

> 트리거 판정(plan `## 시각 요소 분해` 섹션 유무)과 수행 시점(V-7 이후·V-8 이전)은 SKILL.md V-9가 정본이다 — 이 파일은 수행 절차 상세만 담는다(SKILL.md 이관, v1.109.0).

1. **요소 전수 대조**: 분해 표의 각 요소·속성(**디자인 값** 기준)을 구현 결과와 하나씩 대조한다. 공유·재사용 컴포넌트도 빠짐없이 — "행만 맞추고 헤더·검색·칩은 맞겠지" 금지. **대조 결과(현재 구현 값·판정)는 이 V-9 단계에서 산출한다** — plan의 분해 표는 "디자인 값 + 확인 방법"까지만 담으므로(현재 값·일치 열은 계획 단계에 두지 않음, plan-feature Step 2.5), 여기서 각 요소의 실제 구현 값을 확인해 판정한다. (구버전 plan이 "현재 값"·"일치" 열을 이미 가진 경우엔 그 열을 갱신하며 사용해도 된다 — **열 유무와 무관하게 디자인 값 기준으로 대조**하는 것이 핵심.)

2. **각 행에 diff 위치를 지목한다 (근거 의무).** 표의 모든 행에 대해 그 디자인 값이 **어느 파일:라인에서 충족되는지** 적는다(예: `MainPage.xaml:42 CornerRadius="8"`). **지목하지 못한 행은 충족으로 보지 않는다** — "구현했다고 생각한다"는 근거가 아니다. 이 지목은 V-8 자기점검과 `spec-compliance-reviewer` 항목 I(귀속 행 대조)의 입력이 된다.

3. **빌드 ≠ 시각 일치를 명시**: 빌드 통과·테스트·코드리뷰는 **시각 충실도를 검증하지 못한다**. CSS든 XAML이든 마찬가지다 — 폰트 크기·간격·정렬·아이콘 유무·레이아웃 어긋남은 컴파일·바인딩 검사가 잡지 않는다(WinUI 3/WPF/MAUI는 XAML이 컴파일되지만 그것은 문법·바인딩 경로 검증일 뿐 화면 결과의 검증이 아니다). 따라서 빌드만으로 "디자인과 동일"을 선언하지 않는다.

4. **정적 판정 축 게이트 — 렌더 가용성과 무관하게 판정한다 (인벤토리 표가 있을 때).**

   plan에 `### 참조 정합 인벤토리` 하위 표가 있으면, 그 표의 축은 **원본 소스가 기준**이라 화면을 보지 않고 **소스 대 소스로 결정된다.** 아래 축에는 **`⏳ 미확인` 표기를 금지**한다 — 아래 5의 렌더 3분기는 이 축에 적용하지 않는다.

   | 축 | 판정 방법 | `⏳` |
   |---|---|---|
   | 항목 존재·개수·순서 | 원본 ↔ 구현 소스 대조 | **금지** |
   | 라벨·설명 문구 문자열 | 문자 단위 일치 | **금지** |
   | 컨트롤 타입 | 원본 타입 ↔ 구현 타입 | **금지** |
   | 선택지 목록·값·순서 | 원본 ↔ 구현 | **금지** |
   | 기본값·초기 선택 | 원본 ↔ 구현 | **금지** |
   | 활성·비활성 조건 | 원본 ↔ 구현 | **금지** |
   | 간격·정렬·폰트·색·최종 레이아웃 | 아래 5의 렌더 3분기 | 허용 |

   > **이 게이트가 없으면 "화면을 볼 수 없다"가 면죄부가 된다.** 데스크톱 UI는 5의 3분기에서 무조건 `⏳`로 떨어지는데, 축을 나누지 않으면 **소스만 보면 100% 판정되는 것**(문구가 다른가, ComboBox를 TextBox로 바꿨는가)까지 미검증으로 쓸려 들어간다. 그 상태의 완료 보고는 "UI는 확인 못 했지만 구현은 완료"로 뭉뚱그려져, 사용자가 화면을 열어보기 전까지 어긋남이 드러나지 않는다.

   **양쪽 지목 의무 — V-9가 표에 두 열을 추가해 채운다.** 인벤토리 각 행은 **`원본 파일:라인`과 `구현 파일:라인`을 둘 다** 지목해야 ✅다(원본 경로의 기준은 plan `## 시각 요소 분해` 서두의 `**원본**:` 줄). **한쪽만 적힌 행은 미충족(❌)** 이다 — 원본을 지목하지 못했다는 것은 원본을 읽지 않았다는 뜻이고, 그 상태의 "동일"은 추측이다. (위 2의 "지목하지 못한 행은 충족으로 보지 않는다"를 원본 쪽으로 확장한 것.)

   계획 단계의 인벤토리 표에는 `원본 근거` 열까지만 있다(구현 위치는 구현 후에야 정해지므로 계획 시점에 적으면 stale해진다 — plan-feature Step 2.5가 시각 속성 표에 "현재 값" 열을 두지 않는 것과 같은 이유). 따라서 **V-9가 그 표에 `구현 근거`·`판정` 두 열을 덧붙여 채운다**:

   ```markdown
   | # | 항목 | 라벨 문구(원문) | 컨트롤 타입 | … | 원본 근거 | 구현 근거 | 판정 |
   |---|------|----------------|------------|---|----------|----------|------|
   | 1 | 테마 | 앱 테마 | ComboBox | … | SettingsPage.xaml:42 | Views/SettingsPage.xaml:31 | ✅ |
   | 2 | 시작 시 실행 | Windows 시작 시 자동 실행 | ToggleSwitch | … | SettingsPage.xaml:58 | Views/SettingsPage.xaml:47 | ❌ CheckBox로 구현됨 |
   ```

   두 열이 실제로 채워져야 V-8 자기점검("각 행에 둘 다 지목했는가")이 **기계적으로 확인 가능**해진다 — 표 밖 산문으로 흩어 적으면 지목 의무가 형식적으로만 충족된다.

   **컨트롤 타입 대체는 불일치(❌)다.** 원본이 `ComboBox`·`ToggleSwitch`·`Slider`·`NumberBox` 등인데 구현이 `TextBox`·`CheckBox` 등 다른 타입이면 ❌로 확정한다. **"기능적으로 동등하다"·"값을 입력할 수 있으니 같다"는 판정 근거가 되지 못한다** — 선택지 제약·입력 검증·조작 방식이 달라 사용자가 보는 것과 할 수 있는 것이 달라진다. 대상 플랫폼에 대응 컨트롤이 없어 대체가 불가피하면 **임의 판단하지 말고 Halt**해 사용자에게 대체안을 확인받는다(`halt-conditions.md`의 「컨트롤 타입 대체 불가피」 행).

   **문구 불일치도 ❌다.** 라벨·설명 문구가 원문과 다르면(의역·축약·재작성) 불일치다. 원본 문구가 그 플랫폼에서 표현 불가한 경우가 아니면 그대로 쓴다.

   **원본에 접근할 수 없으면 새 표기를 만들지 말고 Halt한다.** 구현 시점에 `**원본**:` 경로가 사라졌거나 접근 권한이 없어 대조 자체가 불가능하면, `⏳ 원본 미접근` 같은 표기를 신설하지 않는다 — F-8 발동과 완료 선언 보류의 조건이 전부 리터럴 **`⏳ 미확인`**에 걸려 있어, 별도 문자열은 어느 게이트에도 안 걸린 채 `🎉 완료`로 종결되기 때문이다(면죄부를 막으려는 표기가 정확히 면죄부가 된다). 이 상황은 **plan이 의무 기재한 경로가 실측과 다른 것**이므로 `halt-conditions.md`의 「중단 조건 표」 중 *계획 결함 — plan.md의 가정이 실측과 불일치* 행에 그대로 해당한다. Halt해 경로 재확인을 요청한다.

5. **렌더 확인 — 3분기.** 대상과 도구 가용성으로 갈린다. **인벤토리 표가 있으면 위 4에서 정적 축이 이미 판정됐으므로, 아래는 시각 축(간격·정렬·폰트·색·레이아웃)에만 적용한다**:

   | 상황 | 처리 |
   |---|---|
   | **웹 대상 + 렌더 캡처 도구 가용**(브라우저 자동화 MCP 등) · 로그인 불필요 | 캡처해 디자인과 **요소별로 대조**하고 결과를 표에 기록. **이 경로만 "확인됨"으로 판정할 수 있다** |
   | **데스크톱 UI 대상**(WinUI 3·WPF·MAUI 등) | 자율 루프에서 앱 기동·상태 준비·창 캡처를 신뢰성 있게 수행할 수단이 없다 → 해당 행을 **`⏳ 미확인`**으로 표기 |
   | **도구 부재 · 로그인 필요 · 캡처 환경 없음** | 위와 동일하게 **`⏳ 미확인`** 표기 |

   > 렌더 캡처 도구는 세션·설치에 따라 있을 수도 없을 수도 있다. **특정 도구의 존재를 전제하지 않는다** — 있으면 쓰고, 없으면 `⏳ 미확인` 경로로 간다.

6. **`⏳ 미확인` 행의 처리 — Phase F-8로 인계한다.** task 루프는 여기서 멈추지 않고 계속하되, **미확인 행 목록을 plan의 분해 표에 남겨 Phase F-8(시각 충실도 최종 관문)이 받도록 한다.** F-8이 완료 선언 직전에 이 목록을 확인하고, 하나라도 남아 있으면 **완료 선언을 보류하고 사용자에게 화면 확인을 요청**한다.
   - **"루프를 멈추지 않는다"가 "검증 없이 완료한다"를 뜻하지 않는다** — 인계는 검증의 이연이지 면제가 아니다. task 단계에서 세우지 않는 이유는 미확인이 task마다 반복 발생하기 때문이며, 선언 게이트는 F-8 한 곳으로 모은다.
   - 미확인 행을 완료 보고에 적는 것만으로 끝내지 않는다 — 보고에 적고 "완료"를 선언하면 사용자가 그 줄을 읽지 않는 한 그대로 묻힌다.
   - "동일하게 맞췄다"고 단정하지 않는다.

7. 분해 표에서 **❌(불일치)**가 남아 있으면 Phase I로 복귀해 수정 후 재대조한다. **`⏳ 미확인`은 ❌가 아니다**(불일치가 아니라 미검증) — Phase I 복귀 대상이 아니라 F-8 인계 대상이다. **인벤토리 표의 ❌**(문구 불일치·컨트롤 대체·항목 누락 등)는 정적 축이라 `⏳`로 도피할 수 없고 **반드시 Phase I 복귀로 해소**한다(해소 불가한 대체는 위 4의 Halt 경로).

> 핵심: "동일하게"는 화면 전체를 요소 단위로 대조해야 하는 작업이다. 일부만 보고 "맞겠지"로 끝내면 사용자가 볼 때만 어긋남이 드러난다. 자동 확인이 불가능한 환경에서는 **확인을 생략하는 대신 완료 선언을 미룬다**(F-8). 다만 **"확인 불가"의 범위를 넓게 잡지 않는다** — 렌더 없이 소스로 판정되는 것(항목·문구·컨트롤)은 위 4에서 반드시 판정한다.
