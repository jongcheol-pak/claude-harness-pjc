# Antipatterns — implement-task

자율 루프에서 절대 금지하는 패턴 목록.

## 검증·완료 관련

| 안티패턴 | 올바른 행동 |
|---|---|
| "구현이 맞아 보입니다"로 완료 선언 | V-1~V-8 모두 통과 후 증거 첨부 |
| Review subagent 생략 | 의무 — 절대 생략 금지. **단 "생략"은 호출할 수 있는데 안 하는 것**이며, 호출 자체가 불가한 환경의 **대체**(`recovery.md` "Reviewer 호출 실패 대응" B — 체크리스트 대조 + 의무 3종 공시)는 이 금지의 대상이 아니다 |
| Review 결과를 자체 판단으로 묵살 | 이슈 0까지 반복 또는 Halt (예외: 파일:라인 인용 반증은 SKILL "지적 이의 절차"로 재호출 — 재호출에도 같은 지적이면 수용, 상한은 수정 사이클 카운터. 근거 없는 무시는 여전히 금지) |
| 모든 변경에 전체 코드베이스 리뷰 | 해당 task diff로 범위 한정 |
| 동일 오류를 다른 방식으로 5회 시도 | Halt — 사용자 보고 |
| 사소한 빌드 오류로 사용자 호출 | 자체 수정 |
| **"잘 동작할 것이다"로 검증 생략** | **빌드 + 테스트 통과 + 2단계 리뷰 통과 후에만 완료** |

## 자율 루프 위반

| 안티패턴 | 올바른 행동 |
|---|---|
| "이건 사용자가 결정해야..." | plan.md 결함 — Halt → plan-feature 복귀 |
| **"T2 시작하면 될까요?" 같은 확인 요청** | **plan.md = 전체 위임장. 이미 승인받음. 그냥 진행** (위임에는 plan의 `## 사전 승인 항목`이 포함됨 — 단 파괴적·외부 작업은 제외, 그 지점에서 별도 승인) |
| **"이 부분 어떻게 처리할까요?" 사소한 결정에 사용자 호출** | **plan-feature Decision Points에서 결정되었어야 함. 결정 누락이면 Halt** |

> task 사이 "다음 진행할까요?"(SKILL "🚫 금지 표현") · MINOR follow-up 등록 시 묻기(SKILL "🚨 자율 루프의 절대 규칙") 등 자율 루프 금지의 정본은 SKILL.md다.

| 안티패턴 | 올바른 행동 |
|---|---|
| 무관한 리팩토링 끼워넣기 | plan.md에 새 task 등록 |

| 분할 판정을 줄 수로 대신하기(임계 미만이면 무조건 유지·초과면 무조건 분리) | 규칙 8의 네 질문으로 판정하고, 분리가 필요하면 plan에 등록 |
