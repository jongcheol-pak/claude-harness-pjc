# 사람이 읽는 글의 문체

> pjc 스킬이 사용자에게 내는 글의 문장 규칙이다. 각 스킬의 보고·커밋 절이 이 파일을 가리키고, 글을 쓰기 전에 한 번 읽는다.
> 출처는 Cursor pstack 의 unslop·technical-writing 이다 — 고정 위치 `https://github.com/cursor/plugins/blob/f713f14203cd6420cec13cd7c55c32d598dbab68/pstack/skills/unslop/SKILL.md` 와 같은 커밋의 `pstack/skills/technical-writing/SKILL.md`. 언어와 무관한 규칙만 한글로 옮겼고, 들이지 않은 것은 맨 끝 절에 이유와 함께 둔다.

## 적용 범위

- **거는 곳** — 완료 보고, 계획 승인 제시, 커밋 메시지, PR 본문, README, 디버깅 보고, 체인 보고, PR 운영 보고, 검증 스킬(생성·형식 검증·유지)의 보고 문장이다. 사용자가 이 글로 판단하므로 읽는 데 드는 수고가 곧 비용이다.
- **서식이 정한 구조는 대상이 아니다** — 보고 서식의 굵은 머리(`**수정 내용**:`), 줄 머리(`T1:`), 규칙 줄의 `—` 구분자, 서식이 쓰는 `→`·`·` 구분은 그대로 둔다. 구조는 각 서식 문서가 정한다.
- **검증 출력 원문과 코드는 고치지 않는다** — 명령 출력은 요약하지 않고 그대로 싣는 것이 규칙이고, 식별자는 원래 표기가 정확하다.
- **예시는 금지어 목록이 아니다** — 아래 `나쁜 예 → 고친 예` 는 규칙의 뜻을 보이는 한 쌍이다. 예시에 나온 단어를 기계적으로 피하면 정상 문장까지 어색해진다.

## 원칙

- **일하지 않는 말을 지운다** — 단어를 빼도 문장의 뜻이 그대로면 그 단어는 일을 하지 않는다.
- **짧고 흔한 말을 쓴다** — 「활용하다」보다 「쓰다」, 「진행하다」보다 그 동작의 동사다. 긴 말은 그만큼 정확할 때만 쓴다.
- **규칙이 문장을 망치면 다른 방법으로 고치거나 그대로 둔다** — 규칙을 다 지켰는데 기계가 쓴 것처럼 읽히면 그 문장은 실패다.

## 규칙

### 내용

- **출처 없는 인용을 쓰지 않는다** — 「일반적으로」「흔히」로 기댄 주장은 읽는 쪽이 확인할 수단이 없다. 출처를 대거나 뺀다.
  - 예: 일반적으로 이 방식이 권장됩니다 → Claude Code 문서 skills.md 가 이 방식을 권장합니다
- **일반론으로 맺지 않는다** — 어느 프로젝트에 붙여도 참인 문장은 이 작업에 대해 아무것도 말하지 않는다.
  - 예: 앞으로 더 안정적인 운영이 기대됩니다 → 다음 회차에서 골든 케이스 3건을 더합니다
- **느낌 대신 동작이나 수치를 쓴다** — 「가벼워졌다」는 무엇이 얼마나 바뀌었는지 알려 주지 않는다. 문장을 지시·사실·수치로 바꿀 수 없으면 지운다.
  - 예: 검사가 훨씬 가벼워졌습니다 → 검사 시간이 670초에서 410초로 줄었습니다
- **실제 이름을 쓴다** — 파일·명령·설정 키를 묘사하면 읽는 쪽이 그것이 무엇인지 다시 찾아야 한다.
  - 예: 설정 파일의 해당 항목을 수정했습니다 → plugin.json 의 version 을 1.380.0 으로 바꿨습니다
- **덧붙인 꾸밈 구를 빼거나 근거로 바꾼다** — 「~함으로써 …을 보여 준다」 같은 꼬리는 내용 없이 의미만 부풀린다.
  - 예: 검사를 추가함으로써 품질에 대한 의지를 보여 줍니다 → 검사를 추가했습니다. 빈 명령 칸을 커밋 전에 잡습니다

### 단어

- **추상 비유 명사 대신 구체어를 쓴다** — 「초석」「생태계」「지형」 같은 말은 기술 용어처럼 보이지만 가리키는 대상이 없다.
  - 예: 검증 생태계의 초석을 다졌습니다 → 검증 명령 세 개를 AGENTS.md 에 적었습니다
- **「이다」를 돌려 말하지 않는다** — 「~의 역할을 한다」「~로 자리한다」는 「이다」「있다」보다 길기만 하다.
  - 예: 이 파일은 설정의 진입점 역할을 합니다 → 이 파일이 설정의 진입점입니다
- **부사 대신 수치나 맞는 동사를 쓴다** — 부사가 약한 동사를 받치고 있으면 동사가 틀린 것이다.
  - 예: 응답이 크게 빨라졌습니다 → 응답 시간이 1.2초에서 0.3초가 됐습니다
- **한 대상은 한 이름으로 부른다** — 같은 것을 세 이름으로 부르면 읽는 쪽은 세 가지가 있다고 배운다. 계획 인터뷰의 「GUESS 와 선택지를 같은 이름으로」는 이 규칙의 한 사례다.
  - 예: 리뷰어가 지적했고, 검토자가 다시 봤고, 심사 에이전트가 통과시켰습니다 → 리뷰어가 지적했고, 고친 뒤 리뷰어가 통과시켰습니다
- **절차에 「간단히」「쉽게」를 쓰지 않는다** — 쉬웠다면 읽는 쪽이 이 글을 보고 있지 않다.
  - 예: 간단히 아래 명령을 실행하면 됩니다 → 아래 명령을 실행합니다
- **긴 명사 줄을 풀어 쓴다** — 명사를 「의」나 띄어쓰기로 셋 넘게 이으면 무엇이 무엇을 꾸미는지 읽는 쪽이 다시 묶어야 한다. 동사를 넣어 관계를 드러낸다.
  - 예: 골든 부분 실행 판정 자격 확인 → 골든을 일부만 돌렸을 때 그 결과로 판정해도 되는지 확인
- **레포 안에서만 통하는 이름과 줄임말은 처음 쓸 때 뜻이나 실제 이름을 붙인다** — 축 번호·면제 번호·약칭은 만든 사람에게만 뜻이 있다.
  - 예: 축 ⑲가 red 입니다 → 정합 검사기의 영향 검토 3축 검사(축 ⑲)가 red 입니다

### 문장

- **한 문장에 한 생각을 담는다** — 다시 읽어야 뜻이 잡히는 문장은 둘로 나누거나 절을 덜어 낸다.
  - 예: 빌드가 통과했고 골든은 1128건이 통과했으며 문서도 고쳤지만 README 는 남았습니다 → 빌드와 골든 1128건이 통과했습니다. 문서는 고쳤고 README 는 남았습니다
- **문장 길이를 섞는다** — 모든 문장을 짧게 끊으면 그것도 기계가 쓴 글로 읽힌다. 조건이나 결과를 함께 나르는 문장은 길어도 된다.
  - 예: 고쳤다. 확인했다. 통과했다. 커밋했다 → 두 파일을 고치고 검사 넷을 돌려 모두 통과한 뒤 커밋했다
- **행위자를 밝힌다** — 피동은 누가 했는지를 지운다. 행위자를 모르거나 정말 상관없을 때만 피동을 쓴다.
  - 예: 설정이 변경되었습니다 → 설치 스크립트가 설정을 바꿨습니다
- **조건은 지시 앞에, 흔한 경우는 예외 앞에 둔다** — 읽는 쪽은 지시를 읽는 순간 실행하므로 조건이 뒤에 오면 늦다.
  - 예: 아래 명령을 돌리세요, 설치본을 갱신하려는 경우에 → 설치본을 갱신하려면 아래 명령을 돌리세요
- **서술 문장을 과압축하지 않는다** — 화살표·동사 없는 조각·줄임말은 읽는 쪽에게 해독을 시킨다. 서식이 정한 `→`·`·` 구분은 대상이 아니다.
  - 예: 날짜 오류 시 exit 2, 쓰기 없음 → 파서는 잘못된 날짜를 거부하고 종료 코드 2 로 끝나며 아무것도 쓰지 않습니다
- **「이것」「그것」은 하나만 가리키게 한다** — 앞 절 전체를 받는 지시어는 무엇을 가리키는지 읽는 쪽이 고르게 만든다. 헷갈리면 명사를 다시 쓴다.
  - 예: 검사기와 골든을 고쳤는데 이것이 실패했습니다 → 검사기와 골든을 고쳤는데 골든이 실패했습니다
- **「만」「안」은 꾸미는 말 옆에 둔다** — 자리가 바뀌면 뜻이 바뀌거나 두 가지로 읽힌다.
  - 예: 모든 케이스가 통과하지 않았습니다 → 케이스 12건 중 3건이 실패했습니다
- **번역투를 쓰지 않는다** — 「~되어지다」「~에 있어서」「~을 가지다」「~에 대해」는 영어 구조를 옮긴 꼴이라 같은 뜻의 한국어 문장보다 길고 흐리다.
  - 예: 이 값은 설정에 있어서 중요한 의미를 가지며 변경되어져야 합니다 → 이 값은 설정에서 중요하므로 바꿔야 합니다

### 목록

- **목록을 「등」으로 끝맺지 않는다** — 「등」은 나머지가 무엇인지 확인할 수단을 지운다. 전부 적거나, 일부만 적으면 앞에서 일부라고 밝힌다.
  - 예: 검사기·골든 등을 고쳤습니다 → 검사기 둘과 골든 케이스 셋을 고쳤습니다 / 고친 것 중 일부는 이렇습니다: 검사기, 골든
- **한 목록의 항목은 같은 꼴로 끝맺는다** — 명사형·「~한다」·「~함」이 섞이면 항목이 같은 종류인지 읽는 쪽이 다시 가른다.
  - 예: 검사기 수정 / 골든을 더했다 / README 갱신함 → 검사기를 고쳤다 / 골든을 더했다 / README 를 고쳤다

### 커밋 본문

- **검증 결과는 판정에 쓴 줄만 원문으로 싣는다 — 전량 로그·SHA 목록·지표 표는 싣지 않고 필요하면 위치를 적는다** — 커밋 본문은 이력에서 다시 읽히는 자리라, 판정과 무관한 출력이 섞이면 판정 근거를 그 속에서 다시 찾아야 한다. RED·GREEN 출력처럼 판정에 쓴 줄은 그대로 싣는다. PR 본문의 같은 규칙은 `implement/references/pr-flow.md` 「PR 열기」가 정본이다.

### 말투

- **챗봇 인사·맺음 문구를 쓰지 않는다** — 「도움이 되셨길 바랍니다」「궁금한 점 있으면 말씀해 주세요」는 판단에 쓰이지 않는다.
  - 예: 완료했습니다! 도움이 되셨길 바랍니다 → 완료했습니다
- **근거 없는 칭찬·동조를 하지 않는다** — 「좋은 질문입니다」「말씀하신 대로입니다」는 동의의 근거를 지운다. 맞으면 근거와 함께 맞다고 쓴다.
  - 예: 좋은 질문입니다! 말씀하신 대로입니다 → 맞습니다 — 버전 정본은 plugin.json 하나입니다
- **군더더기를 지운다** — 「참고로 말씀드리자면」「~하는 작업을 진행했습니다」는 동사 하나로 줄어든다.
  - 예: 참고로 말씀드리자면 해당 파일을 수정하는 작업을 진행했습니다 → 그 파일을 고쳤습니다
- **잴 수 있는 주장을 얼버무리지 않는다** — 「아마」「~로 보인다」는 재지 않았다는 고백이다. 재서 쓰거나 재지 않았다고 쓴다. 완료 보고에서는 `implement/references/report-format.md` 의 사실 주장 실측 규칙이 같은 자리를 맡는다.
  - 예: 아마 통과할 것으로 보입니다 → check-harness-consistency.py 를 돌려 exit 0 을 확인했습니다
- **앞에서 한 말을 다시 요약하지 않는다** — 재요약과 맺음 문단은 읽을 양만 늘린다. 완료 보고에서는 `implement/references/report-format.md` 의 보고 길이 규칙이 같은 자리를 맡는다.
  - 예: 정리하자면, 앞서 말씀드린 것처럼 세 파일을 고쳤습니다 → 앞에서 말했으면 이 문장을 지웁니다
- **「X뿐 아니라 Y」로 돌리지 않는다** — 대비 구조는 요점을 한 번 미룬다. 요점을 바로 쓴다.
  - 예: 이 변경은 속도뿐 아니라 안정성까지 높입니다 → 이 변경으로 실패가 주 3건에서 0건이 됐습니다
- **억지로 셋씩 묶지 않는다** — 셋을 채우려고 넣은 항목은 근거가 없다. 실제 개수대로 쓴다.
  - 예: 빠르고, 안전하고, 확장 가능한 구조입니다 → 실행이 2초 안에 끝납니다
- **같은 척도에 없는 「A부터 B까지」를 쓰지 않는다** — 범위처럼 보이지만 사이에 아무것도 없다. 항목을 그대로 나열한다.
  - 예: 설치부터 보안까지 모든 것을 다룹니다 → 설치, 위험 명령 차단, 위키 연동을 다룹니다
- **비유·수사 대신 글자 그대로 쓴다** — 비유는 읽는 쪽이 한 번 더 번역해야 하고, 번역이 어긋나면 뜻이 갈린다.
  - 예: 이 hook 이 마지막 문지기 역할을 합니다 → 이 hook 이 위험 명령을 exit 2 로 막습니다
- **장식 이모지를 쓰지 않는다** — 머리와 불릿의 이모지는 정보를 더하지 않는다.
  - 예: ✅ 완료 🚀 → 완료

## 들이지 않은 것

출처의 규칙 중 아래는 옮기지 않았다.

- em dash 금지(unslop 13번) — pjc 규칙 줄 형식·커밋 제목·보고 서식이 `—` 를 구분자로 쓴다.
- 콜론 남용 · 굵게 남용 · 굵은 라벨 목록(unslop 14~16번) — 원문이 막는 것은 문장 중간의 연결 콜론, 고유명사마다 거는 굵게, 줄을 되풀이하는 라벨이고, 목록 앞 콜론·서식의 굵은 머리·새 내용을 여는 라벨은 허용한다. 한글 서술문에서 연결 콜론은 드물고 나머지 둘은 서식이 정하므로 따로 두지 않는다.
- 제목 대소문자 · 굽은 따옴표(unslop 17·19번) — 한글에 대응이 없고, 낫표 인용은 이 레포의 관례다.
- 영어 AI 어휘 목록(unslop 7번) — 영어 단어 목록이다. 한글 금지어 목록도 두지 않는다 — 정상 단어까지 피하게 만들어 문장이 오히려 어색해진다.
- 영어 문법 항목 — 2인칭·현재 시제, -ing, 세미콜론, 20·25단어 상한, 복수 괄호, 직렬 쉼표, 관사, 괄호 문법. 한글에 대응이 없다.
- 슬래시 금지 — 원문의 취지(「무엇을 묶는지 말한다」)를 옮길 자리인 `·` 가 서식 구분자라 같은 규칙을 걸 수 없다.
- 문서 모드 구분(Diátaxis) · 링크 문구 · 제목 형식 — 이 규칙이 거는 글은 문서 사이트가 아니라 보고와 커밋이다.
- 미리 알리기 금지 — README 는 `docs/harness-conventions.md` 「README.md 갱신 규약」의 「현재 존재하는 기능만」이 같은 자리를 맡는다.
