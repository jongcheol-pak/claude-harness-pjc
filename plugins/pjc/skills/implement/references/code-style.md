# 코드 작성 규약

> `pjc:implement`의 자율 루프 2번이 **첫 코드 task 전 1회** 읽는다. 디버깅 스킬의 4-B(최소 수정)는 이 파일의 주석 절을 읽는다.
> **이 파일은 글로벌 `~/.claude/CLAUDE.md`「수정」 절이 있으면 그것을 대체하지 않고 보완한다** — 그 절을 여기 복창하지 않으며, 그 절이 없는 배포 환경에서도 여기 담은 것은 그대로 적용된다. 여기 담는 것은 **그 절이 다루지 않는, 이 하니스가 겪어서 아는 것과 다른 하니스가 겪은 것을 `[면제 ⑤ · 외부 선례]` 로 들인 것**뿐이다. **단 주석 절만은 그 절의 「딸린 주석을 갱신하거나 삭제」를 「예외면 갱신, 아니면 삭제」로 좁힌다** — 갱신과 삭제 사이를 고를 기준이 없으면 갱신으로 흘러 코드를 되풀이하는 주석이 남는다. **삭제 먼저 · 옛 API 정리 · codemod 줄바꿈 세 불릿은 글로벌 「수정」에 한 줄 원칙이 있어도 여기를 배포 환경의 정본으로 둔다** — 글로벌이 없는 배포 환경에서는 이 파일만 남는다(`../../DESIGN.md`「2. 자기참조 금지」의 의도적 이중화).
> **계획 시점의 구조 결정(파일 분할·모듈 배치·스타일 공통화·기각한 대안)은 여기가 아니다** — 그것은 `plan.md`의 각 task 에 붙는 **구조** 줄이 담고, 서식은 `../../plan/references/plan-template.md`가 정본이다.

## 확인할 수 있게 만든다

- **저장소·네트워크·파일 시스템에 닿는 코드를 판단 로직과 갈라 둔다** — 둘이 한 함수에 있으면 그 로직을 확인하는 데 그 인프라를 세워야 하고, 그러면 아무도 확인하지 않게 된다.
- **상태는 만들 때 정하고 이후 바꾸지 않는 쪽을 기본으로 한다** — 여러 곳이 같은 값을 고치면 결함이 재현되지 않는 형태로 나타나 원인을 좁히지 못한다. **다만 프레임·틱 단위로 도는 성능 경로는 예외다** — 그 자리에서는 값을 새로 만드는 비용이 문제를 옮길 뿐이다.
- **다른 값에서 계산되는 값은 저장해 동기화하지 않고 쓸 때 계산하며, 상태는 가장 좁은 범위(지역 < 필드 < 모듈 < 전역)에 둔다(파생 상태)** — 저장한 사본은 원본을 고치는 경로 하나만 동기화를 빠뜨려도 둘이 갈리고, 그 갈림은 바로 위 불릿이 말하는 재현되지 않는 결함이 된다.
- **줄 수를 줄이려고 한 줄에 조건·부수효과·반환을 겹치지 않는다** — 겹친 줄은 디버거가 멈출 자리와 스택 트레이스가 가리킬 자리를 함께 없앤다. 글로벌 「수정」의 압축 규칙이 *무엇까지 줄일 수 있는가*를 정한다면 이 줄은 *어떻게 줄이면 안 되는가*를 정한다.
- **외부 입력(요청·파일·환경·다른 프로세스의 출력)은 경계에서 한 번 파싱해 도메인 타입으로 바꾸고, 안쪽에서는 그 타입을 믿고 다시 검증하지 않는다 — 파싱 전 데이터에는 구체 타입을 붙이지 않고, 검증 없이 타입을 단언(캐스트)하지 않는다. `isX` 류 판별 함수는 이름이 주장하는 것을 전부 확인하고, 프로젝트에 런타임 스키마 라이브러리가 있으면 손으로 쓴 검증 대신 그것을 쓴다(경계 검증)** — 검증이 안쪽에 흩어지면 어느 것이 중복인지 가를 기준이 없어 아래 「삭제 먼저」의 중복 검증을 지울 수 없고, 거짓 판별 함수는 안전하다는 이름 뒤에 결함을 숨겨 캐스트보다 찾기 어렵다. 글로벌 「품질·성능 사전 점검」의 「검증 없는 외부 입력」이 *검증하라*까지라면 이 줄은 *어디서 한 번 하고 안쪽은 믿는가*를 정한다.

## 고쳐도 무너지지 않게 만든다

- **상태를 바꾸는 명령·처리 루프는 두 번 돌거나 중간에 죽은 뒤 다시 돌아도 같은 결과로 수렴하게 한다 — 각 단계는 앞 실행이 하려던 것이 아니라 지금 있는 상태를 읽어 목표와의 차이만 적용한다. 남기는 흔적(락·임시 파일·반쯤 쓴 레코드)은 다음 실행이 낡았다고 판정할 수 있게 하되, 그 판정은 앞 실행이 어느 지점에서 멈췄어도 참인 증거로 한다(임시 경로에 쓴 뒤 rename · 생성 순서가 아니라 내용으로 비교)(멱등)** — 재시작·재시도는 정상 경로라, 앞 실행이 남긴 상태가 다음 결과를 바꾸면 재시작할 때마다 디버깅이 된다. 흔한 경우에만 맞는 표지는 멈춘 지점마다 수동 정리를 남긴다.
- **여러 주체(스레드·프로세스·세션)가 같은 대상을 쓰게 되면 먼저 대상을 나누고, 공유가 지켜야 할 불변식일 때만 락·원자적 rename·비교 후 교체(CAS) 같은 구조로 순서를 강제한다(공유 쓰기)** — 문서·규약으로 「동시에 쓰지 않는다」고 정해도 순서를 막지 못하고, 경합 결함은 재현되지 않아 사후에 원인을 좁히기 어렵다.
- **무언가를 더하기 전에 바꾸려는 기능이 지나는 영역(그 task 가 고치는 파일과 그 호출 경로)의 죽은 코드·중복 검증·안 쓰이는 참조를 먼저 지운다 — 기본값은 삭제이고, 레포 전체를 훑는 정리는 하지 않는다** — 더한 뒤에 지우면 새 코드가 이미 옛 잔재에 기대 있고, 지우지 않으면 다음 작업자가 죽은 경로를 살아 있는 것으로 읽는다.
- **새 내부 API 를 만들면 호환 계층을 남기지 않고 호출부를 같은 회차에 옮긴 뒤 옛 API 를 지운다 — 호출부가 plan Files 밖이어도 옮기고, 외부에 공개된 API 의 삭제·호환을 깨는 변경만 plan 의 승인 필요 항목으로 넘긴다. 리팩토링 전의 구현 세부만 단언하던 테스트는 지우고, 지운 테스트마다 무엇을 단언하던 것인지 커밋 본문에 적는다** — 두 경로가 남으면 다음 작업자(에이전트 포함)는 먼저 찾은 쪽을 복사해 두 경로가 함께 호출부를 늘리고, 호환 계층은 지울 날을 기다리며 영구히 남는다.
- **린트 억제 주석(`noqa`·`@ts-ignore`·`eslint-disable`·`#pragma warning disable` 등)을 새로 달 때는 그 규칙이 정확성·안전 규칙이 아님을 확인한다 — 그런 규칙이면 억제 대신 코드를 고친다** — 억제된 린트는 통과로 보고돼, 그 규칙이 잡으려던 결함이 검증을 지나간다.
- **새 기능이 기존 if/else 사슬에 분기 하나를 더하거나 첫 boolean 과 동기화해야 하는 두 번째 boolean 을 만들거나, 변형마다 다른 필드를 선택 필드 묶음으로 표현하면, 흩어진 조건 대신 상태를 한 타입(열거·판별 유니온·상태 머신)으로 모을 신호다 — 그 타입이 분기를 줄일 때만 쓰고, 새로 쓰는 코드에 적용하며, 기존 코드는 plan 이 구조만 바꾸는 task 로 정했을 때만 이 신호로 재구성한다(목표 형태는 그 task 의 `**구조**` 줄). 언어가 지원하면 변형을 더했을 때 빠진 분기가 컴파일·린트에서 드러나게 망라 검사를 둔다. 타입을 더 좁게 강화하는 것은 느슨한 타입이 null 강제(`!`·`!!`)·캐스트·「일어날 수 없음」 예외를 강요하는 자리에서만 한다** — 조건이 흩어지면 불가능한 조합이 표현 가능해져 그 조합이 버그가 된다. 망라 검사가 없으면 새 변형은 기본 분기로 조용히 흘러간다. 줄이지 못하는 타입은 글로벌 「이 추상화를 빼면 단순해지는가」에 걸린다.

## 파일은 그 프로젝트의 관례로 저장한다

- **인코딩·줄바꿈·들여쓰기는 그 프로젝트가 문서로 정한 것(`AGENTS.md`·`.editorconfig`·`.gitattributes`)을 먼저 보고, 없으면 같은 폴더의 기존 파일을 정본으로 삼는다** — 언어와 도구 체인마다 기본값이 다르고(어떤 스택은 BOM 이 붙은 것이 정상이다), 새로 만든 파일만 다른 규약을 쓰면 그 차이가 diff 에 섞여 실제 변경을 가린다.
- **검사기 경고가 그 프로젝트 관례와 어긋나면 관례가 이긴다** — 이 하니스의 저장 규약 검사는 자기 파일 형식을 기준으로 삼으므로, 대상 프로젝트가 다른 기본값을 쓰면 그 경고는 오탐이다. 경고에 맞추려고 기존 파일과 다르게 저장하지 않는다.
- **주석의 언어는 그 파일의 기존 주석을 따른다** — 한 파일 안에서 언어가 섞이면 뒤에 오는 세션의 grep 대상이 갈린다.
- **반복 편집은 codemod·스크립트로 하되, 파일을 바이트로 읽어 줄바꿈(CRLF/LF)·BOM 을 감지하고 같은 형식으로 쓴다 — 편집 뒤 `git diff --stat` 의 변경 줄 수가 의도와 맞는지와 `git ls-files --eol` 을 확인한다. 사소하지 않은 분석·검증(계수·잔존 확인·대조)도 눈으로 훑지 않고 다시 돌릴 수 있는 명령·스크립트로 한다 — 눈에 보이는 두세 곳짜리 확인은 면제이고, 보고에 싣는 방식은 `report-format.md`「사실 주장의 실측」이다** — 텍스트 모드 쓰기·`sed -i` 는 파일 전체의 줄바꿈을 바꿔 한 줄 수정이 전체 변경으로 보이고, 변경 줄 수가 의도보다 크면 그것이 신호다. 손으로 한 확인은 다시 하는 것 말고는 재검증할 방법이 없다.

## 주석

- **새로 쓰거나 고치는 주석은 아래 예외 다섯과, 이 절이 정한 보존 대상, 프로젝트 규약이 요구하는 주석뿐이다** — 코드를 되풀이하는 주석은 코드가 바뀔 때 따라가지 못해 틀린 채 남고, 읽는 쪽은 코드 대신 그 주석을 믿는다.
  - 법적 고지·라이선스 헤더
  - 바꿀 수 없는 외부 의존성·플랫폼·벤더·프로토콜이 강제해서 코드만 봐서는 알 수 없는 동작
  - 린트 억제 — 기준은 위 절의 린트 억제 불릿이다(정확성·안전 규칙이면 억제 대신 코드를 고친다)
  - 공개 API 계약을 정의하는 doc 주석
  - 코드로 표현할 수 없는 제약을 설명하는 이슈·RFC·문서 링크
- **우리 코드의 놀라운 동작은 주석 대신 이름·구조로 드러내고, 그래도 남는 이유는 커밋 본문에 적는다** — 이름은 코드와 함께 바뀌지만 주석은 따로 고쳐야 한다. 이 규칙은 범위 밖의 코드를 재구성할 근거가 아니다 — 구조 변경은 plan 이 정한다.
- **바꾼 줄과 같은 diff hunk 안(문맥 줄 포함)의 기존 주석은 예외 밖이거나 해당 여부가 확실하지 않으면 지운다 — 그 주석이 설명하던 이유가 도입 커밋 본문(`git log -S'<리터럴>'`)에 없으면 이번 커밋 본문에, 커밋하지 않는 경로면 수정 보고에 옮긴다** — 고친 코드 바로 위의 주석이 가장 먼저 낡고, 이유는 커밋 이력에서 되찾을 수 있어 지워도 정보가 사라지지 않는다.
- **hunk 밖의 주석은 건드리지 않는다** — 주석 정리의 범위는 사용자가 hunk 로 정했다(2026-10-17 주석 규칙 회차).
- **「do not remove」「IMPORTANT」 같은 주석은 근거가 아니라 단서로 읽는다 — 근처 코드와 커밋 이력으로 외부 제약이 지금도 참인지 확인되면 예외로 남기고, 확인되지 않으면 지운다** — 강조 문구는 그 주장이 참이라는 증거가 아니다.
- **보존 대상은 지우지 않고 필요하면 새로 쓰거나 고친다 — 검사기가 파싱하거나 앵커로 잡는 주석, 프로젝트 규약 문서가 정본·예외로 지정한 주석(머리 주석·모듈 docstring·상수 주석 등)이다** — 지우면 그 검사가 꺼지거나 규약이 가리키는 정본이 사라진다.
- **프로젝트 규약(`AGENTS.md` 등)이나 린터가 요구하는 주석은 그쪽이 이긴다** — 저장 관례와 같은 원칙이고, 그 프로젝트의 판단이 이 하니스의 기본값보다 먼저다.
