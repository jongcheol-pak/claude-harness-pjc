> `write-gate-rationale.md` 에서 분리했다 — 그 파일이 `scripts/rules/*.md` 예산 20,000 B
> (`skills/DESIGN.md` 4절)를 넘겨서다. 이 판정만 담고, 나머지 write-gate 근거는 원본에 있다.

## §23 PLAN-EXEMPT 면제 판정

```
# pjc:plan 이 사용자 승인을 받아 낸 「계획 불필요」 판정을 파일 단위로 인정한다.
#   판정 주체를 훅의 크기 임계가 아니라 「사용자가 A 를 고른 사실」에 둔 이유: 크기 임계를
#   넓히는 방향은 이미 관측된 오판정(deferred plan-pos-9 — 값 치환에 조건 분기가 섞인 요청을
#   모델이 trivial 로 판정)의 통과 폭을 함께 키운다.
# 매칭이 '마커 뒤 토큰의 파일명·부모 완전 일치'인 이유: transcript 는 JSON 이라 경로 구분자가
#   이스케이프돼 전체 경로 매칭이 취약하고, 부분문자열 매칭은 'write.ps1' ⊂ 'guard-write.ps1' 처럼
#   표식에 없는 파일을 연다(부모의 'scr' ⊂ 'scripts' 도 같다). 마커 앞을 보지 않는 이유는 이 판정을
#   담은 소스·문서를 읽거나 grep 한 결과가 경로 접두를 마커 앞에 붙이기 때문이다 — 그러면 승인 없이
#   그 파일들이 열린다(완료 리뷰 BLOCKER 로 실증됐다).
# fail-closed 인 이유: §6 의 fail-open 은 '차단을 여는' 게이트라 안전측이 통과지만, 이 판정은
#   '통과를 여는' 것이라 방향이 반대다. transcript 부재·읽기 실패는 면제 없음(기존 차단 유지).
# 검사 위치가 차단 직전인 이유: plan 이 있으면 어차피 통과하므로, 앞에 두면 불필요한 transcript
#   I/O 가 매 호출 발생한다.
```

**판정 세부 (코드에서 이관 — `guard-write.ps1` 의 면제 블록은 로직만 남긴다)**

- **마커는 대괄호를 포함한다** — 맨 토큰(`PLAN-EXEMPT`)만 찾으면 이 판정을 설명하는 주석·문서 줄이
  grep 결과로 transcript 에 실릴 때 그 줄이 표식으로 인정된다(완료 리뷰 BLOCKER 로 실증됐다).
- **마커는 텍스트 줄의 시작이어야 한다** — transcript 한 줄은 JSON 객체 하나라 텍스트 내부 개행은
  리터럴 `\n` 두 글자로 실린다. 그 뒤이거나 `"text":"` 필드 시작일 때만 표식으로 본다(그 사이 공백·탭은
  허용 — JSON 안의 탭은 리터럴 `\t` 두 글자라 그 형태로 받는다). 이 규칙을 *설명하는* 산문은 마커로 줄을 시작하지 않으므로 이 조건 하나가 산문 오통과를 닫는다.
- **표식은 한 줄이다** — 마커 뒤를 다음 리터럴 `\n` 에서 자른다. 자르지 않으면 마커 줄 뒤에 문장이
  더 있을 때 토큰이 `path\n문장` 이 되고, Windows 에서 `\` 가 경로 구분자라 `GetFileName` 이 `n문장` 을
  돌려줘 **정상 표식이 차단된다**. 발급 지시가 표식을 펜스 코드블록으로 보여 주므로 이 형태가 흔하다.
- **대소문자는 무시한다**(`RegexOptions.IgnoreCase`) — 1차 필터인 `Select-String -SimpleMatch` 가 무시하므로
  2차 판정만 구분하면 두 층의 기준이 갈린다.
- **표식을 인정하는 채널은 assistant 줄뿐이다** — 줄에 `"assistant"` 가 없으면 건너뛴다. 첫째 갈래(리터럴
  `\n`)는 필드를 가리지 않으므로 이 조건이 없으면 **user 줄·tool_result 줄에 실린 마커가 표식이 된다**
  — 즉 그런 내용을 담은 파일을 읽는 것만으로 면제가 발급된다(재리뷰 MAJOR 로 실증됐다). 표식의 출처는
  `pjc:plan` 이고, 사용자는 `A) 바로 수정` 을 고르는 쪽이지 표식을 내는 쪽이 아니다.
- **마커에 붙은 장식(`- ` · `**` · `> ` · 백틱)과 리터럴 탭 들여쓰기를 허용한다** — 모델은 마커를 볼드·
  백틱으로 감싸는 습관이 있다(회차 13 실측: 이 세션 transcript 의 마커 등장 상위 형태에 `**` 접두가 10건).
  허용하지 않으면 승인받은 표식이 조용히 차단되고 사용자는 이유를 알 수 없다.
- **마커 '뒤'만 본다** — 파일을 읽거나 grep 한 결과는 경로 접두를 마커 '앞'에 붙이므로, 그 줄로는
  면제가 성립하지 않는다.
- **분해 문자에 백틱·별표·꺾쇠를 포함한다** — 표식에 마크다운 장식이 붙으면 토큰이 `` `path` ``
  처럼 되어 조용히 차단되는데, 그때 사용자는 승인했는데도 막히는 것으로 보인다.
- **경로 구분자를 정규화하지 않는다** — `Path` API 가 `/` · `\` 와 JSON 이스케이프된 `\\` 를 모두
  같게 처리한다(실측: 셋 다 file=`guard-write.ps1` parent=`scripts`).
- **부분문자열이 아니라 완전 일치다** — `write.ps1` 은 `guard-write.ps1` 의 부분문자열이라 `IndexOf`
  로 보면 표식에 없는 파일이 열린다(부모의 `scr` ⊂ `scripts` 도 같다).
- **표식이 파일명만 적었으면 대상이 프로젝트 루트 파일일 때만 인정한다** — 그러지 않으면 흔한
  이름(`README.md` · `Program.cs`)이 어느 디렉터리에서든 열린다. 절대 경로에서는 `$exParent` 가 항상
  차므로(루트 파일이면 프로젝트 폴더명) `$exIsRootFile` 판정 없이는 이 규칙이 **도달 불가능한 죽은
  분기**가 된다 — 완료 재리뷰가 그 상태를 MAJOR 로 잡았다.

**골든 픽스처에 레포의 실재 경로를 쓰지 않는다** — 마커 뒤에 실재 경로를 두면 그 픽스처 파일을 읽는
것만으로 해당 파일의 면제가 발급된다. `px` 접두의 가짜 이름으로 부분문자열 기하만 재현한다.

**막지 못하는 것**: **문단을 마커로 시작하면서 그 줄에 실제 경로가 함께 있는 산문** 하나다 — 줄 시작
조건이 「문장 안에 낀 마커」를 전부 걷어냈으므로 남는 것은 이 형태뿐이다. **실측 「0건」은 한 세션의
transcript 를 본 것이지 전수가 아니다**(회차 13 조사: 마커 등장 26건+ 전부가 문장 안, 줄 맨 앞 0건).
§6 의 스킬 발동 판정이 같은 성질의 약점을 갖고 있고(골든 `$trPlanNo` 가 「산문 언급」 케이스로 그
계열을 잰다), 그쪽과 같은 수준으로 둔다.

**표식의 수명은 세션 전체다** — transcript 는 append-only 라 앞부분의 표식이 끝까지 유효하다.
파일 한정이 범위를 좁히지만, 같은 파일을 한참 뒤 무관한 목적으로 고칠 때도 열려 있다.
