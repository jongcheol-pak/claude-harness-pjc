# 최종 보고 서식

> `karina:implement`가 **전 task 완료 후 1회** 읽는다. 회차 끝에만 쓰이는 서식이라 `SKILL.md` 본문에 두지 않는다 — 매 task 상시 로드하면 그 바이트가 루프 내내 실린다. 아래 「소요 기록」의 호출과 판정은 체인 보고(`../../chain-plan/references/report.md`)도 가리킨다 — 그쪽이 쓰는 것은 같은 스크립트 호출과 `karina-clock` 줄 판정뿐이다. 「plan 파일 커밋」 절은 `../SKILL.md` 완료 순서가 가리킨다. 「화면 시나리오 실행」·「사실 주장의 실측」 두 절은 예외로 루프 중 앱 조작 시점에도 읽힌다(`../SKILL.md` 의 HUMAN-VERIFY 불릿이 가리킨다).

## 보고 형식

```markdown
## 완료 보고

- **소요**: <시작> ~ <완료> (<N시간 M분>) — 「소요 기록」
- **수정 내용**: <무엇을 어떻게 바꿨는가 — 회차 전체를 관통하는 서술>
- **변경 파일**: <표. 3개 초과면 표로>
- **검증 결과**: <명령과 그 실제 출력. 요약하지 않는다>
- **HUMAN-VERIFY**: <기계로 확인 못 한 항목 — `AGENTS.md` 의 `Verify (앱 조작)` 줄이 없거나 "없음"이면 사용자가 `/karina:create-verification-skill` 을 돌려 검증 스킬을 만들도록 한 구로 권한다 — 항목이 없으면 줄 생략>
- **판정**: <plan과 달라 스스로 정한 것 — 없으면 줄 생략>
- **PR**: <URL | 건너뜀 — 사유(`pr-flow.md`「적용 판정」) — 브랜치를 옮겼으면 옮긴 사실과 원격보다 앞서 있던 커밋 수>
- **남은 이슈**: <없으면 줄 생략>
- **승인 필요 항목**: <사용자 결정 N건 — 항목마다 「<항목> — 권장: <안>(이유 한 구) — 답이 없으면: <무엇이 그대로 남는가>」 · 태그·릴리즈·배포 등 — 없으면 줄 생략>
```

- **검증 출력을 그대로 첨부한다** — "테스트 통과"라는 요약은 판정에 쓸 수 없다. 사용자가 확인할 수 있는 것은 실제 출력뿐이다.
- **예산은 보고에 싣지 않는다** — 등급을 가리지 않는다. 정본은 `skills/BUDGET.md` 「초과했을 때」이고, 처방으로 닫지 못한 경우의 1줄 예외도 그 파일이 정한다.
- **보고 길이는 내용에 맞춘다** — 없는 항목의 줄·채울 것이 없는 절·배경 설명·앞에서 말한 것의 재요약·맺음 문단은 판정에 쓰이지 않는다. **「검증 결과」는 이 규칙의 대상이 아니다**(출처: Opus 5 가이드 「작성된 산출물의 길이」).
- **보고 문장은 `../../WRITING.md` 의 한글 문체 규칙을 따른다** — 사용자는 이 보고로 판단하므로 번역투·피동 남용·과압축이 든 문장은 읽는 수고를 더하고 뜻을 흐린다. 서식이 정한 머리와 구분 기호는 그 규칙의 대상이 아니다.
- **승인 필요 항목은 건수로 시작하고 항목마다 권장안과 답이 없을 때 그대로 남는 것을 적는다 — 권장을 고를 근거가 없으면 `권장: 모름 — <무엇을 몰라서>`** — 나열만 하면 사용자는 답하지 않았을 때 무엇이 남는지 모른 채 결정을 미룬다. 예: 버전 커밋을 미루면 그 사이 `plugins/` 변경이 미배포로 남는다.
- **「판정」은 `plan.md`의 `## Progress Log`에 남긴 `판정:` 줄을 전량 옮긴다** — 골라 실으면 사용자가 되돌릴 기회를 못 가진 결정이 남고, `plan.md`는 다음 회차에 교체돼 그 줄이 달리 남는 곳이 없다.

### 「남은 이슈」의 판정

**이 줄은 이슈를 나열하는 자리가 아니라 판정을 마친 결과를 적는 자리다.** 최종 보고는 대화에만 남고 `plan.md`는 다음 회차에 교체되므로, 판정도 이관도 없이 여기 적힌 이슈는 세션이 끝나는 순간 사라진다.

- **화면에 싣는 것은 `[등재]`와 `[다음 회차]` 둘뿐이다** — 사용자가 이 줄에서 쓰는 것은 *어디에 남아 있는가*와 *다음에 무엇이 이어지는가*다. 올리지 않기로 판정한 항목을 함께 적으면 그 둘이 판정 서사에 묻힌다. **단 `[미등재:대장 없음]`은 예외로 싣는다** — 그 레포에는 올릴 곳이 없어 화면이 유일한 전달 경로다.
- **판정은 전건 하되 결과는 `plan.md`에 남긴다** — 남은 발견은 「지금 고칠 것인가」 3조건과 등재 하한선을 먼저 거치고(정본 `deferred-rules.md`), 그 결과를 `plan.md`의 `## Deferred / Follow-up`에 마커와 함께 **전건** 적는다. **보고에서 빼는 것은 출력이지 판정이 아니다** — `session-context` hook의 계수 입력이 `plan.md`라, 거기서 빠지면 판정을 마친 항목이 기계에는 미판정으로 남는다.
- **판정하지 않은 항목이 하나라도 있으면 완료가 아니다** — 화면에 안 낸다고 판정을 건너뛰는 것이 아니다.

## 소요 기록

**`../SKILL.md` 「최종 리뷰」 완료 순서의 「완료 시각 기록」에서 쓴다. 시각과 소요는 셸 출력만 쓴다** — 모델은 현재 시각을 모르고, 시각 차를 손으로 셈하면 날짜 경계에서 틀린다.

**호출 (공용)** — `<스크립트>` 는 `"<skill>/scripts/work-clock.ps1"`(`<skill>` 은 `karina:implement` 의 SKILL.md 폴더 — plan·chain-plan 에서는 `"<skill>/../implement/scripts/work-clock.ps1"`)이고, `<시작>` 은 `YYYY-MM-DD HH:mm` 이다.

```
Bash:       "$(command -v pwsh || echo powershell)" -NoProfile -File "<스크립트>" -Since '<시작>'
PowerShell: & "<스크립트>" -Since '<시작>'
```

- **판정은 출력의 `karina-clock ` 줄 하나로 한다 — `karina-clock <완료> <H>h <M>m` 이 소요 · `karina-clock <완료> ERROR <사유>` 면 `시작 판독 실패` 로 적고 완료 시각은 같은 줄에서 얻는다 · 그 줄이 없으면(실행기·경로·정책 실패) `시각 미확인`** — 다른 명령에 `;` 로 이으면 그 명령의 stderr 가 섞여, stderr 로 가르면 정상 경우에도 실패로 읽힌다. 실행기는 한 명령 안에서 골라 실패 후 재호출이 없고, 스크립트는 PS 5.1·7 양쪽에서 돈다.
- **`<시작>` 이 없으면 `-Since` 없이 불러 완료 시각만 얻고, 보고에는 `<H>h <M>m` 을 `N시간 M분` 으로 옮긴다** — 시작이 없어도 완료 시각은 남아야 하고, 출력에 한글을 두지 않는 것은 Git Bash 를 거친 PowerShell 출력에서 한글이 깨지기 때문이다.

**`plan.md` 기록 (`karina:implement` 전용)** — `<시작>` 은 `plan.md` `## Goal` 의 `> 시작:` 값이다.

- **호출을 plan 파일 추적 판정(`git ls-files --error-unmatch -- <plan 경로>`)에만 `;` 로 잇는다** — 따로 부르면 왕복이 하나 늘고, `&&` 로 이으면 호출이 실패할 때 판정까지 건너뛴다.
- **그 출력으로 `> 완료:` 줄을 `> 완료: <완료> · 소요 <N시간 M분>` 로 Edit 한 뒤, 추적 레포면 `git status --porcelain -- <plan 경로>` 로 커밋 여부를 잰다 — 그 줄이 없는 옛 서식이면 `> 시작:`(없으면 `> 승인:`) 아래에 넣는다** — `ls-files` 결과는 Edit 로 바뀌지 않지만 `status` 는 바뀌어, Edit 전에 재면 「커밋 불필요」로 판정된 채 미커밋 변경이 남는다. 중계 모드면 인계 절 커밋(`../../plan/references/relay-mode.md`)보다 먼저다.
- **`> 시작:` 이 없거나 자리표시 그대로면 `시작 미기록` 으로 적고 완료 시각만 남긴다** — 옛 서식의 plan 이거나, hook 이 발화하지 않았고 Step 1 폴백도 비어 시작 시각이 남지 않은 경우다.
- **보고의 `- **소요**:` 줄은 `> 시작:` 과 위에서 Edit 한 `> 완료:` 줄에서 옮긴다** — 보고를 쓸 때 다시 재면 `> 완료:` 와 다른 시각이 실려, 기록과 보고가 갈린다.

## plan 파일 커밋

**`../SKILL.md` 「최종 리뷰」 완료 순서의 「plan 파일 커밋」 에서 쓴다 — 완료 시각 기록 뒤, PR 열기 전이다.**

- **`plan.md` 를 추적하는 레포면 PR 열기 전에(PR 을 열지 않으면 최종 보고 직전에) `plan.md` 를 커밋한다** — `git ls-files --error-unmatch -- <plan 경로>` 가 성공하고 `git status --porcelain -- <plan 경로>` 가 비어 있지 않을 때 `문서: plan.md 진행 기록` 커밋 1개를 만들고, 중계 모드면 마지막 인계 절 커밋에 함께 담는다(인계 절을 쓰지 않는 계획이면 단독 커밋). gitignore 인 레포는 건너뛴다 — 남기면 다음 회차가 미커밋 변경 위에서 시작한다.

## 화면 시나리오 실행

**task 에 `**화면**` 줄(서식 `../../plan/references/plan-template.md`「작업 단계」)이 있으면 `AGENTS.md` 의 `Verify (앱 조작)` 줄이 가리키는 검증 스킬로 그 시나리오를 HEAD 에서 돌리고, 스크린샷을 그 스킬의 Evidence 위치에 줄에 적힌 이름으로 남겨 통과 조건으로 판정한다.** 순서는 그 스킬의 Launch → Doctor → Drive → Evidence → Cleanup 이고, 증거 기준은 아래 「사실 주장의 실측」 이다. 계획 시점에 정한 시나리오를 그대로 돌려야 실행 시점의 즉흥 설계가 판정을 대신하지 않는다.

- **검증 스킬이 없으면(`Verify (앱 조작)` 줄이 없거나 「없음」) 화면 줄을 그대로 HUMAN-VERIFY 로 옮기고, 커밋 본문에 `화면: 미촬영(HUMAN-VERIFY) · 스크린샷 <이름>` 줄을 남긴다** — 시나리오·스크린샷 이름·통과 조건을 그대로 적어야 사용자가 같은 것을 돌린다. 커밋 줄이 없으면 체인 끝 PR 이 화면 task 를 찾지 못해 ship 의 화면 게이트가 걸리지 않는다(`../../chain-plan/references/pr-mode.md`「Y 체인 끝 PR」).
- **`(BASE 대조)` 가 붙은 줄은 BASE 에서도 같은 시나리오를 돌린다** — `git worktree add --detach <스크래치>/base-<sha7> <plan.md 의 > BASE:>` 로 BASE 를 받고, 검증 스킬의 Launch 를 그 worktree 경로에서 돌린 뒤 같은 Drive·Evidence(스크린샷 이름 앞에 `base-`)·Cleanup 을 거쳐 `git worktree remove <경로>` 로 지운다. 사용자의 체크아웃은 건드리지 않는다(선례 `../../pr/references/ship.md` 3·6번).
- **판정은 넷으로 갈린다 — 「BASE 에서 거짓·HEAD 에서 참」 만 통과다** — 변경 전에도 참인 시나리오는 이 변경을 재지 않는다.

  | HEAD | BASE | 판정 | 처리 |
  |---|---|---|---|
  | 거짓 | — | 실패 | 그 task 의 검증 실패다 — `loop-exceptions.md`「실패 처리」 |
  | 참 | 거짓 | 통과 | `[x]` |
  | 참 | 참 | BASE 대조 불성립 | 시나리오가 계획을 잘못 옮긴 것이면 1회만 고쳐 두 쪽을 다시 돌린다(원래 문면과 사유를 그 task 에 남긴다). 그래도 참이면 다른 검증이 통과한 task 를 `[x]` 로 닫고 Progress Log 에 `판정:` 줄을 남긴다 |
  | 참 | 못 돌림 | BASE 미실행 | worktree·Launch 실패 사유를 적고, 다른 검증이 통과한 task 를 `[x]` 로 닫는다 |

- **위 표의 뒤 두 판정은 통과로 적지 않고 재시도 루프도 돌리지 않는다 — 커밋 본문과 최종 보고 「기계로 확인 못 한 항목」 에 `화면 — BASE 대조 불성립(미검증)` 또는 `화면 — BASE 미실행(미검증)` 으로 싣는다** — 통과로 적으면 BASE 를 재지 않은 채 게이트가 열리고, 코드로 풀 수 없는 실패를 실패 카운터에 태우면 「동일 원인 3회」로 루프가 선다.
- **커밋 본문에 판정 한 줄을 남긴다 — `화면: HEAD <참|거짓> · 스크린샷 <이름> [· BASE <거짓|참|미실행>]`** — 완료 리뷰가 이 줄로 시나리오를 돌렸는지 대조한다(`../../../agents/completion-reviewer.md`).

## 사실 주장의 실측

**보고의 사실 주장 — 지금 상태·원인·영향·수치 — 은 읽기 전용 명령으로 잴 수 있으면 보고를 쓰기 전에 재고, 그 명령과 출력 요지를 함께 적는다.** 사용자는 보고를 읽고 다음 결정을 내리는데, 잰 것과 짐작한 것이 같은 문장으로 적히면 둘을 가르지 못한다.

- **잴 수 없는 것만 `추정(근거)` 또는 `모름` 으로 표시하고 왜 못 재는지 한 구를 붙인다** — 사용자 화면 확인·외부 서비스 상태·재현에 시간이 드는 동작처럼 이 세션의 명령이 닿지 않는 것이다.
- **잴 수 있는 주장에 「아마」「~일 것」「~로 보인다」를 쓰지 않는다** — 그 말은 재지 않았다는 고백이지 확신도 표시가 아니다. 한 번 재면 끝나는 것을 짐작으로 남기지 않는다.
- **성능 비교·회귀 판정에 쓰는 수치는 교대 반복 횟수·중앙값·범위와 함께 적는다 — 결론 불가의 조건은 `../../PERF-MEASUREMENT.md`「성능 수치의 판정」 이다** — 1회 측정의 차이는 실행 간 편차와 갈리지 않는다. 검증 실행 시간 같은 부수 수치는 대상이 아니다.
- **앱을 조작해 확인한 것은 실제 사용자 경로로 조작하고(내부 setter·테스트 전용 경로 금지) 조작과 그 결과 상태·부수 효과(쓴 파일·바뀐 행·보낸 메시지)를 함께 적는다 — 화면 하나만 보고 통과로 적지 않는다** — 내부 경로로 만든 상태는 사용자가 겪는 경로를 재지 않고, 마지막 화면만 보면 그 사이에 깨진 동작과 화면 밖 효과가 빠진다.
- **「판정」 줄과 「남은 이슈」도 대상이다** — 원천인 Progress Log 의 `판정:` 줄이 짐작이면 보고도 짐작이다.

## 다음 회차 인계 프롬프트

**발동 조건은 하나다 — `plan.md`의 `## Deferred / Follow-up`에 `[다음 회차]` 마커가 1건 이상 있는가.** 있으면 위 완료 보고 **뒤에** 아래를 코드블록으로 낸다. 없으면 이 절은 없는 것과 같다.

**코드블록이어야 한다** — 사용자는 그것을 복사해 새 세션 입력창에 붙여 넣는 방식으로 일한다. 산문에 섞어 쓰면 어디부터 어디까지가 프롬프트인지 사용자가 잘라내야 한다.

**담을 것은 넷이고, 빠지면 새 세션이 맥락을 처음부터 다시 조사한다.**

| # | 무엇을 | 왜 |
|---|---|---|
| 1 | **다음 회차에서 할 일** — `[다음 회차]` 항목을 **사용자 원문 표현 그대로** 옮긴다 | 이번 회차가 재해석한 말로 옮기면 그 해석이 확정된 요구로 굳는다 |
| 2 | **직전 회차가 무엇을 끝냈는가 + HEAD SHA** | 새 세션이 `git log`부터 뒤지지 않아도 되고, 이어받는 것과 이미 끝난 것을 가른다 |
| 3 | **착수 전 판정할 것** — 그대로 믿으면 틀리는 지점(이번 회차가 바꾼 수치·명칭, 아직 확인 못 한 전제) | 인계에서 가장 잘 유실되는 것이고, 없으면 새 세션이 낡은 값을 근거로 계획한다 |
| 4 | **현황 재측정 명령** — 그 시점의 값을 다시 재는 명령 | 인계 프롬프트에 적힌 수치는 작성 시점의 것이라 붙여 넣는 시점에는 이미 낡았을 수 있다 |

- **부수 항목은 별도 코드블록으로 나눈다** — 함께 넣을지 사용자가 고르게 한다.
- **plan 초안까지 쓰지 않는다** — 인계는 「출발점」이지 「완성된 계획」이 아니다. 미리 분해해 두면 그 조사가 이번 회차 시점의 것이라 낡고, 새 세션의 요구 인터뷰가 통째로 빠진다.
- **`loop-stop-patterns.md` ①(세션 전환·컨텍스트 우려 제안) 위반이 아니다** — ①이 금지하는 것은 **루프 도중에** 위임을 반납하는 것이고, 이 프롬프트는 **전 task가 끝난 뒤 최종 보고의 일부**다. 낼 자리가 완료 보고 뒤라는 것이 그 구분이다. 이 문단이 없으면 다음 세션이 자기 정지 규칙에 걸린 줄 알고 서식을 통째로 뺀다.
