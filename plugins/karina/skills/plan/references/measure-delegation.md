# 실측 위임 (`karina:plan` Step 3)

> `../SKILL.md` Step 3 이 아래 조건이 맞을 때만 이 파일을 연다 — 조건이 맞지 않는 실측은 메인 세션이 그대로 잰다.

## 실측 위임

- **조건은 하나다 — 변경 대상을 가리키는 리터럴(바꿀 함수·키·문면)마다 `git grep -lF <리터럴>` 로 센 파일 수의 합이 30 을 넘을 때다. 그 계수 명령과 합을 Investigation Log 에 1행 남긴다** — `git grep` 은 추적 파일만 세어 gitignore 된 `plan.md`·의존성 디렉터리가 수를 부풀리지 않는다. 가이드는 위임을 *"a wide multi-file investigation"* 에만 허용하고 *"Do not delegate work you can finish yourself in a handful of tool calls"* 라 한다(`../../DESIGN.md` 3-2) — 30 은 Step 3 의 「hit 30건 초과 시 `grep -C`」 와 같은 선이다.
- **Explore 서브에이전트 하나만 띄운다** — 가이드가 *"If one subagent can complete the task, use one rather than several"* 라 하고, 한 계획의 탐색은 서로 독립된 조각으로 나뉘지 않는다.
- **맡기는 것은 위치 탐색이다 — 변경 대상의 호출자·구현체·직렬화·테스트·심볼 밖 소비자(설정·기능 플래그·DB 열·같은 데이터를 읽는 다른 언어·프로세스)가 어디 있는지 · 호출하는 라이브러리의 소스 위치·고정 버전·로컬 패치와 "없다" 확인 검색** — 출력이 큰 것은 이쪽이라, 맡겨야 메인 컨텍스트가 줄어든다.
- **메인에 남는 것은 넷이다 — acceptance 현재값(`(착수 N)`) 측정 · 삭제 복구 판정 · 버그 원인 규명 · "없다" 행의 확정** — 앞의 셋은 plan 에 수치·승인 항목·task 로 박히는 값이라 요약 한 겹 뒤에 두면 리뷰어가 확인할 근거가 숨는다. "없다" 행은 돌려받은 명령을 메인이 그대로 다시 돌려 확정한다 — 0건 검색은 출력이 작아 다시 돌려도 컨텍스트가 늘지 않는다.

### 프롬프트

- **규칙 칸은 띄울 때 `../SKILL.md` Step 3 의 해당 불릿 원문을 인용해 채운다 — 이 파일에 규칙 사본을 두지 않는다** — 서브에이전트는 대상 레포에서 돌아 하니스 스킬 경로를 열지 못하고, 사본을 두면 Step 3 만 고쳐질 때 이쪽이 조용히 낡는다.

```
대상 레포: <경로> · AGENTS.md: <경로>
변경 대상: <리터럴·심볼 목록 — 각각 무엇을 바꾸는가 한 구>
찾을 것: 각 변경 대상의 호출자·구현체·직렬화·테스트·심볼 밖 소비자(설정·기능 플래그·DB 열·같은 데이터를 읽는 다른 언어·프로세스) 위치 · 호출하는 라이브러리의 소스 위치·고정 버전·로컬 패치 · 아래 "없다" 후보의 부재 확인
"없다" 후보: <없다고 결론 낼 주장 | 없음>
고치지 않는다(읽기 전용).
지켜야 할 규칙(인용):
- 사정거리: <인용 — ../SKILL.md Step 3 「명령의 사정거리가 주장의 범위와 같은지 본다」 불릿>
- "없다": <인용 — 같은 절 「"없다"를 결론으로 쓸 때는 …」 불릿>
- 30건 초과: <인용 — 같은 절 「hit가 30건을 넘으면 …」 불릿>
돌려줄 것 — Investigation Log 표 행 그대로(주장 | 실행한 명령 | 출력 요지), 행마다 실제로 돌린 명령을 적는다. 명령 없는 행은 적지 않는다.
```

### 반환 처리

- **돌려받은 행을 Log 에 옮길 때 명령 열 끝에 `(위임)` 을 붙인다** — 서식 정본은 `plan-template.md`「Investigation Log」 다.
- **서브에이전트가 실패하거나 행이 비면 메인이 잰다** — 위임은 컨텍스트를 아끼는 수단이지 실측을 건너뛰는 근거가 아니다. 그 사실을 Log 에 1줄 남긴다.
