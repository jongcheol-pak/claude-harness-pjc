# 이어받기 (`karina:chain-plan` — 워커가 회차를 나눴을 때)

> `../SKILL.md` 「워커 루프」가 `worker_done`(succeeded) 을 받았을 때 PR 모드 꺼짐 또는 스택 · 병렬 그룹 밖이면 「코디네이터 검증」 을 위해, 그 밖에는 `--body` 의 `남은 일` 이 「없음」이 아닐 때만 이 파일을 연다. 먼저 남은 일을 가르고, `[다음 회차]` 면 체인 승인이 그 계획 전체를 위임했으므로 남은 회차는 사용자에게 묻지 않고 같은 계획의 이어받기 워커로 잇는다.

## 코디네이터 검증

- **PR 모드 꺼짐 또는 스택(`stack-mode.md`「코디네이터」 — 그 PR 브랜치에서) · 병렬 그룹 밖 계획(이어받기 포함)의 `succeeded` 를 받으면 `release.md`「닫기」 뒤, 아래 「남은 일 판정」 전에 spec 의 「근거로 정한 것」 ③ 을 이 세션이 대상 레포에서 직접 돌린다** — 워커의 `--body` `검증:` 은 작성자 자신의 주장이고, 이 모드에는 `pr-verifier`(PR 모드)·병합 뒤 재검증(`parallel.md`「병합」 ⓓ) 같은 독립 확인이 없어 틀린 주장이 다음 계획의 출발점이 된다. 병렬 ⓓ 는 커밋 전 병합 상태에서 재고 `merge --abort` 로 가는 다른 갈래라 이 절과 합치지 않는다.
- **돌릴 명령은 ③ 의 항목 중 완성된 셸 명령뿐이다 — 자리표시(`<…>`)가 남은 것·수동·화면 확인·쓰기 모드(`--fix`·check 플래그 없는 포매터)는 고르지 않고, 「~ 수정 시」 같은 조건부 명령은 워커 `--body` `검증:` 에 오른 것만 고른다. ③ 이 위치만 가리키면(「AGENTS.md Build & Test」) 그 절을 Read 해 같은 규칙으로 고른다. 고르지 못한 항목은 보고에 `건너뜀` 으로 남기고, 고른 것이 없으면 검증 전체가 `건너뜀 — <사유>` 다** — ③ 칸에는 명령·자리표시·기대값·화면 실기동이 한 칸에 섞여 있다(실측). 쓰기 모드를 돌리면 이 세션이 대상 레포를 고치게 된다.
- **명령마다 본문을 임시 폴더 스크립트 파일로 써서(`pwsh -Command "…"` 꼴은 그 인자를 `.ps1`, 그 밖은 `.sh`) `timeout 40m pwsh -NoProfile -File <파일>` · `timeout 40m bash <파일>` 을 대상 레포 경로에서 Bash `run_in_background: true` 로 하나씩 띄우고, 완료 알림이 오면 다음 명령을 띄운다** — 본문을 셸 인자로 넘기면 bash 가 `$` 를 먼저 치환하고 파이프의 일부에만 시한이 걸린다. 이 사이에는 깨울 워커도 대기 스크립트도 없어 시한이 없으면 알림이 오지 않을 때 체인이 선다 — 40분은 백그라운드 대기 수명 실측 45분 안쪽이다.
- **판정은 exit code 다 — 단 기대값이 괄호·비교로 적힌 항목(「(1719)」·「(0건)」·「= N」)은 출력을 그 값과 대조하고, 대조할 수 없으면 `건너뜀` 이다** — `… | wc -l` 같은 명령은 늘 exit 0 이라 exit 만 보면 검증하지 않은 것을 통과로 적는다.
- **exit 124(시한) · 126/127(실행 불가·명령 없음) · `timeout` 자체가 없음은 실패가 아니라 `미검증 — <사유>` 로 보고에 싣고 진행한다. 그 밖의 0 아닌 exit 와 기대값 불일치는 실패다** — 고칠 것이 없는 판정불가를 실패로 보내면 이어받기가 3회 헛돈다.
- **띄우기 전과 끝난 뒤 `git -C "<대상 레포 경로>" status --porcelain` 을 잰다 — 추적 파일이 바뀌었으면 되돌리지 않고 체인을 멈추고 보고한다(쓰기 모드 명령이 섞였다). 무시되지 않은 untracked 만 생겼으면 아래 「이어받기」 의 `실측 요지:` 에 `검증이 남긴 untracked — <목록>` 을 싣는다** — 그 변경 위에 다음 워커를 띄우면 워커의 `plan.md` 가 모르는 변경에서 출발한다(`../SKILL.md` 「하지 않는 것」 의 근거).
- **전부 통과면 「남은 일 판정」 으로, 실패면 「이어받기」 로 간다 — 결과는 보고 plan 칸 `코디네이터 검증:` 줄에 싣는다(`report.md`「보고 서식」)** — 이 절은 사용자 몫 범주를 더하지 않는다.

## 남은 일 판정

- **`남은 일` 이 「없음」이 아니면 다음 계획을 띄우기 전에 가른다 — `[다음 회차]` 는 멈추지 않고 다음 절의 이어받기를 따른다(체인 승인이 그 계획 전체를 위임했다). 그 밖에 뒤 계획이 계획 간 의존으로 넘겨받는 것이면 체인을 멈추고 보고하고, 아니면 보고의 남은 일로 모으고 다음으로 간다. 애매하면 멈춘다** — `succeeded` 라도 계획이 미완일 수 있고, 그 위에 다음 계획을 띄우면 순서 의존이 깨진다. 멈춘 사유에 「남은 일을 처리한 뒤 plan N+1 부터 재개」를 적는다.
- **화면 확인 대기 PR 항목(`pr-mode.md`「워커」 표)도 `[다음 회차]` 가 아니다 — 위 의존 판정 그대로 가른다(스택 체인의 `스택 대기` PR 은 판정 대상이 아니다 — 뒤 계획이 그 브랜치 위에서 시작한다, `stack-mode.md`「코디네이터」)** — 그 PR 은 사용자가 화면을 확인할 때까지 merge 되지 않아 뒤 워커의 base 에 그 변경이 없다. 뒤 계획이 그 변경에 의존하면 멈추고 사유에 「PR merge 뒤 plan N+1 부터 재개」 를 적는다. 의존하지 않으면 남은 일로 모으고 다음으로 간다.
- **`[체인 대조]` 는 `[다음 회차]` 가 아니다 — 아래 이어받기 ⓐ 의 앞 계획(M<N) 정지 대상이 아니고 위 판정으로 가른다(의존 재료는 `../SKILL.md`「인터뷰」의 ①)** — 착수 때 이미 거짓이던 앞 계획 기준이라 받을 이어받기가 없고, 그 워커가 깨뜨린 것도 아니다.

## 이어받기

- **ⓐ 먼저 `[다음 회차]` 항목을 가른다 — 체인 계획 목록(plan 번호·제목)의 뒤 계획(M>N)을 가리키는 항목은 이어받지 않고 보고의 남은 일에 「plan M 이 받음」으로 남긴다** — 그 계획이 체인에서 곧 돌아, 이어받으면 같은 일이 두 번 돈다(2026-10-03 Karina 체인 워커가 `[다음 회차] plan 2·3` 을 적었다). 단 plan M 재진술의 결과에 그 일이 없으면 이 계획의 항목으로 본다.
  - 앞 계획(M<N)을 가리키는 항목은 받을 곳이 없는 미완이라 멈추고 보고한다. 어느 쪽인지 애매해도 멈춘다.
  - 거른 뒤 남은 항목이 0이면 `남은 일` 이 「없음」인 것과 같다 — 다음 계획으로 간다.
  - **위 「코디네이터 검증」 의 실패와 남긴 untracked 도 이 계획의 이어받을 항목이다 — `[다음 회차]` 와 함께 오면 한 이어받기에 함께 싣는다** — 같은 계획의 결과를 고치는 일이라 뒤 계획으로 넘길 곳이 없다.
- **ⓑ 진척을 본다 — 거른 뒤 이어받을 항목의 제목 집합(`(근거: …)` 를 뗀 것)이 직전 워커의 집합과 같거나, 그 계획의 이어받기가 이미 3회면 멈추고 보고한다** — 근거 필드는 회차마다 sha 가 달라 원문으로 대조하면 반복이 잡히지 않고, 같은 일을 다른 말로 적는 반복은 제목으로도 못 잡는다. 3회는 `../../implement/SKILL.md`「멈추는 넷」 4번의 수다. **코디네이터 검증 실패 항목은 제목 집합 대조에서 빼고 3회 상한만 적용한다** — 같은 명령의 실패는 제목이 같아, 대조에 넣으면 한 번 고쳐 본 뒤에 바로 멈춘다. 멈춘 사유에 「plan N부터 다시 부르면 그 계획을 새로 실측한다」를 적는다.
- **ⓒ task 를 만든다 — plan N 의 spec 을 그대로 쓰되 둘만 바꾼다** — 원문·재진술·`인계:`·`DB 변경`·`다른 회차:` 를 그대로 두어야 워커가 같은 목표·제약 안에서 남은 일만 한다.

  ```
  <CLI> orchestration task-create --json --task-title "plan <N>/<총> 이어받기 <k> — <한 줄>" --deps <방금 끝난 task id> --spec "$(cat <<'EOF'
  [chain-plan 중계] plan <N>/<총>
  이어받기: <k>
  … (plan N spec 의 나머지 줄 그대로) …
  EOF
  )"
  ```

  - **`실측 요지:` 칸에는 이어받을 `[다음 회차]` 항목 원문과 `(근거: …)` 를 싣는다 — 코디네이터 검증 실패는 `코디네이터 검증 실패 — <명령> exit <N> (근거: 출력 끝 <k>줄 요지)` 한 줄이다** — 칸 이름을 바꾸지 않는다. 워커의 `karina:plan` 중계 모드가 이 칸 이름으로 출발점·`실측 요지 대비:` 를 잡는다.
  - **`진행:` 1 끝에 덧붙인다: 「args 둘째 줄에도 `이어받기: <k>` 를 싣는다. 작업 task 는 실측 요지 항목뿐이다(인계 절은 마무리 마지막 커밋으로 쓰고 절 이름은 `## plan <N> 이어받기 <k>` — relay-mode 인계 절의 생략 조건 제외)」** — 압축 뒤에도 워커가 이어받기임을 알고, 다음 계획이 이 회차의 변경을 인계 파일에서 읽는다.
  - **첫 Task 의 이어받기여도 `--deps <방금 끝난 task id>` 를 준다** — 「첫 Task 는 `--deps` 를 뺀다」는 앞 task 가 없을 때의 규칙이고 이어받기 task 는 첫 Task 가 아니다. 앞 task 가 completed 라 이 task 는 곧바로 ready 다.
- **ⓓ 그다음은 `../SKILL.md` 「워커 루프」 그대로다 — 앞 워커를 `release.md`「닫기」 로 닫은 뒤 `worker-start` 로 띄운다.** 병렬 그룹의 계획이면 띄우는 폴더·병합 시점은 `parallel.md`「중단·이어받기·사후 완료」 를 따른다. PR 모드면 앞 워커가 이미 merge 했으므로 이어받기 워커도 자기 PR 을 merge 까지 간다(스택이면 merge 하지 않고 같은 PR 브랜치에 더한다 — `stack-mode.md`「워커」) — 병렬은 같은 worktree 브랜치를 다시 쓰고, `pr-mode.md`「워커」 의 base 합치기가 squash 된 앞 PR 을 그 브랜치에 들여 새 PR 의 diff 가 새 커밋만 담는다. 이어받기가 끝나 `남은 일` 에 `[다음 회차]` 가 또 오면 ⓐ부터 다시 돈다.
  - **승인 요청은 체인 승인 위임으로 답하되 봉투의 task 줄 대조는 이어받기 기준으로 본다 — 이어받기 항목은 각각 task 에 있거나 `실측 요지 대비:` 에 근거가 있고, task 는 이어받기 항목을 넘지 않는다(task ⊆ 이어받기 항목)** — 원 계획 결과 전체를 덮었는지는 보지 않는다. 앞 워커가 이미 끝낸 항목을 누락으로 세면 `E:` 왕복이 생긴다. `승인 필요 항목`·`DB 변경` 대조는 `user-relay.md`「봉투 대조」, 위임되지 않는 항목은 `../SKILL.md` 「답하는 기준」 그대로다.
- **ⓔ 보고는 `report.md` 「보고 서식」의 plan N 칸 하나에 합친다** — 이어받기 수와 합치는 규칙은 그 파일에 있다.
