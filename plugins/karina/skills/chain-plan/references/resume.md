# 재개 (`karina:chain-plan` — 「plan N부터」)

> `../SKILL.md` 「계획 목록」이 「plan N부터」로 불렸을 때만 이 파일을 연다. 재개는 새 Run 을 만들므로 spec `인계:` 의 기본 경로(`docs/plans/chain-<Run id>.md`)는 아직 없는 파일이고, 워커는 그 파일이 없으면 첫 계획으로 넘어간다(`../../plan/references/relay-mode.md`「중계 모드」) — 앞 계획의 결정·제약을 읽지 못한다.

## 재개

- **N 이 1이면 처음 실행과 같다 — 아래를 건너뛴다.**
- **앞 계획들이 쓴 인계 파일을 고른다 — 대상 레포 루트에서 레포 상대 경로로 `grep -lE "^## plan <N-1>([^0-9]|$)" docs/plans/chain-*.md` 를 돌리고, 후보마다 `git log -1 --format='%ct %h' -- <경로>` 의 `%ct` 가 가장 큰 것을 고른다. 커밋이 없는(출력이 빈) 후보는 뺀다** — 한 레포에 여러 체인의 인계 파일이 쌓여 「앞 계획 절이 있는 파일」은 여럿 나온다(Karina 레포 실측 3개). 정규식 끝의 `([^0-9]|$)` 는 `## plan 1` 이 `## plan 10` 에 걸리지 않게 하면서 `## plan 1 이어받기 2` 와 CRLF 줄 끝(`\r`)은 받는다.
- **화면 직렬 워커가 base 에 남긴 미push 인계 커밋(`pr-mode.md`「워커」 의 화면 줄 task 직렬 예외)도 위 `git log` 가 로컬 이력으로 집는다 — 고른 경로의 마지막 커밋이 `origin/<체인 브랜치>` 에 없으면(`git branch -r --contains <%h>` 빈 출력) 아래 `앞 인계:` 줄 끝에 `· 미push` 를 더한다** — 그 절은 이 체크아웃에만 있어, 다른 폴더에서 재개하면 읽히지 않는다.
- **후보가 없으면 새 Run 경로를 쓰고 아래 줄은 `없음 — 새 파일` 이다.**
- **체인 승인 화면 머리 줄 아래에 `앞 인계: <경로 (근거: 마지막 커밋 <%h>) | 없음 — 새 파일>` 줄을 싣는다** — 다른 체인의 파일을 골랐는지 사용자가 거기서 본다. `E` 로 경로를 고치면 그것을 따른다.
  - 고른 파일에 `## plan <N>([^0-9]|$)` 절이 이미 있으면(멈춘 plan N 이나 그 이어받기가 남긴 것) 같은 줄 끝에 `· plan N 절 이미 있음 — 새 워커가 같은 이름의 절을 덧붙인다` 를 더한다 — 뒤 계획이 두 절 중 어느 것을 따를지 사용자가 미리 안다.
- **고른 인계 파일 이름의 옛 Run id 로 임시 폴더에 `karina-chain-<옛 Run id>-decisions.md` 가 있으면, 새 Run 의 결정 파일을 `chain-decisions.md`「결정 기록」 대로 만들 때 머리 줄 아래에 그 파일의 머리 줄 밖 내용을 이어 붙이고, `앞 인계:` 줄 끝에 `· 결정 기록 <N>줄 이어받음`(없으면 `· 결정 기록 없음`)을 더한다** — 멈추기 전 체인의 답·판정이 재개 뒤 계획에도 앞 결정으로 남아, 같은 갈림길이 다시 사용자에게 가거나 반대로 판정되지 않는다.
- **spec 의 `인계:` 줄은 Run id 경로 대신 고른 경로를 레포 상대 경로(`docs/plans/…`)로 적은 것이고, 모든 계획 task 에 같다** — 원 서식과 같은 형태라 워커의 Read·커밋 경로가 어긋나지 않고, 워커는 그 파일을 Read 한 뒤 `## plan <N>` 절을 덧붙인다.
- **PR 모드 체인의 인계 파일은 체인 브랜치에만 있다 — 위 후보가 없고 `git ls-remote --heads origin 'karina/chain-*'` 에 브랜치가 있으면 `앞 인계:` 줄을 `없음 — PR 모드 체인 브랜치 <목록> 에 있을 수 있음(그 브랜치에서 다시 부른다)` 으로 싣는다** — 계획 PR 은 체인 브랜치로 merge 되고 기본 브랜치에는 끝 PR merge 뒤에야 들어간다(`pr-mode.md`「P 체인 끝 PR」). 멈춘 체인은 체크아웃을 체인 브랜치나 그 위의 워커 브랜치에 두어 보통은 위 grep 이 집는다.
- **재개를 `P`·`T` 로 승인하면 새 체인 브랜치를 만들지 않고 옛 것을 다시 쓴다(`T` 의 부모는 `stack-mode.md`「재개·압축」) — 고른 인계 파일 이름의 옛 Run id 로 `karina/chain-<옛 8자>`(`<옛 8자>` 는 그 Run id 의 run_ 뒤 앞 8자)를 얻고, `git ls-remote --exit-code --heads origin karina/chain-<옛 8자>` 가 성공하면 그 브랜치가 체인 브랜치다** — 앞 계획들의 merge 가 그 브랜치에 있다(spec 「근거로 정한 것」). 원격에 없으면 `pr-mode.md`「켜기」 대로 새로 만든다.
  - 승인 화면 `PR 모드:` 줄은 `꺼짐(끝에 PR 하나) — [P] 로 켠다(옛 체인 브랜치 karina/chain-<옛 8자>)` 이고, 출발 브랜치 판정은 지금 브랜치가 그 브랜치면 커밋 수 줄을 재지 않는다(그 위의 미push 커밋은 다음 워커 PR 이 옮긴다).
  - 이름을 run-create 전에 알므로 objective 의 `[체인 승인:]` 앞에 `[체인 브랜치: karina/chain-<옛 8자>]` 를 싣는다(`compaction.md`「압축 뒤 복원」). run-create 뒤 task-create 전에 `git fetch origin karina/chain-<옛 8자>` → `git switch karina/chain-<옛 8자>` → `git pull --ff-only` 로 전환하고, 실패하면 `pr-mode.md`「켜기」 의 실패 처리와 같다.
  - 아래 「미병합 병렬 브랜치」·「열린 PR」 의 `<체인 브랜치>` 도 이 브랜치다.

## 미병합 병렬 브랜치

> 멈춘 체인에 병렬 그룹(`parallel.md`)이 있었으면, 끝났는데 체인 브랜치에 병합되지 않은 계획 브랜치가 남아 있을 수 있다. 모르고 재개하면 끝난 계획을 처음부터 다시 돌린다.

- **위에서 고른 인계 파일 이름 `docs/plans/chain-<Run id>.md` 에서 옛 Run id 를 얻고, `git branch --no-merged <체인 브랜치> --format='%(refname:short)'` 에서 이름이 `chain-<Run id 의 run_ 뒤 8자>-p<M>` 으로 끝나는 브랜치를 고른다(`-p<M>` 끝 고정 — `-p1` 이 `-p10` 에 걸리지 않게)** — 병렬 워커는 그 이름으로 띄워져(`parallel.md`「띄우기」) 브랜치가 계획 번호를 가진다. 인계 파일을 못 골랐으면 `chain-` 과 `-p<숫자>` 가 든 미병합 브랜치를 전부 후보로 싣고 사용자가 `E` 로 고른다.
- **`gh` 를 쓸 수 있으면(원격이 GitHub·`gh auth status` exit 0) 후보 브랜치마다 먼저 `gh pr list --head <브랜치> --state all --json number,state,url` 을 본다 — MERGED 면 완료·병합 불요라 `merged: plan <M> — <URL>` 로 싣고 아래 두 불릿을 건너뛰며, OPEN 이면 아래 「열린 PR」 에 싣고, PR 이 없으면 아래 판정 그대로다** — PR 모드 체인(`pr-mode.md`)의 squash merge 는 원 커밋을 체인 브랜치에 넣지 않아 끝난 브랜치가 `--no-merged` 에 남는다. 모르고 병합하면 끝난 계획을 다시 넣는다.
- **브랜치마다 `git worktree list --porcelain` 에서 그 worktree 경로를 찾고, 그 경로의 `plan.md` 가 미완료 체크박스(`^- \[ \]`) 0개 · 완료(`^- \[x\]`) 1개 이상이면 완료로 본다** — 마지막 계획은 인계 절을 쓰지 않을 수 있어 인계 절 유무로는 완료가 갈리지 않고, worktree 폴더는 지우지 않으므로 남아 있다(`parallel.md`「닫기」).
- **완료 브랜치는 체인 승인 화면 `앞 인계:` 줄 아래에 `미병합: plan <M> — <브랜치> (완료)` 로 싣고, 승인 뒤 plan N 을 띄우기 전에 `parallel.md`「병합」 으로 먼저 병합한다** — 뒤 계획이 그 커밋을 봐야 한다. M 이 N 이상이면 그 계획은 건너뛴다(이미 끝났다).
- **미완료 브랜치는 병합하지 않고 `미병합: plan <M> — <브랜치> (미완료 — 새로 돌림)` 으로 싣는다** — 그 계획은 체인 브랜치에서 새 워커로 다시 돌고, 옛 브랜치·worktree 경로는 보고의 `병렬 병합:` 줄에 남긴다.

## 열린 PR

> 멈춘 체인이 PR 모드(`pr-mode.md`)였으면 워커가 merge 하지 못하고 열어 둔 PR 이 남아 있을 수 있다. 모르고 재개하면 그 계획을 새 워커가 처음부터 다시 돌린다.

- **위에서 고른 인계 파일 이름 `docs/plans/chain-<Run id>.md` 에서 옛 Run id 를 얻고, `gh pr list --state open --limit 200 --json number,url,headRefName,body` 에서 본문에 `체인: <Run id>` 를 담은 PR 을 고른다** — 워커가 PR 본문 끝 줄에 그 표지를 싣는다(`pr-mode.md`「워커」). 마지막 계획은 인계 절을 쓰지 않아 인계 파일로는 그 브랜치를 찾지 못한다. 기본 목록은 30건이라 상한을 올린다.
- **본문에 `## 화면` 줄이 있는 PR 은 `열린 PR: plan <M> — <URL> (<브랜치>) · 화면 확인 대기` 로 구분한다** — 그 계획은 끝났고 merge 만 사용자의 화면 확인(`../../pr/references/ship.md` 7번)을 기다린다. 사용자가 확인·merge 한 뒤 plan M+1 부터 잇는 경로가 막힌 PR 과 다르다.
- **고른 PR 마다 체인 승인 화면 `앞 인계:` 줄 아래에 `열린 PR: plan <M> — <URL> (<브랜치>)` 를 싣는다 — 그 PR 을 merge 뒤 plan M+1 부터 잇는지, 닫고 plan M 을 새로 돌리는지는 사용자가 `E` 로 정한다** — 열린 PR 에는 끝난 일과 막힌 사유가 함께 있어, 코디네이터가 고르면 사용자가 답한 것을 뒤집거나 이미 있는 것을 깨는 결정을 대신 한다(`../SKILL.md`「답하는 기준」 ②·④).
- **본문에 `스택:` 줄이 있는 PR 들은 하나씩 싣지 않고 `stack-mode.md`「재개·압축」 의 `열린 스택:` 한 줄로 싣는다** — 스택은 위아래 순서가 있어 맨 위 브랜치가 다음 계획의 부모다.
- **표지를 담은 PR 이 없으면 `열린 PR: 없음`, 인계 파일을 못 골랐거나 `gh` 를 쓸 수 없으면 `열린 PR: 확인 불가 — <사유>` 를 싣는다** — 확인하지 않은 것을 「없음」으로 적으면 사용자가 남은 PR 을 모른 채 승인한다.
