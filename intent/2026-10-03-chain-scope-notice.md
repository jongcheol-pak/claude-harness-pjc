# Intent: 계획 체인에서 요청 밖 작업을 계획 단계에 사용자에게 묻고, 회차 분할의 실측을 워커까지 넘긴다
Author: 사용자(이 세션 1문1답 4회 + 재진술 동의). Status: approved.

## Problem
원문: *"chain-plan 스킬에서 작업시 계획을 분할해서 계획을 작성 하는데 plan 스킬에서 상세하게 작성을 하는거 같은데 불필요하게 중복되는 부분이나 chain-plan 에서 작성한 계획과 plan에서 작성한 계획이 전혀 다르게 작성되는 부분이 있는지 확인, chain-plan에서 자동으로 분할된 계획을 작업할 때 문제가 되는 부분이 없는지 확인, chain-plan에서 작업시 사용자가 요청하지 않은 작업도 같이 수정해야 된다고 판단되는 항목이 있으면 계획 작성시 인터뷰로 사용자에게 알림"*
문서 대조로 확인한 빈틈(실행 재현 없음): A `pjc:plan` 이 Step 3 실측·Step 4 분해 뒤 회차를 나누는데 넘김 args 네 블록에 그 결과가 없어 워커가 회차마다 처음부터 다시 잰다 · B `회차 경계:` 가 한 줄이라 워커가 다른 회차의 task 를 흡수하거나 빈틈을 남겨도 승인 대조 ①(재진술 결과·범위 밖)이 못 잡는다 · C 체인 승인의 `바뀌는 영역`·`승인 필요 항목` 을 코디네이터가 `AGENTS.md` 만 읽고 채운다(출처 미정의) · D 요청 밖 작업이 회피 설계 또는 코디네이터 판정으로 처리돼 사용자는 체인 보고에서야 안다 — 글로벌 「승인 없이 요청 범위를 넘는 수정」 금지와 어긋난다.
이 세션 사용자 답: Q「요청 밖 항목을 언제 알리나」 → *"체인 전+워커 단계 둘 다 (권장)"* · Q「A·B·C 도 고치나」 → *"A·B·C 모두 고침 (권장)"* · Q「계획 목록을 직접 준 경로의 체인 전 알림」 → *"워커 단계에 맡김 (권장)"* · Q「체인 승인 화면의 회차별 성공의 모습·범위 밖 중복(E)」 → *"현행 유지 (권장)"* · 재진술 → *"동의"*.

## Proposed outcome
`pjc:plan` 이 회차를 나눠 넘길 때 다섯째 블록 `회차 실측:`(회차마다 task 초안·바뀌는 파일·승인 필요 후보·요청 밖 후보)을 싣는다. chain-plan 은 회차별 확인 인터뷰에서 요청 밖 후보를 하나씩 묻고(포함/제외/보류), 체인 승인의 `바뀌는 영역`·`승인 필요 항목` 을 그 블록에서 채우며(없으면 「워커 실측 후 확정」), spec 의 `실측 요지:` 로 워커에 넘긴다. 워커는 그것을 출발점으로 다시 재고 다른 회차의 task 를 넣지 않으며, 계획 중 회피 설계로 피할 수 없는 요청 밖 작업이 새로 드러나면 `[요청 밖]` 질문으로 묻는다. 코디네이터는 그것을 판정하지 않고 사용자 몫으로 넘긴다(구현 중에 드러난 것은 현행대로 `failed`). 승인 대조 ①에 다른 회차 task 흡수 금지를 더한다.

## Affected users and systems
계획 체인을 돌리는 사용자와 그 코디네이터·워커 세션. 하니스 레포 — `plugins/pjc/skills/plan/SKILL.md` · `plan/references/interview.md` · `skills/chain-plan/SKILL.md` · 신설 `skills/chain-plan/references/handoff.md` · `README.md` · 버전(`plugin.json`·README).

## Constraints
2026-10-03 결정(봉투 밖이라는 이유만으로 사용자에게 넘기지 않는다)은 요청 밖 작업에 한해서만 좁힌다 — 승인 필요 항목·DB 목록 판정은 지금처럼 코디네이터가 한다. 계획 목록을 직접 받은 경로에서 코디네이터는 실측하지 않는다. 체인 승인 화면 구성(E)은 그대로 둔다. 비체인 `pjc:plan` 경로는 바꾸지 않는다. 두 스킬 `description` 은 바꾸지 않는다. `SKILL.md` 12,000자 · `references/*.md` 15,000자 예산. push·릴리즈는 별도 승인이다.
