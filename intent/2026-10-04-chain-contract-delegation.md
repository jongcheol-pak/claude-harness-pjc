# Intent: 계획 체인이 추가형 프로그램 접점(새 CLI 갈래·플래그, 새 API·공개 함수, 새 설정 키)의 외부 계약 갈림길을 체인 승인 위임으로 코디네이터가 판정한다
Author: 사용자(이 세션 1문1답 2회 + 재진술 동의). Status: approved.

## Problem
원문: *"외부 계약(명령줄 갈래 추가) 갈림길이라 사용자 몫입니다. 이런 문제로 멈추었는데 해결 방법은?"* → 제시한 안 중 *"②로 계획 세워줘"*(체인 승인에 추가형 외부 계약 위임 줄을 두고 그 범위 안의 워커 질문은 코디네이터가 권장안으로 판정).
실측: 2026-10-03 Karina run_919c7f19 plan 2/2 워커가 `karina-cli hook-post` 갈래 추가(A 권장 / B 대장 / C PowerShell)를 외부 계약 갈림길로 `ask` 했고, 코디네이터(chain-plan 1.328.0)는 「외부 계약(명령줄 갈래 추가) 갈림길이라 사용자 몫입니다」로 사용자에게 넘겨 체인이 사용자 답까지 섰다. `chain-plan/SKILL.md` 는 외부 계약을 다루는 문면이 없고(grep 0) 사용자 몫 넷에도 없다 — 코디네이터 발화에 판정 근거 문구가 없어 애매하면 사용자 몫 규칙·글로벌 공개 API 승인 중 어느 경로였는지는 추정이다. 워커 권장안은 재진술 목표(Antigravity 훅 stdin 경계) 안이었다.
이 세션 사용자 답: Q「위임하는 추가형 외부 계약의 범위」 → *"프로그램 접점만 (권장)"* · Q「위임을 체인 승인에 기본으로 넣나」 → *"기본 포함, E로 끌 수 있음 (권장)"* · 재진술 → *"동의"*.

## Proposed outcome
체인 승인 화면에 `외부 계약 위임:` 줄이 기본으로 들어가 `Y` 가 함께 승인하고 `E` 로 「위임 없음」으로 끌 수 있다. 위임이 켜져 있으면 워커의 외부 계약 갈림길 질문 중 추가형 프로그램 접점이고 재진술 목표 안이며 워커 권장안이 제약 안인 것은 코디네이터가 그 권장안을 `코디네이터 판정` 으로 답하고 체인 보고에 모은다. 워커 계획 승인 요청의 승인 필요 항목 중 그 범위의 공개 API 추가는 체인 승인으로 승인된 것으로 본다. 워커는 외부 계약 질문 머리에 추가/변경 표식을 단다. 기존 계약의 변경·삭제, UX 동작, 권장안이 없거나 목표 밖인 질문은 지금처럼 사용자에게 간다.

## Affected users and systems
계획 체인을 돌리는 사용자와 그 코디네이터·워커 세션. 하니스 레포 — `plugins/pjc/skills/chain-plan/SKILL.md` · 신설 `chain-plan/references/delegation.md` · `chain-plan/references/report.md` · `plugins/pjc/skills/plan/references/interview.md` · `README.md` · 버전(`plugin.json`·README).
