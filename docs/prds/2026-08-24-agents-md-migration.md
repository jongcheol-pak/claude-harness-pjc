# PRD: AGENTS.md 소급 정리 경로

## 목적

새 저장 경계(v1.193.0)는 **앞으로 생성되는 것**(bootstrap 템플릿)과 **앞으로 기록되는 것**(record-project-fact 금지 목록)만 규정했다. **이미 존재하는 `AGENTS.md`를 그 경계로 옮기는 경로는 없다** — `bootstrap-agents-md`는 파일이 있으면 즉시 종료하고(절대 규칙 2), `record-project-fact` Step 5는 「기록으로 커졌을 때」 발동하는 절 단위 이관이라 성격이 다르다.

그 공백을 Maid(174,642B)에서 실측으로 확인했다. 사용자가 판정 기준을 프롬프트에 직접 적어 넣어야 정리가 됐고, 그 기준은 사용자가 알 수 없는 것이었다. 이 PRD는 **그 판정을 스킬이 갖게** 한다.

**선행 PRD와의 관계**: `docs/prds/2026-08-22-agents-wiki-boundary.md`가 경계를 **정의**했고 그 Out of Scope가 소급 정리를 *"각 프로젝트의 다음 작업 세션에서 점진 적용"*으로 미뤘다. 이 PRD는 그 「점진 적용」이 **무엇을 근거로 수행되는가**를 만든다 — 경계 자체를 다시 정의하지 않는다.

## 기능 요구사항 (Functional Requirements)

| ID | 요구사항 | 우선순위 | 검증 방법 |
|----|---------|---------|----------|
| FR-1 | **경계 표 정본이 레포 밖 세션에서도 열린다** — 4스킬이 가리키는 「AGENTS.md 내용 경계」가 `docs/harness-conventions.md`(이 레포에만 있음)에서 **플러그인 배포 경로 안**으로 옮겨지고, 레포 문서는 그것을 가리킨다 | Must | 설치 캐시(`~/.claude/plugins/cache/pjc-harness/pjc/<판>/`) 아래에 경계 표 본문이 실재하고(eval 픽스처 사본이 아닌 것), 4스킬의 포인터가 그 경로를 가리킨다. 같은 표가 두 곳에 복제되지 않았음을 grep으로 확인 |
| FR-2 | **`KEEP_SECTIONS`가 경계 표의 AGENTS.md 행과 정합한다** — 현재 `("위키", "Build & Test", "DO NOT", "Plan Location")` 4종인데 경계 표는 **`Conventions`·`데이터 접근`·`산출물·파일 관리` 셋을 더** 담는다. 지금 스크립트를 돌리면 잔류해야 할 절을 내보낸다 | Must | `relocate-agents.py`의 `KEEP_SECTIONS`와 경계 표 AGENTS.md 행의 절 이름 집합이 일치. **정합을 기계로 고정**한다(`check-harness-consistency.py` 축) |
| FR-3 | **소급 정리 진입점이 `record-project-fact`에 신설된다** — 사용자 요청(`"AGENTS.md 정리해줘"`·`"새 경계로 맞춰줘"`)으로 발동하고, **산출물은 `plan.md`**다(스킬이 직접 고치지 않는다) | Must | SKILL.md에 해당 단계가 존재하고 산출물이 plan.md임이 명문화. description의 라우팅 문구가 그 요청을 포함 |
| FR-4 | **삭제 전에 정본 실재를 실측으로 확인한다** — 「옮긴다」와 「지운다」를 가르는 판정. 지우려는 내용의 정본이 **다른 곳에 실제로 있는지** 확인한 근거(파일·건수·명령 출력) 없이는 삭제하지 않는다 | Must | 절차에 그 확인 단계가 있고, 산출 plan의 삭제 항목마다 근거 칸이 요구된다. 근거 없는 삭제 항목을 걸러내는 검사가 있다 |
| FR-5 | **목적지가 3분기로 판정된다** — ① 위키(프로젝트 성격·아키텍처 상세·기능 명세) ② **레포 문서 신설**(해석용 상세 — 결과를 해석할 때 필요한 것) ③ 삭제(정본이 이미 다른 곳에 있는 것). 경계 표는 ①③만 명확하고 **②의 신설 판정이 없다** | Must | 절차에 3분기 판정과 각 분기의 기준이 있고, ②를 고를 때 파일명·위치 규약이 정해져 있다 |
| FR-6 | **잔류 절 안에서 「명령·값」과 「근거 서술」을 가른다** — 절 단위 판정만으로는 감축되지 않는다. Maid 실측: `## Plan Location`은 잔류 절인데 41,555B였고 그중 남을 것은 경로 4줄이었다 | Must | 절차에 절 내부 판정 축(*"명령을 실행할 때 필요한가, 결과를 해석할 때 필요한가"*)이 있고, 잔류 절도 축약 대상임이 명문화 |
| FR-7 | **이관 후 무손실 역대조가 의무다** — 옮긴 원문의 각 줄이 목적지에 도달했는지 기계로 대조하고, 의도적으로 압축·삭제한 것은 그 사실을 근거와 함께 남긴다 | Must | 대조 수단이 실행 가능한 형태로 제공되고(스크립트 또는 명령), 산출 plan의 검증 단계에 그 대조가 포함된다. Maid 실측에서 이 대조가 누락 1건을 잡았다 |
| FR-8 | **`suggest-agents-record`의 오탐 2종이 차단된다** — ⓐ 명령이 **다른 레포를 대상으로 실행**됐는데 cwd의 AGENTS.md로 기록 여부를 판정한다 ⓑ 명령 문자열이 **heredoc·인용 안의 데이터**여도 실행 명령으로 본다. 2026-08-23 실측: Maid AGENTS.md를 쓰는 heredoc 안의 `cargo test`가 하니스 레포 기준으로 미기록 판정됐다 | Should | 두 형태를 재현하는 골든 케이스가 음성(제안 없음)으로 통과하고, 기존 양성 케이스가 그대로 발화 |
| FR-9 | **회귀 자산이 새 판정을 덮는다** — 이관 골든(현행 7케이스)에 FR-2·FR-4·FR-7의 케이스가 더해진다 | Must | `run_relocation_evals.py` 전건 통과 + 신규 케이스가 **수정 전에는 실패**함을 확인(무회귀 케이스만으로는 근거가 못 된다) |

우선순위: Must(없으면 미완성) / Should(중요하나 1차 출시 후 가능) / Could(여유 시)

| ID | 요구사항 | 검증 방법 |
|----|---------|----------|
| NFR-1 | **기존 Step 5(주입 상한 이관) 무회귀** — 소급 정리를 더해도 상한 임박 시의 무승인 이관 동작이 바뀌지 않는다 | 이관 골든 7케이스 전건 통과 |
| NFR-2 | **소급 정리에는 승인 게이트가 있다** — Step 5가 무승인인 근거는 *"내용을 한 글자도 바꾸지 않는 무손실 이동"*인데, 소급 정리는 **삭제를 포함**해 그 전제가 성립하지 않는다 | SKILL.md에 두 경로의 승인 차이와 그 사유가 명문화 |
| NFR-3 | **새 스킬·agent·hook을 신설하지 않는다** — 기존 스킬 확장으로 끝낸다. 신설하면 `validate.ps1` 화이트리스트·hooks 배선·라우팅 중복이 따라온다(대장 `[2026-08-12]`) | `validate.ps1`의 스킬·agent 배열과 `hooks.json`이 무변경 |
| NFR-4 | **AGENTS.md 서술 밀도 규칙을 이 회차가 스스로 지킨다** — 규정을 늘리되 이 레포 `AGENTS.md`는 목표선 10,000B 이내를 유지한다 | 정리 후 바이트 측정 + `check-harness-consistency.py` 목표선 축 통과 |
| NFR-5 | **문서 로드 예산 기준선이 갱신된다** | `check-harness-consistency.py` 예산 기준선 축 exit 0 |

## Out of Scope (명시적 제외)

- **나머지 레포 11곳의 실제 정리** — MOA(22,182B) 등. 이 PRD는 **경로를 만들 뿐** 각 레포의 정리는 그 프로젝트 세션에서 수행한다(선행 PRD의 같은 판단을 승계). Maid 1곳은 이 PRD 착수 전에 표본으로 이미 정리했다.
- **`session-context.ps1`의 절 단위 지목**(선행 PRD FR-11, Could) — 대장에 등재된 별개 항목이다. `top_sections()` 재사용이라는 접점이 있으나 이 PRD의 요구는 아니다.
- **`require-plan-for-write`의 AGENTS bootstrap 게이트를 `guard-agents-content`로 합치는 것** — 대장 등재된 SUGGEST이고 기존 골든이 대거 걸린다.
- **경계 표 내용 자체의 개정** — 4분류의 항목을 늘리거나 옮기지 않는다. FR-1은 **위치**만 바꾸고, FR-2는 스크립트를 표에 맞춘다(표를 스크립트에 맞추지 않는다).

## 성공 기준

- Must 요구사항 100% 충족 (FR-1~7·9) + Should(FR-8) 충족
- **재현 기준**: Maid 정리에서 사용자가 프롬프트에 직접 적어야 했던 판정 5건(P1~P5)이 전부 스킬 문서 안에 있어, 다음 레포에서는 `"AGENTS.md 정리해줘"` 한 줄로 같은 결과에 이른다
- 이관 골든 전건 통과 + 신규 케이스가 수정 전 실패 실증
